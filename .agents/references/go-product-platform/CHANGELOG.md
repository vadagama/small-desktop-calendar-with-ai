# История изменений

## Не выпущено

- Graphify подключён к самому репозиторию платформы: проектные навыки,
  область анализа, AGENTS/CLAUDE, MANUAL и локальный семантический граф.
  Это отдельная интеграция от настройки продуктовых репозиториев.

### 2026-11-25 — модернизация готового продукта

- Добавлен go-product-modernization: аудит Git-продукта, подготовка перехода и
  реализация этапов рефакторинга/миграции с baseline, проверками поведения,
  переносом данных, переключением и откатом. Завершение всей миграции возвращает
  продукт к обычному SDD на фактическом новом стеке.
- Bootstrap получил четвёртый стартовый путь; manager поддерживает передачу и
  возобновление. Навык включён в переносимый набор платформы и маршрутизацию.
- Engineering schema 1.2 дополнена необязательным modernization-блоком; документы
  размещаются в существующих hld/adrs/initiatives/specs/operations без новых папок.

### 2026-11-25 — выбор ADE и интерактивная настройка

- Инструкции Codex, Claude Code, OpenCode, Orca и Zed объединены в
  `ade-installation.md`; прежний отдельный гайд OpenCode включён в него.
- Пользователь выбирает ADE, основную среду и исполнителей. Настраиваются только
  выбранные интеграции; предпочтения меняются управляющим навыком без полного
  bootstrap. Engineering schema 1.2 сохраняет ADE отдельно от харнеса, описана
  миграция 1.1 с сохранением назначений; product schema остаётся 1.0.
- Опрос использует нативные опции и multi-select при наличии. При ограничении
  числа вариантов или отсутствии множественного выбора вопросы разбиваются на
  шаги. Markdown-чекбоксы не считаются формой; текстовый fallback применяется
  при недоступности инструмента или по предпочтению пользователя.

- Прототипы размещаются в prototypes/PROTOTYPE-NNNN-name; обновлены профиль,
  примеры и миграция прежних каталогов из корня с сохранением номеров.

- Из целевой структуры docs исключены data, interfaces, lld и requirements.
  Требования остаются в requirements.md SPEC, детали реализации — в design.md
  SPEC; общая архитектура и ограничения контрактов — в HLD со ссылками на
  исходники. Обновлены инструкции создания документов и миграции без потери данных.

### 2026-11-24 — UI, модели и харнесы

- Общий UI-набор с публичным Impeccable применяется к целевому интерфейсу и
  экспериментам. Добавлены docs/ui/DESIGN.md и шаблоны vision/components/screens
  для инженерной SPEC. Прототипы проверяют гипотезы в PROTOTYPE-NNNN-slug на
  едином стеке; в продукт переносятся решения, код оценивается отдельно.
- Engineering schema 1.1 разделяет целевой UI и эксперименты, содержит семь ролей
  моделей/харнесов. Описаны выбор при настройке, handoff, проверка и замена
  назначений в существующем продукте с откатом.
- Добавлена поддержка OpenCode: общие AGENTS.md и .agents/skills, проектные
  адаптеры и конфигурация, проверка версии и моделей.
- Миграция: ui.mode prototype → skills; prototype_path классифицируется по
  фактическому назначению приложения. Автоматического переноса/удаления нет.
  Product schema остаётся 1.0; старые записи ниже описывают прежний контракт.

- Управляющий навык получил сценарий замены canvas прототипированием:
  инвентаризация, резервная копия локальных данных, перенос дизайн-материалов,
  проверка замены, удаление интеграций с сохранением Graphify и общих worktree,
  итоговые проверки и откат. Обычная смена UI-режима ничего не удаляет.

- Добавлена альтернатива canvas — «Скиллы для разработки прототипов»: выбор
  UI-режима в опроснике, проектная установка с фиксацией SHA, каталог дизайнерских,
  reviewer, motion, desktop и mobile навыков. Описаны приложение в `prototype/`,
  UI kit и дизайн-система, mock/API граница, Storybook и проверки качества.

  продукта: область анализа в .graphifyignore, первоначальный граф, Git-хуки

  обновление. Добавлены критерии приёмки и восстановление в шаблоне MANUAL.md;

  (раздел «Критерии готовности»).
