# Настройка ADE

Единый справочник установки и настройки Codex, Claude Code, OpenCode, Orca и
Zed. Применять разделы только выбранных пользователем сред и их исполнителей.
Общий контракт ролей — [модели и харнесы](model-harness-configuration.md).
Источники проверены 2026-11-25; точные команды, поля и доступность инструментов
сверять с установленной версией. Версия CLI не доказывает возможности desktop,
ACP-адаптера или удалённой сессии.

## Установка выбранных приложений

Агент сначала проверяет наличие и версию выбранной ADE и её исполнителя.
Если приложения нет, включает установку из официального источника в план
настройки и выполняет разрешённые шаги сам. Не переустанавливать существующее
приложение и не обновлять его без необходимости; глобальные изменения выполнять
в согласованном объёме. Интерактивный вход в аккаунт проходит пользователь,
после него агент продолжает проверку. Наличие приложения не подтверждает авторизацию.

| ADE | Официальный источник установки |
|---|---|
| Codex | [Quickstart](https://developers.openai.com/codex/quickstart) — выбрать desktop/CLI по предпочтениям |
| Claude Code | [Setup](https://code.claude.com/docs/en/setup) |
| OpenCode | [Getting started](https://opencode.ai/docs/) |
| Orca | [Install](https://orca.dev/docs/install) |
| Zed | [Installation](https://zed.dev/docs/installation) |

Для Orca/Zed проверить отдельно наличие выбранного агента/адаптера. Не считать
установку редактора установкой всех исполнителей. Способ установки, источник,
фактическую версию, запуск и ограничения сохранить в MANUAL, без credentials.

## Выбор сред и исполнителей

1. Прочитать предпочтения из запроса и engineering.yaml. Если они неизвестны,
   предложить выбор нескольких ADE: Codex, Claude Code, OpenCode, Orca, Zed;
   сохранить свободный ответ. Одна открытая сейчас ADE не означает выбор за пользователя.
2. Уточнить основную среду, если выбрано несколько. Для Orca выбрать запускаемого
   агента; для Zed — встроенный Zed Agent, внешний ACP-агент или CLI в терминале.
3. Записать `ai.surfaces` (выбранные ADE), `ai.primary_surface` (основная),
   `ai.harnesses` (фактические исполнители). Назначение содержит `surface` и
   `harness`: Orca + Claude Code → `orca` / `claude-code`; Zed + Codex → `zed` /
   `codex`; встроенный Zed Agent → `zed` / `zed`. Для Codex напрямую — `codex` /
   `codex`. Если один исполнитель используется в двух ADE, создать два назначения
   с разными id и отдельно проверить запуск каждого.
4. Настроить только выбранные интеграции. Не устанавливать все пять приложений,
   не менять их глобальные настройки и не включать дополнительные MCP ради полноты.
   Общий переносимый снимок платформы в `.agents/` и `.claude/` остаётся базой
   совместимости: наличие копии не означает, что Claude Code выбран или установлен.
   Нативные адаптеры ролей и настройки запуска создаются только для выбранных сред.
5. Для каждой связки проверить правила, обнаружение навыков, модель, инструменты,
   ограничения и способ диалога. Зафиксировать версии и результат в MANUAL.

Согласованный выбор можно изменить через `go-project-platform-manager` без
повторного bootstrap. Добавление среды включает её адаптер и проверку; смена
основной среды не меняет назначения остальных ролей. При удалении из выбора
сначала переназначить используемые роли. Пользовательские конфиги, общий снимок,
worktree, историю и активные сессии автоматически не удалять. Откат возвращает
прежние назначения и только изменённые агентом настройки.

## Codex

### Правила и конфигурация

Общие правила — `AGENTS.md`, проектные навыки — `.agents/skills/`.
Локально проверено наличие Codex CLI 0.171.0-alpha.13 и его `--help`; это не
минимальная версия платформы. При установке продукта определить его версию.
Проектные настройки помещать в `.codex/config.toml` только при необходимости;
проверить доверие проекту, иначе проектная конфигурация может не применяться.
Сохранять существующие MCP, hooks и ограничения. Источники:
[конфигурация](https://learn.chatgpt.com/docs/config-file/config-basic),
[навыки](https://developers.openai.com/codex/skills).

### Назначения, запуск и проверка

Для выбранных ролей использовать поддерживаемые установленной версией custom
agents: в текущем руководстве — `.codex/agents/<role>.toml` с `name`,
`description`, `developer_instructions`, при необходимости `model` и
`model_reasoning_effort`. Это нативные определения, а не копия каталога персон.
Права наследуются от родительской сессии: текст «только чтение» не создаёт sandbox.
Если роли недоступны, описать проверенный запуск отдельной сессии в MANUAL.
Источник: [multi-agent](https://developers.openai.com/codex/multi-agent).

Модель выбирать штатным интерфейсом или подтверждённым флагом CLI; не считать
изменение engineering.yaml переключением текущего чата. Формат профилей зависит
от версии: в актуальном руководстве это отдельные `~/.codex/<name>.config.toml`,
а не старые таблицы `[profiles]`. Проектная настройка не требует создания
глобального профиля. Источник: [профили](https://learn.chatgpt.com/docs/config-file/config-advanced).
Проверить в новой сессии чтение AGENTS, вызов проектного навыка, фактическую модель
и доступные инструменты; записать способ запуска, версию и статус. Обновление CLI
выполнять только в согласованном объёме, после него повторить эти проверки.

## Claude Code

### Правила и конфигурация

Проверить `claude --version` и `claude --help`. Создать тонкий `CLAUDE.md` по
[примеру](../skills/go-platform-bootstrap/references/claude-md-example.md),
ссылающийся на AGENTS.md; для нативного импорта поддерживается `@AGENTS.md`.
Не копировать правила продукта в несколько документов.
Источник: [память и инструкции](https://code.claude.com/docs/en/memory).
Проектный набор — `.claude/skills/`, настройки команды — `.claude/settings.json`;
локальные предпочтения и credentials не публиковать. Сохранить существующие
permissions, hooks и MCP. Источник: [settings](https://code.claude.com/docs/en/settings).

### Назначения, запуск и проверка

Нативные роли — `.claude/agents/<role>.md`: YAML frontmatter (`name`,
`description`, `model`, допустимые `tools`) и инструкции роли. Для ревью
ограничить доступные инструменты, проверить фактические права. Модель выбирается
из доступных в установленной среде; в MANUAL фиксировать фактическую модель,
а не только меняющийся alias. Не превращать каждую роль в фоновую задачу:
диалог с пользователем ведёт основной агент. Источник:
[custom subagents](https://code.claude.com/docs/en/sub-agents).

В новой сессии проверить загрузку общих правил, навыка и нативной роли, модель,
ограничения и интерактивный вопрос. Если нужен перезапуск/повторный вход, назвать
конкретное действие. После изменения модели или версии повторить проверку;
без credentials отметить blocked. Смена среды сохраняет `.claude` пользователя.

## Orca

### Среда и агент

Здесь Orca — ADE проекта stablyai/orca с документацией на orca.dev.
Выбрать фактического агента и способ работы (Chat UI или терминал), проверить
версию Orca и этого агента. Правила, навыки, модель и нативные роли настраивать
по разделу исполнителя выше/ниже; `harness: orca` не заменяет выбор агента.
Источник: [агенты Orca](https://orca.dev/docs/agents/native-chat).

### Проект, запуск и проверка

Подключить существующий репозиторий. Если нужны lifecycle-команды, дополнить
корневой `orca.yaml`: команды нового worktree находятся в `scripts.setup`,
а не в вымышленном верхнеуровневом `setup`. Не добавлять разрушительный archive
по умолчанию. Проверить источник команд в настройках репозитория: Local only
может игнорировать YAML, Run both — дублировать выполнение. Команды должны быть
идемпотентными. Источник: [worktree и миграция команд](https://orca.dev/docs/migrate-from-conductor).

Собственные Orca skills ставить официальным механизмом выбранной версии;
инструкции команд получать из `orca skills list` и `orca skills get <topic>`
после определения фактического CLI. Не копировать внутренние stub-навыки вручную
и не устанавливать все расширения. Источник: [Orca skills](https://orca.dev/docs/cli/skills).
Проверить запуск выбранного агента в нужном worktree, доступность общего набора,
модель, чтение правил и вопрос в выбранном интерфейсе. Lifecycle-команды проверять
в тестовом worktree только если они входят в настройку; не создавать облачную
инфраструктуру ради проверки. Версии Orca и агента и способ восстановления
записать раздельно. Обновлять их также раздельно в согласованном объёме.

## Zed

### Встроенный или внешний агент

Проверить версию Zed и выбранный способ работы. Встроенный Zed Agent использует
модели и инструменты Zed; ACP-агент имеет собственные авторизацию, модель и
конфигурацию. Для внешнего агента открыть ACP Registry (`zed: acp registry`)
и установить только выбранную интеграцию; затем применить раздел её исполнителя.
Zed API key сам по себе не настраивает авторизацию внешнего Codex/Claude.
Источник: [External Agents](https://zed.dev/docs/ai/external-agents).

### Правила, настройка и проверка

Для встроенного агента — AGENTS.md и `.agents/skills/`. Проверить существующие
`.rules` и совместимые файлы: Zed выбирает первый подходящий файл, поэтому
AGENTS.md может быть затенён. Сохранить пользовательский текст и добавить
необходимую маршрутизацию в фактически читаемый файл, затем проверить загрузку.
Источники: [instructions](https://zed.dev/docs/ai/instructions),
[skills](https://zed.dev/docs/ai/skills).

Настроить выбранную модель и профиль инструментов через настройки Zed;
в `.zed/settings.json` сохранять только разрешённые проектные поля по схеме
установленной версии. Не записывать секреты и не переносить весь пользовательский
settings в Git. Если выбор модели/профиля доступен только локально, записать
способ выбора в MANUAL; `config_paths` не должен ссылаться на фиктивный адаптер.
Источник: [tools и профили](https://zed.dev/docs/ai/tools).
Для интерактивных вопросов проверить `ask_user` в профиле. В ветке 1.17 его
[отключили по умолчанию](https://github.com/zed-industries/zed/pull/63038),
оставив включение через `agent.profiles.<profile>.tools.ask_user: true`.
Если пользователь выбирает формы, включение этого инструмента внести в план
настройки Zed, сверить схему и допустимую область конфигурации версии, затем
проверить в новом чате. Не менять глобальные настройки молча и не ослаблять
разрешения остальных tools. Сам опрос до настройки использует доступный канал.

Открыть новую беседу выбранного типа, проверить правила, навык, модель, tools
и форму вопроса. Для ACP отдельно подтвердить передачу вопросов через адаптер:
возможности встроенного агента автоматически не наследуются. После обновления
Zed или ACP-агента повторить проверку затронутой связки, сохранить прежние настройки.

## OpenCode

OpenCode — поддерживаемый харнес платформы рядом с Codex и Claude Code.
Инструкции ниже сверены с официальной документацией 2026-11-24; перед установкой
проверить версию CLI и схему этой версии. V1/V2 различаются: не смешивать их
поля конфигурации и пути agents.

### Общие материалы и адаптер

- Общие правила продукта — корневой AGENTS.md. Не создавать OPENCODE.md с копией
  правил. Обнаружение описано в [Instructions](https://opencode.ai/docs/instructions/).
- Общий набор — `.agents/skills/`, референсы — `.agents/references/`.
  OpenCode обнаруживает Agent Skills; не требуется третья копия платформы.
  Проверить конфликты одноимённых навыков с `.claude/skills/`, `.opencode/skills/`
  и явно настроенными источниками. Правила приоритета —
  [Skills](https://opencode.ai/docs/skills/). Более приоритетная старая копия
  не должна незаметно подменять проектную ревизию.
- В `.opencode/` хранить только нативные адаптеры/команды. Персоны в
  `.agents/agents/` — материалы, а не автоматически работающие OpenCode agents.
- При подключении Impeccable проверить сборку `.opencode` выбранной ревизии;
  добавить требуемый upstream адаптер команды в `.opencode/commands/`, если он
  нужен этой версии. Не дублировать одноимённый skill без необходимости.

### Настройка

1. Проверить `opencode --version` и доступные команды через help. Если CLI нет,
   включить установку по [официальной инструкции](https://opencode.ai/docs/) в план.
2. Подключить выбранного провайдера штатным способом. По текущей документации
   это `/connect`, каталог — `/models`; агент готовит конфигурацию, пользователь
   проходит интерактивную авторизацию, если она необходима. Секреты не просить
   в чате и не писать в Git. DeepSeek/GLM/Claude выбираются по реально доступным
   provider/model ID, а не по предположению о названии.
3. Создать или дополнить один проектный `opencode.json`/`opencode.jsonc`.
   Начальная форма — [шаблон](../templates/opencode.json); он задаёт только схему,
   не готовую модель. Значения модели и назначения брать из `ai.assignments`.
4. Для ролей OpenCode создать нативные agents установленной версии. Для V2
   документация описывает `.opencode/agents/<role>.md` либо `agents` в JSONC.
   Использовать [шаблон роли V2](../templates/opencode-agent.md), заменив placeholders.
   Указать description, mode и model `provider/model`; поддерживаемый variant
   задаётся по схеме. Роль чтения/ревью ограничить соответствующими permissions.
   Не создавать одновременно две конфигурации одного агента. Формат сверять с
   [Agents](https://opencode.ai/docs/agents/) и [Config](https://opencode.ai/docs/config/).
5. В body каждого агента указать роль, чтение AGENTS.md, engineering.yaml,
   соответствующих skills и SPEC/docs/ui. Общие правила не копировать целиком.
   Согласованные нативные определения и конфиг коммитятся вместе с профилем;
   credentials, caches и session state — нет.

Сопоставление ролей: documentation → documentation, code → code-development,
ui → ui-development, code_review → code-review, design_review → design-review,
requirements → requirements, architecture → architecture. Это рекомендуемые ID
адаптеров, а не встроенные имена OpenCode. Создавать только назначенные OpenCode
роли; роли другого харнеса передаются по общему handoff-контракту.

В конфиге можно задать default model, но это не заменяет назначения каждой роли.
Выбор в существующей сессии может иметь приоритет: после перенастройки проверить
фактическую модель нового запуска. Точный provider/model и способ запуска
подтверждаются по [Models](https://opencode.ai/docs/models/); аутентификация — по
[Providers](https://opencode.ai/docs/providers/).

### Проверка и обновление

Проверить конфигурацию по схеме установленной версии, обнаружение AGENTS и skills,
запуск каждого уникального назначения, модель и доступные инструменты. Дизайн-ревью
должно получать снимки/рендер, а не только исходники. Проверка без credentials
подтверждает лишь статическую конфигурацию. Записать версии и результаты в MANUAL.

Обновления и смена моделей — через
[перенастройку продукта](model-harness-configuration.md#перенастройка-существующего-продукта).
Глобальная `~/.config/opencode/` не меняется при проектной настройке. Сохранить
пользовательские providers, agents, permissions и MCP; повторный запуск не должен
дублировать записи. Смена UI-режима не удаляет OpenCode и его настройки.

## Интерактивный выбор пользователя

Markdown `- [ ]` в сообщении — описание вариантов, а не гарантия кликабельной
формы. Опрос проводит текущая сессия, даже если пользователь настраивает другую ADE.
Перед первым вопросом проверить реально доступные tools, их schema и ограничения
режима. Не менять режим или permissions ради появления формы.

| Текущая сессия | Как задавать вопрос |
|---|---|
| Codex | Доступный `request_user_input_async` с `options`; либо `request_user_input`, только когда режим и инструкции разрешают его вызов. В проверенной desktop-сессии async имеет варианты и свободный ответ, но не имеет поля multiSelect |
| Claude Code | `AskUserQuestion`; для нескольких ответов — `multiSelect`, если поле есть в схеме доступного инструмента; собственный ответ через штатный Other/notes |
| OpenCode | `question` с `multiple: true` для нескольких ответов, если поддерживается версией и клиентом |
| Orca | Инструмент фактического агента; Chat UI отображает структурированные карточки вопросов, терминал использует интерфейс CLI |
| Zed | Нативный `ask_user`, только если реально доступен; для ACP — возможности выбранного агента и адаптера. Не предполагать наличие формы по одному названию ADE |

Источники: [Claude tools](https://code.claude.com/docs/en/tools-reference#askuserquestion-tool-behavior),
[схема вопросов Claude](https://code.claude.com/docs/en/agent-sdk/user-input),
[OpenCode question](https://opencode.ai/docs/tools/#question),
[Orca question cards](https://orca.dev/docs/agents/native-chat#questions-from-the-agent),
[Zed releases](https://zed.dev/releases/preview).
Имена Codex tools и отсутствие multiSelect проверены по schema текущей сессии
2026-11-25; это наблюдение, не обещание одинакового API во всех клиентах.
У Zed список tools зависит от версии и профиля: доступность ask_user нужно проверить.

### Правила опроса

- Закрытые вопросы задавать нативной формой, если доступный инструмент разрешён
  для такого вопроса. Сохранить свободный ответ; не добавлять дубликат «Другое»,
  если интерфейс уже предоставляет его автоматически.
- Один выбор — опции; несколько — нативный multi-select/чекбоксы. Если multi-select
  отсутствует, последовательно спросить «Подключить Codex?» → Да/Нет,
  затем то же для остальных ещё не выбранных сред. Показать собранный набор.
- Если лимит опций меньше списка, разбить выбор на группы или шаги. Например,
  четыре пути старта при лимите в три опции разделяются на два шага; свой текст
  вводится штатным полем.
  Не обрезать варианты и не уходить в текст только из-за длины списка.
- Если tool недоступен, запрещён для этого типа вопроса, форма не отображается
  или пользователь предпочитает текст, использовать короткий нумерованный список;
  для нескольких значений принять номера через запятую. Однократно назвать причину.
  Не требовать редактирования Markdown и не создавать отдельный сайт-опросник.
- Вложения запрашивать через обычный чат. Не просить пароли или ключи ни в форме,
  ни текстом. Для согласования действий соблюдать ограничения самого tool:
  вопрос о предпочтении не подменяет разрешение на установку или публикацию.
- Асинхронный вызов не означает ответ: ждать поступления выбора перед зависимым
  действием; разрешённую независимую работу можно продолжить. Предвыбор, таймаут
  и пустой результат не считать согласием. Не повторять уже полученные ответы.
- В MANUAL фиксировать фактически проверенный способ диалога и ограничения.
  Не спрашивать фиктивный тестовый вопрос при обычной настройке: первый реальный
  выбор пользователя служит проверкой формы.

## Приёмка и корректировка

Проверить каждую выбранную связку ADE/исполнитель, включая новую сессию после
изменения адаптеров. Сопоставить surfaces, primary_surface, harnesses, assignments
и семь roles. Для каждой: версия, правила, навык, модель, инструменты, форма
вопроса либо причина текстового fallback, проверенный запуск и честный статус.
Непроверенное обозначить явно; работающий Codex не доказывает готовность Zed+Codex.
Для смены предпочтений использовать [перенастройку](model-harness-configuration.md#перенастройка-существующего-продукта),
сохранить незатронутые назначения, проверить новые и записать способ отката.
