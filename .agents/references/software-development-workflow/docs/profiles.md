# Профили и настройка процесса

Профиль управляет глубиной документации и условиями подключения практик, но не снижает проверки применимого upstream skill. Не создавайте пустые документы ради дерева каталогов.

| Профиль | Минимум | По условиям |
| --- | --- | --- |
| `lean` | README, AGENTS, конфигурация, краткий HLD; критерии и результаты проверки в задаче | SPEC/план для значимой работы; ADR для значимых решений; контракты при наличии границы |
| `standard` | Минимум `lean`, CONSTRAINTS; оценка влияния и доказательства каждой значимой работы | LLD сложных модулей; SPEC/план; Data/API/Events; долг и инициативы |
| `critical` | Минимум `standard`, разделы влияния и проверки в плане, измеримые NFR и анализ угроз в HLD/LLD | Для эксплуатируемой системы — SLO, восстановление и откат в HLD/LLD; LLD затронутых критичных модулей |

`standard` — рекомендуемый исходный профиль. `critical` выбирается по последствиям отказа, а не по размеру команды. Исследовательский прототип использует `lean`; перед превращением в продукт его профиль и пробелы пересматриваются.

Независимо от профиля действуют язык, frontmatter, уникальные ID, единый источник задач, фиксация значимых решений и проверка актуальности. Для любого профиля наличие API, данных и событий включает соответствующие контракты; чувствительная информация и эксплуатация требуют соответствующих разделов HLD/LLD и проверок задач. Упрощение означает меньший объём, а не пропуск важного содержания.

## Расширение

Конфигурация перечисляет возможности продукта (`capabilities`), добавочные обязательные артефакты (`required_artifacts`), карту путей (`paths`) и исключения (`exceptions`). Она описывается в [контракте интеграции](integration.md). Списки добавочных требований объединяются без дубликатов; удаление требования через пустой список не допускается. Скалярные настройки продукта уточняют платформенный default в разрешённых пределах.

Каждое исключение содержит правило, основание, область, владельца, доказательство согласования, компенсирующую меру и дату пересмотра. Конфликт обязательных требований нельзя разрешать принципом «последний файл победил». Неизменяемые требования этого стандарта (русский язык, Markdown + frontmatter, сохранение истории ADR) не отменяются профилем; их изменение требует новой версии стандарта.

Смена профиля — отдельное изменение конфигурации с оценкой недостающих документов. Понижение профиля не удаляет историю, открытый долг и обязательства платформы. Нельзя менять профиль только ради прохождения текущей проверки.
