# Метаданные и жизненный цикл

Каждый авторский Markdown-документ продукта, включая README, AGENTS, ADR, план, задачи и CHANGELOG, начинается с YAML frontmatter. Исключения: неизменённые сторонние файлы и автоматически сгенерированные документы — их происхождение и исключение фиксируются в конфигурации. Этот стандарт не добавляет поля в upstream SKILL.md.

Метаданные проверяются структурно: frontmatter разбирается безопасно, с отклонением повторяющихся YAML-ключей, и проверяется полученный объект, а не весь Markdown. Правила проверки описаны в [критериях качества](validation.md). Даты записываются строками в кавычках `YYYY-MM-DD`. Поле `schema_version` версионирует формат метаданных, версия стандарта фиксируется отдельно в конфигурации продукта.

| Поле | Смысл |
| --- | --- |
| `schema_version` | Сейчас `1` |
| `id` | Уникальный ID в пределах продукта; после переноса не меняется |
| `type` | Тип из [каталога артефактов](artifacts.md); собственные расширения требуют изменения стандарта |
| `title` | Русское название |
| `status` | Состояние по таблице ниже |
| `language` | Всегда `ru` для создаваемой документации |
| `owner` | Реальный человек или команда, отвечающие за актуальность |
| `created`, `updated` | Даты создания и последнего содержательного изменения |
| `related` | Массив ID других локальных артефактов; ссылки в тексте ведут к файлам |
| `sources` | Пути от корня продукта и/или URL первоисточников |
| `reality` | Для HLD/LLD: `current`, `target` или `mixed` |
| `level` | Для ADR: `hld` или `lld` |
| `supersedes` | ID заменяемого ADR, если решение пересматривается |
| `external_refs` | URL задач внешнего трекера, PR и иных внешних доказательств |
| `extensions` | Объект платформенных метаданных; не переопределяет общие поля |

Допустимые значения `type`: `standard`, `guide`, `readme`, `constraints`, `hld`, `lld`, `adr`, `capability-map`, `spec`, `plan`, `tasks`, `api`, `events`, `data`, `debt`, `initiative`.

| Тип | Состояния |
| --- | --- |
| ADR | `proposed` → `accepted` → `superseded` / `deprecated`; `proposed` → `rejected` |
| Остальные | `draft` → `active` → `completed` / `deprecated`; `draft` → `deprecated` |

`active` означает действующий документ, а не автоматически реализованное решение. `completed` используется для завершённых планов, задач, инициатив и долга. Для долга принятие риска описывается в активном документе с владельцем и датой пересмотра; это не закрытие долга. Шаблоны имеют `draft`, ADR — `proposed`.

Все ADR хранятся непосредственно в `docs/architecture/decisions/`, без подкаталогов уровней, и используют одну последовательность `ADR-0001`, `ADR-0002`, … независимо от HLD/LLD. Перед merge проверяются коллизии с целевой веткой. Принятое содержание ADR не переписывается: новый ADR содержит `supersedes`, старый переводится в `superseded` со ссылкой. Исправление опечатки и изменение служебного статуса допустимы с записью причины; решения не удаляются.

В `reality: mixed` разделы явно помечают текущую и целевую архитектуру. Принятый ADR не доказывает, что решение уже реализовано. Для текущего состояния нужны ссылки на код и проверки; для целевого — SPEC и задачи.

В одном `tasks/todo.md` задачи имеют стабильные `TASK-0001` в заголовках; ID frontmatter относится к списку целиком. Для внешнего трекера используются его ID и URL. Зависимости задач не должны образовывать циклы. `related` содержит только ID документов, а ID задач размещаются в содержимом плана.
