# Заказы — инструкции для агентов (Claude Code)

Перед ответом, планированием, исследованием, правками или запуском команд
в каждом сообщении откройте и перечитайте `AGENTS.md` в корне репозитория
и следуйте ему как собственным инструкциям. Единственный источник правил
продукта — `AGENTS.md`; в этом файле их дубликатов нет.

Отличия для Claude Code:

- проектные навыки автоматически обнаруживаются в `.claude/skills/`;
  slash-команды и персоны подключены по setup-гайду набора для Claude Code;
- пути `.agents/...`, упомянутые в AGENTS.md, остаются валидными: проектные
  копии хранятся в обоих каталогах (`.agents/` и `.claude/`) и идентичны;
- правило AGENTS.md «предпочитайте проектную копию одноимённому глобальному
  навыку» здесь означает каталог `.claude/skills/`.

## Правила агентной работы
- Ведите AGENTS.md и CLAUDE.md полностью на русском языке: заголовки, пояснения, правила и новые разделы. Сохраняйте без перевода только команды, пути, имена файлов, названия продуктов и технические идентификаторы. При настройке существующего продукта переведите и остальные разделы этих файлов, сохраняя смысл и силу всех пользовательских правил.
- Обязательно соблюдайте процесс разработки. Перед изменением прочитайте `.agents/references/docs/workflow.md`, карту `.agents/references/docs/upstream.md` и проектные полномочия `docs/agent-policy.md` (если создан); для Claude Code те же референсы лежат в `.claude/references/`.
- Используйте проектные навыки из `.agents/skills/` (Codex и OpenCode) и `.claude/skills/` (Claude), роли из `agents/` и материалы из `references/` этих каталогов. Эти версии имеют приоритет над одноимёнными глобальными навыками. Применяйте навыки по характеру задачи; не отменяйте обязательные проверки процесса.
- Держите разделы продукта в AGENTS.md, помимо блока платформы: правила на каждый запрос (перед сообщением выбирать применимые навыки из установленных проектных и сообщать на русском, какие применяются и почему; при наличии using-agent-skills начинать с его чтения), таблица маршрутизации задач по навыкам — она покрывает каждый навык из engineering.yaml, при добавлении навыка строка добавляется; краткий контекст продукта, конвенции работы, команды проверки и раздел навигации Graphify. CLAUDE.md — тонкая ссылка на AGENTS.md с отличиями Claude Code; правила продукта в нём не дублируются.
- Выбирайте исполнителей по ai.roles и ai.assignments в engineering.yaml; модель и харнес текущей сессии должны соответствовать назначению либо требуется явная передача работы. Ревью выполняйте в отдельном контексте. Способы запуска и ограничения храните в MANUAL.md.
- Для целевого UI поддерживайте docs/ui/DESIGN.md и vision.md, components.md, screens.md в docs/ui/<имя инженерной SPEC>/. UI-навыки применяются и к продукту, и к экспериментам prototypes/PROTOTYPE-NNNN-slug; прототип проверяет гипотезу, перенос решений в продукт проходит инженерную SPEC.
- Порядок работы: контекст → уточнение требований → проектирование → планирование → реализация → проверка → независимое ревью → выпуск → развитие. Выполняйте применимые согласования и проверки процесса разработки.
- Храните требования, HLD/ADR и технические решения SPEC, контракты и доказательства проверок в Git продукта; обновляйте затронутую документацию вместе с кодом. Не выдумывайте результаты или согласования.
- Настройка и запуск описаны в `MANUAL.md`. Состав и происхождение проектного набора зафиксированы в `engineering.yaml`; паспорт продукта — в `product.yaml`.
- Для управления набором читайте проектную копию `.agents/skills/go-project-platform-manager/SKILL.md` (для Claude Code — `.claude/skills/go-project-platform-manager/SKILL.md`). Перед установкой или обновлением покажите структурированный список навыков, источников, версий, агентов и референсов для согласования. Глобальное обновление не обновляет проектные копии.
- Если проектные материалы отсутствуют, завершите согласованную установку; не подменяйте их молча глобальными версиями. В новом worktree материалы приходят из Git; восстанавливайте только генерируемые артефакты (например, граф graphify).
