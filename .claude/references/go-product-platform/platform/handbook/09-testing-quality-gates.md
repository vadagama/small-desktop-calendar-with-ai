# Тестовая стратегия и контрольные проверки качества

**В этом документе:** [Уровни контроля качества](#testing) · [Базовые проверки качества Go](#go-tests)

<a name="testing"></a>

## Уровни контроля качества

| Проверка | Когда | Технологии |
|---|---|---|
| 1. Статические проверки | Каждое изменение | `gofmt`, `go vet`, `golangci-lint`, строгий режим TypeScript, ESLint, Buf lint |
| 2. Модульные тесты / имитации | Каждое изменение | `go test`, Vitest, Testing Library, имитации привязок Wails |
| 3. Интеграционные проверки | MR | Настоящая PostgreSQL 18, SQLite, контракты Connect, Wails IPC, migrations |
| 4. Браузерные E2E + визуальные проверки | MR / affected | Playwright, снимки экрана, трассировки, axe-core |
| 5. Нативные E2E | Перед merge релевантных клиентов | Wails desktop; iOS XCTest; Android Espresso/Maestro |
| 6. Базовая проверка рабочей среды | Релиз | Подписанные приложения, упакованный образ VM, разрешения, первый вход, откат |
| Безопасность / цепочка поставки | MR + release | `govulncheck`, SBOM, сканирование образа, поиск секретов, изолированная среда инструментов агента |

**Локально:** в первую очередь тесты связанных и затронутых компонентов без сборки приложения. **В CI:** полный контракт, миграции, интеграционные проверки и проверки, критичные для выпуска, даже если локальная разработка не использует Docker. Результат независим от «успешно на моем Mac». GitLab Runner может собирать OCI в Linux и подписывать артефакты, исполнители macOS/iOS — подписывать .app/.ipa, Android — .aab.

<a name="go-tests"></a>

### Пример базовых проверок качества Go

```bash
gofmt -w .
go vet ./...
go test ./...
go test -race ./...   # отдельный CI job / supported targets
govulncheck ./...
buf lint
buf breaking --against '.git#branch=main'
```

Для CI проверка форматирования должна **падать**, а не изменять файлы. `go test -race` и часть задач для нативных платформ и профилей запускаются на поддерживаемых OS/ARCH и при необходимости отдельно от быстрого цикла.

**Анализ влияния изменений на тесты с помощью ИИ:** изменения `.proto` → все затронутые SDK и контрактные тесты; изменения домена → доменные тесты + интеграция API; React → компонентные тесты + затронутые тесты Playwright; мост Wails → нативные E2E настольного приложения; схема SQLite → восстановление после офлайн-работы; аутентификация/разрешения → расширенный набор проверок безопасности; изменение CI/развёртывания → полный цикл базовых проверок.
