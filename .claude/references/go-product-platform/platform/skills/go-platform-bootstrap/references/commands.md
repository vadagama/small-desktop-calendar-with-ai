# Go Product Platform — справочник операций для агента

Отдельного установщика для пользователя у платформы нет: операции выполняет
агент своими инструментами (осмотр файлов, копирование, git, shell, запуск
согласованных скриптов), подтверждая изменение у пользователя. Обычным
пользователям достаточно попросить агента на естественном языке; таблица ниже —
расшифровка, что агент фактически делает.

| Действие агента | Изменения | Как выполняется |
|---|---|---|
| Отчёт о глобальных установках и наборе проекта | только чтение; глобальные каталоги — с согласия | осмотр `~/.agents/skills/`, `~/.claude/skills/` и engineering.yaml продукта |
| Выбрать профиль проекта | отслеживаемое изменение; запросить подтверждение | состав профиля из [skill-sources.md](skill-sources.md#профили-и-критерии); скопировать набор и записать состав в engineering.yaml |
| Установить отсутствующие навыки глобально | изменяет `~/.agents` и `~/.claude`; явное согласие | клонировать источники из [skill-sources.md](skill-sources.md) на согласованных ревизиях; копировать в оба каталога, не перезаписывая существующее |
| Проверить актуальность ревизий | только чтение; сетевое обращение к upstream | сравнить ревизии engineering.yaml с источниками (локальные клоны или `git ls-remote`); изменения показать планом |
| Обновить глобальные снимки навыков | изменяет **оба** глобальных каталога; явное согласие | по одобренному плану: обновить глобальные копии, сохранив прежние до успеха; ревизии — в engineering.yaml |
| Проверить проект | только чтение | чек-лист из [SKILL.md](../SKILL.md#критерии-готовности): наличие `SKILL.md` всех навыков, соответствие engineering.yaml, свежие команды стека |
| Подготовить продукт по согласованному плану | записи в проекте; требуется разрешение | [SKILL.md](../SKILL.md#полная-настройка-продукта): стек → инициализация → навыки → engineering.yaml → [полная интеграция Graphify](../../../references/graphify-installation.md) |
| Восстановить материалы в worktree | только локально, без глобальных и сетевых изменений | `.agents/` и `.claude/` приходят из Git; построить генерируемые материалы (граф graphify) |

- Глобальное обновление затрагивает несколько проектов. Изучите изменения по
  ревизиям; требуется отдельное одобрение, помимо самой проверки.
- Upstream-ревизия может измениться после проверки. Обновляйте только то, что
  показано и одобрено.
- Orca обновляется своим официальным механизмом, Graphify — командой
  `uv tool upgrade graphifyy`; каждый способ — только с согласия.
- Проектный управляющий навык — `.agents/skills/go-project-platform-manager/SKILL.md`
  (тот же файл в `.claude/skills/`); по выбору навыков проекта всегда сверяйтесь с ним.

## Процесс продукта (SDD)

Этапы и артефакты задают главы 19–20 руководства и процесс разработки;
проектные исключения — `docs/agent-policy.md` продукта. Агент:

| Операция | Как выполняется |
|---|---|
| Новая фича | Создать `docs/specs/<SPEC-ID>/requirements.md` по контракту артефактов |
| Перед реализацией | Заполнить design.md, plan.md и tasks.md; зависимые фичи — ready/released |
| Проверки | Реальные команды продукта (unit/e2e/contract); команда и результат — в verification.md |
| Новый цикл | Изменение согласованных входов — пересогласование и свежие проверки; после выпуска — delta-spec с новым ID |
| Перед слиянием | Независимая сессия ревью; код и документы зафиксированы в Git |

High-риск и выпуск требуют фактического решения человека и записи ссылки на решение
в PR/журнале фичи. Никакие операции платформы не выполняют deploy.

## Опциональный UI canvas

Установка описана в
[canvas-installation.md](../../../references/canvas-installation.md) материалов
платформы: агент клонирует и проверяет источник, создаёт `.canvas/` и отслеживаемый
`design/`, для существующего UI подключает приложение. После установки проверить
`python3 .canvas/board.py doctor`. Источник —
https://gitlab16.skiftrade.kz/design/app-canvas.

## Общий набор UI и экспериментальные прототипы

Следовать [prototyping-installation.md](../../../references/prototyping-installation.md):
проверенный источник → согласованный состав и SHA → оба проектных каталога →
engineering.yaml → целевой UI и `docs/ui/`; отдельно эксперименты
`prototypes/PROTOTYPE-NNNN-slug`, если выбраны → проверки и MANUAL.
Команды с `-g` не использовать для проектной установки.
