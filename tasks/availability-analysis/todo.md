# Задачи: аналитика доступности из AI-Ассистента

Основание: [план](plan.md) и [спецификация 1.9](../../docs/proposals/assistant-availability.md). AV01–AV21 выполнены; фактические файлы и результаты проверок сопоставлены в [отчёте](../../docs/implementation/availability-analysis.md). Предполагаемые файлы ниже сохранены как исходная декомпозиция; тесты объединены без дублирования. Существующий todo первой версии не изменяется.

Реализация выполнена последовательными срезами; предполагаемая декомпозиция ниже сохранена для трассировки. Каждая задача — один срез S/M (не более пяти предполагаемых файлов). Области файлов ниже — ориентир перед реализацией, новые пути помечаются самим фактом отсутствия исходника; перед редактированием проверить git status и фактическую структуру. Если требуется больше пяти файлов, выделить дополнительный срез, не расширять задачу молча.

Команды запускаются из корня. Сфокусированный unit-тест: `node --import tsx --test <указанный tests/agent/*.test.ts>`; Electron: `npm run test:desktop -- <указанный tests/desktop/*.spec.ts>`. Новые тестовые файлы — планируемые, команды применимы после их создания. Для каждого среза выполнять нужные тесты и `npm run typecheck`; сборку/форматирование по затронутой области и контрольной точке. UI-проверки — headless/скрыто с изолированным профилем. Никаких реальных приглашений для проверки.

Обязательная часть каждой UI-задачи — соответствие прототипу, а не свободная переработка. Для каждой AI-задачи — типизированный вызов/событие, не парсинг произвольного текста модели. Критерии задачи дополняются [Definition of Done](../../.agents/references/definition-of-done.md).
