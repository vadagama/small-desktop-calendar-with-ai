# План реализации: аналитика доступности из AI-Ассистента

Дата: 9 ноября 2026. Статус: AV01–AV21 реализованы и проверены. [Отчёт и доказательства](../../docs/implementation/availability-analysis.md).
Размещение в отдельной папке выбрано пользователем. `tasks/plan.md` и `tasks/todo.md` первой версии не изменяются. Задачи ведутся локально в [todo.md](todo.md); публикация в трекер/коммиты/релиз в этот запрос не входят.

## Основание и результат

Требования — [спецификация, редакция 1.9](../../docs/proposals/assistant-availability.md).
Иконка раздела свободных слотов — `CalendarClock`, календарь с часами; значок графика оставить для будущей аналитики.

Обязательный визуальный и интерактивный эталон — [прототип](../../prototype/availability.html) и его `availability-demo.css`, `availability-demo.js`, `availability-people-picker.js`. Локальный просмотр: [дашборд](http://127.0.0.1:5173/availability.html?v=horizontal).

Пользователь пишет «найди свободные слоты на этой неделе для …», «найди время для встречи с тимлидами во вторник» или перефразирование. Ассистент разрешает людей и даты, автоматически открывает слева вкладку дашборда и показывает loading до получения доступности. В панели часы 00–24 по горизонтали, даты вниз, участники строками внутри даты, поиск/удаление участников как в форме события. Выбранное окно после повторной проверки передаётся в существующий черновик. Создание встречи и сохранение памяти требуют своих штатных подтверждений.

## Обязательный контракт реализации

1. Внешний вид и взаимодействия должны соответствовать последнему прототипу: стиль Small, обе прокрутки, закрепление имён/часов, размеры и плотность, поиск участников, общие окна и панель выбора. AV17 и AV19 проверяют это явно; «похожая таблица» не считается выполнением.
2. Для открытия не требуется отдельная команда «покажи аналитику». Поиск доступности — намерение, а не жёсткий список ключевых слов. Дашборд заменяет прежнюю выдачу карточек слотов для этого сценария.
3. Новая UI-панель в существующем React/Electron/Dockview; не открывать внешнюю веб-страницу и не вставлять отдельную HTML-оболочку прототипа в production.
4. Данные и команды передаются типизированным bridge. Модель не вычисляет доступность, не выбирает аккаунт и не исполняет URL/HTML/JS. Предлагаемый tool `showAvailabilityAnalysis` — read-only запрос на открытие/обновление, не создание встречи.
5. Состав — подтверждённые ID из каталога/актуальной памяти; «тимлиды» не превращаются в произвольный список по первой странице поиска. Отсутствие/неоднозначность группы разрешается уточнением.
6. Для дня анализ ограничивается этим днём и отображает один блок даты; для недели — дни недели. Шкала всегда 00–24. Все даты вычисляются в Asia/Almaty по текущему времени, прошлые интервалы не предлагаются.
7. Явная длительность важнее контекста и памяти. При её отсутствии использовать существующие предпочтения, затем видимый default 60 минут; это не должно блокировать открытие дашборда.
8. Параметры панели и текущей AI-задачи синхронизируются. Новый независимый запрос заменяет параметры, уточнение продолжает задачу; отменённые/поздние ответы не восстанавливают старый состав или закрытую панель.

## Проверенная исходная база

- `src/agent/calendar-runtime.ts`: текущий `findSlots`; `src/agent/content/skills/availability/SKILL.md`: инструкция показать до пяти карточек и уточнить неизвестную длительность. Эти правила нужно заменить для сценария дашборда.
- `src/agent/content/skills/people-search/SKILL.md`, `src/main/memory-tools.ts`: память/группы, проверка каталога. Переиспользовать механизм вместо отдельной памяти групп.
- `src/shared/calendar-tools.ts`: `slotsToolInput` принимает одну дату. `src/shared/calendar.ts`: `SlotsResult` содержит общие интервалы, но не персональный free/busy и полноту покрытия.
- `src/main/assistant.ts`: проверка enabled-навыка, адресация событий владельцу; существующий `eventListChannel` — пример доставки структурированного результата, не готовый канал доступности.
- `src/renderer/DockWorkspace.tsx`, `DesktopWorkspace.tsx`: реестр и открытие панелей. `MeetingPeoplePicker.tsx`, `useAvailability.ts`: поиск/состав, защита от поздних запросов. Изменять узко, сохраняя сценарий создания события.
- Прототип не содержит реальных интеграций и не доказывает возможности календарного API.

## Граница синтетического и реального среза

AV01 проверяет источник персональных данных прежде дорогой реализации. Если источник недоступен, результат — документированный блокер и подтверждённый синтетический контракт. UI и транспорт можно реализовать на фикстурах, но AV14, AV15 и сквозная реальная приёмка не помечаются выполненными по демо.

Если подтверждён только текущий `SlotsResult`, допускается честный ограниченный режим общих окон, но он не завершает задачу персонального дашборда. Не реконструировать занятость отдельных людей из общих слотов. Расширение backend/API при необходимости — отдельное согласованное изменение; создание вымышленного endpoint не считается выполнением AV01/AV14.

## Проверки

Общие команды существуют в корневом package.json: `npm run typecheck`, `npm test`, `npm run build:desktop`, `npm run format:check`. Сфокусированные команды и предполагаемые новые тестовые файлы указаны в задачах. Новые файлы не выдаются за существующие runnable-тесты до их создания.

Playwright — headless; все Electron-окна скрыты, профиль изолирован. Не открывать trace viewer/отчёты автоматически. Визуальная сверка с прототипом использует одинаковые синтетические данные, масштаб, viewport и scrollLeft; сохранять скриншоты штатного результата, выбора, поиска, unknown/error. Проверять 320/768/1024/1440 CSS px, длинные имена, 1/20 участников, день/неделю и 5/7 дней. Computed font-size — по общим токенам в Electron.

Два разных доказательства AI-качества: детерминированные SDK/bridge-тесты структуры/прав/доставки и смысловые прогоны перефразирований с поддерживаемой LLM. В сетевых прогонах только разрешённый тестовый контур и синтетические каталоги; секреты не попадают в файлы и логи.

## Риски и решения

| Риск                                                   | Как проверяется/ограничивается                                                           |
| ------------------------------------------------------ | ---------------------------------------------------------------------------------------- |
| Нет персонального free/busy                            | AV01 рано; AV14 не закрывать общими слотами или фикстурами                               |
| Группа «Тимлиды» неполная/неоднозначная                | AV10: память прежде каталога, пагинация, подтверждённый состав/уточнение                 |
| Дата/длительность разрешаются иначе старой инструкцией | AV08/AV12: единые правила, часы из тестового контекста, явно видимый default             |
| Карточки `findSlots` продолжают быть главным ответом   | AV11/AV12/AV18: проверить и tool-description, и системные инструкции, и UI-представление |
| Состояние UI расходится с историей чата                | AV13/AV15: ревизия задачи, адресация, инвалидация и контекст панели                      |
| Таблица технически работает, но отличается от макета   | AV17/AV19: обязательная сравнительная визуальная приёмка по прототипу                    |
| Утечка занятости/смешение аккаунтов                    | AV09/AV14/AV15: read-only права, минимум данных, очистка аккаунта, owner/request guards  |

Критерий завершения: выполнены [критерии функционала](../../docs/proposals/assistant-availability.md), задачи/контрольные точки и [Definition of Done](../../.agents/references/definition-of-done.md). Нужен фактический путь «промпт → подтверждённые участники/дата → автоматически открытый дашборд → выбор → проверенный черновик». План сам по себе не разрешает приглашения, публикацию или релиз.
