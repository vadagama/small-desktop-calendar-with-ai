# Задачи первой версии

Статус: **T01–T03 и компоновка T07 проверены; T04–T06 реализованы с открытыми реальными
интеграционными проверками**. Основание — [план](plan.md).
Для невыполненных задач указаны предполагаемые области.
Каждый срез ограничивается пятью файлами; дополнительные изменения отделяются
в следующую задачу. Команды T01 зафиксированы в корневом `package.json`.

## T01 — Безопасный вызов инструмента через Vercel AI SDK

- [x] Зафиксированы версии SDK/provider, поддерживаемый Node engine и команды.
- [x] Реальный SDK-loop выполняет синтетический tool и возвращает результат.
- [x] Некорректные аргументы и отмена дают ожидаемый исход без внешних запросов.

Проверено 28 октября 2026 года: 12 тестов, typecheck, сборка, форматирование
и запуск скомпилированного сценария. [Результаты и ограничения](../docs/implementation/t01-sdk-runtime.md).
Обновление README, плана и отчёта выполнено отдельным документационным срезом.

Проверка: тест через SDK с моделью-заглушкой на LLM-границе; схема, ошибка
и AbortSignal; typecheck по созданному манифесту. Зависимости: нет.
Файлы: `package.json`, lockfile, `tsconfig.json`, `src/agent/runtime.ts`,
`tests/agent/runtime.test.ts`. Размер: M.

## T02 — Запуск desktop-окна

- [x] После ревью ADR-002 создана локальная оболочка для macOS 15.1 arm64.
- [x] Окно показывает локальный UI, sandbox/isolation включены, Node в UI недоступен.
- [x] Сборка запускается без глобально установленного Node у конечного пользователя.

Проверен dev-режим и локальная `.app` с `PATH` без Node.
[Команды, проверки и ограничения T02–T03](../docs/implementation/t02-t03-desktop.md).

Проверка: запуск dev и упакованной сборки на Mac; проверка изоляции renderer.
Зависимости: решение по ADR-002. Файлы: build-конфигурация, `package.json`,
`src/main/index.ts`, `src/preload/index.ts`, renderer entry. Размер: M.

## T03 — Диалог с инструментом в окне приложения

- [x] Чат отображает текст, streaming и результат безопасного tool из T01.
- [x] Ошибка, ожидание ввода и отмена различимы; повторный запрос не смешивает turns.
- [x] Transport/bridge не раскрывает ключи и произвольные привилегированные вызовы.

Выполнено срезами: контракт и transport; utility process и IPC; React-панель;
интеграционная проверка; документация. Запись календаря отсутствует.

Проверка: интеграционная проверка stream через transport и UI-проверка сценариев.
Зависимости: T01, T02. Файлы: `src/agent/runtime.ts`, transport, bridge,
компонент чата и интеграционный тест. Размер: M.

### Контрольная точка A

## T04 — Подключение выбранного LLM-профиля

- [x] UI позволяет задать Small vLLM либо персональный OpenAI-compatible профиль.
- [x] Ключ сохраняется через Keychain; смена origin не пересылает старый ключ.
- [ ] Реальные streaming/tool calls проверены отдельно от синтетического теста;
      нет скрытого fallback между профилями.

Проверка: тест сетевого адаптера на локальном сервере, Keychain с синтетическим
секретом и очисткой; реальный endpoint после настройки пользователем.
Зависимости: T03. Файлы: profile model, provider adapter, Keychain adapter,
settings UI и integration test. Размер: M.

Реализовано в `codex/t04-llm-profiles`: локальный HTTP streaming/tool loop и
настоящий Keychain проверены, включая упакованную сборку. Проверка выбранной
GLM на Small endpoint остаётся открытой до ввода ключа пользователем в UI.
Подробности: [отчёт T04](../docs/implementation/t04-llm-profiles.md).

## T05 — Вход сотрудника в Small

- [ ] Встроенный вход определяет текущего пользователя, без персонального логина в коде.
- [ ] Сессия обновляется; отзыв ведёт к повторному входу; выход очищает локальный доступ.
- [ ] Два тестовых аккаунта изолированы; секреты не видны модели/UI-логам.

Проверка: сценарии auth/refresh/logout на синтетическом API и read-only профиль
при настроенной сессии; Keychain refusal. Зависимости: T02.
Файлы: auth service, session store, login UI, profile adapter, auth test. Размер: M.

Реализация T05 добавлена в `codex/t05-small-login`: локальная форма, четыре
фиксированные операции Small, отдельный cookie jar, Keychain, refresh и выход.
Синтетические проверки и упакованное приложение проходят; пункты выше
остаются открытыми до реального входа и проверки двух разрешённых аккаунтов.
[Проверки и ограничения T05](../docs/implementation/t05-small-login.md).

## T06 — Просмотр календаря

- [ ] День/неделя/месяц и выбор календарей показывают события из Team API.
- [ ] Пустой период отличается от недоступных/неполных данных; видны ошибки прав/сети.
- [ ] Время и карточка события совпадают с API в явном часовом поясе.

Проверка: синтетические ответы, read-only сверка нескольких доступных событий
без сохранения персональных payload в repo. Зависимости: T05.
Файлы: calendar adapter, events query, calendar widget, event card, tests. Размер: M.

Реализация T06 разделена на `codex/t06-calendar-read` и `codex/t06-calendar-ui`:
API, сессия и узкий IPC; затем календарный интерфейс и Electron E2E.
Синтетическое чтение, карточки, неполные данные и изоляция аккаунтов проверены.
Пункты выше остаются открытыми до сверки с реальными календарями Small.
[Проверки и ограничения T06](../docs/implementation/t06-calendar-read.md).

## T08 — Подбор общего времени

Добавлен [диалог подбора общего времени](../docs/implementation/t08-availability.md):
явный выбор участников, дата/длительность, проверка индивидуальной занятости
и отображение слотов. Синтетические проверки проходят; реальный API, полный
состав команды остаются открытыми.
[Вызов из AI-чата](../docs/implementation/t08-assistant-tools.md) добавлен и проверен
на синтетических API: явный полный список, отдельные карточки результатов,
ограниченный канал worker/main и отмена.

Первый срез реализован в `codex/t08-directory`: проверен клиентский mapping
`person_guid` → `participant_ids`, добавлен постраничный поиск сотрудников
в доверенном сервисе с ограниченным GET-маршрутом. [Результаты и оставшаяся работа](../docs/implementation/t08-directory.md).

- [ ] Участники разрешаются по подтверждённому mapping, неоднозначность уточняется.
- [ ] Полнота состава команды проверяется; неизвестная занятость не считается свободой.
- [ ] Показаны общие варианты либо объяснение отсутствия, без исключения участников.

Проверка: синтетическая группа с конфликтами/неполным каталогом; read-only busy/slots.
Зависимости: T04, T06, подтверждённый контракт каталога.
Файлы: directory adapter, availability service, find-slots tool,
slots card, tests. Размер: M.

## T09 — Создание подтверждённой встречи

Первый срез: [черновик в AI-чате](../docs/implementation/t09-meeting-drafts.md).
Проверены параметры, 30 минут по умолчанию, организатор текущего аккаунта,
повторное чтение доступности и карточка с аджендой/URL. [Следующий срез](../docs/implementation/t09-confirm-meeting.md) добавляет
подтверждение версии, durable-журнал, запись и проверку чтением. Синтетические
сценарии проходят; разрешённая проверка серверного контракта остаётся открытой.

- [ ] Черновик показывает все параметры, 30 минут по умолчанию, адженду и URL.
- [ ] Только подтверждённая неизменённая версия проходит повторную проверку и запись.
- [ ] После таймаута сначала сверяется исход; успешный результат читается из API.

Проверка: запрет записи до подтверждения, изменённая карточка, конфликт,
таймаут без дубля; тестовая запись только в разрешённом окружении.
Зависимости: T08. Файлы: draft model, operation controller, operation store,
confirmation card, integration test. Размер: M.

## T10 — Изменение и отмена разовой встречи

Первый срез: [предпросмотр названия и отмены](../docs/implementation/t10-change-preview.md).
Повторное чтение, проверка организатора/разового события и UI проверены
синтетически. Добавлено [подтверждение и применение](../docs/implementation/t10-confirm-change.md):
PUT/DELETE, журнал, сверка исхода и обновление календаря проверены синтетически.
Реальный предпросмотр проверен чтением; реальный PUT/DELETE остаётся открытой
интеграционной проверкой, атомарная серверная защита версии не подтверждена.

- [ ] Событие и права сверяются до изменения; итог показан до записи.
- [ ] Незатронутые поля сохраняются, результат проверяется чтением.
- [ ] Операции серий блокируются до T13, неизвестный исход не повторяется вслепую.

Проверка: синтетические edit/cancel с правами и таймаутом; разрешённое тестовое API.
Зависимости: T09. Файлы: change model, controller, API adapter,
confirmation card, tests. Размер: M.

## T12 — Проверяемая аналитика

- [ ] После ревью правил считает вхождения, время и отдельные исключения за период.
- [ ] Темы/команды не выдаются за факты без источника; у группы есть состав встреч.
- [ ] Пересечения и границы периода дают заранее известный результат.

Проверка: синтетические интервалы и серии; значения рассчитаны независимо
от модели; read-only выборка помечается частичной при неполноте.
Зависимости: T06 и ревью правил аналитики.
Файлы: normalization, aggregation, classification, report tool/card, tests. Размер: M.

## T13 — Явная область операции серии

- [ ] Серверные области и идентичность исключений подтверждены до записи.
- [ ] «Это вхождение» и «это и последующие» явно показаны при подтверждении.
- [ ] Просмотр/аналитика не материализуют вхождения; прошлые события не меняются молча.

Проверка: тестовый backend с серией, исключением, переносом и таймаутом
материализации; при отсутствии среды не объявлять выполненным.
Зависимости: T10, ревью правил и проверенный контракт повторяемости.
Файлы: recurrence adapter, scope model, controller, scope UI, tests. Размер: M.
