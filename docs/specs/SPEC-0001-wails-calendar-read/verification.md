# Проверки и исходное состояние

В рабочей копии Electron на `776bdd5` с локальными правками прошли `npm run typecheck` и `npm test` (580/580). Это исходная проверка TypeScript, а не результат приёмки первого среза.

AC-001 проверяется сравнением экранов и сценариев в двух оболочках. AC-002 — контрактными тестами сессии и сценариями запуска. AC-003 — тестами Go, временным файловым хранилищем и сквозным сравнением ответов. AC-004 — замерами на одном Mac с одинаковыми данными и комплектацией. Проверки Wails, сравнение UI и замеры ожидают реализации.

## Проверка оболочки Wails

На macOS 27.2.1 arm64 Electron собрался через `npm run build:desktop`. С `SMALL_E2E_BACKGROUND=1` прошли три сценария Playwright Desktop: `window.spec.ts`, `small-auth.spec.ts`, `calendar-cache-restart.spec.ts`. Эти проверки относятся к исходной рабочей копии с локальными изменениями.

Из корня репозитория с установленными зависимостями:

```sh
./node_modules/.bin/vite build --config desktop-wails/vite.config.ts
mkdir -p release/wails-stage-metrics
(cd desktop-wails && go build -trimpath -ldflags='-s -w' -o ../release/wails-stage-metrics/small-calendar-preview .)
release/wails-stage-metrics/small-calendar-preview -smoke -user-data-dir "$(mktemp -d -t small-wails-test)"
```

Сборка на Go 1.26.10 и Wails 3.0.0 прошла. Фоновая проверка запустила скрытый WKWebView, открыла форму входа и подтвердила пустые логин и пароль и наличие Dockview. Тестовый адаптер выдаёт состояние выхода и не читает профиль Electron. Проверены TypeScript и форматирование файлов адаптера. При линковке Xcode предупредил о несовпадении версий SDK и целевой macOS. Совместимость с macOS 15.1 требует отдельного прогона.

Бинарник оболочки занимает 13 454 290 байт. Цель по DMG будет проверена на полной сборке. AC-001 частично проверен. Сравнение экранов, проверка всех полей начального состояния, интеграция Small, перенос данных и замеры полной сборки впереди.

## Go-сессия и чтение календаря

`(cd desktop-wails && go test ./...)` прошёл на локальном HTTP-стенде. Сценарий проверил чистое состояние, вход, проверку профиля, cookie при обновлении токена после 401, чтение справочника и диапазона событий, отклонение запроса для другого аккаунта и выход. Сборка Wails и скрытый запуск прошли повторно. Форма входа получила ответ «вышел» через действующий вызов Wails → Go. `npm test` (580/580) и `npm run typecheck` прошли после изменения декодирования ответа календаря.

Сессия пока живёт в памяти Go. Транспорт чтения работает через Go, обработка диапазонов и экземпляров событий переиспользует TypeScript. AC-002 и AC-003 остаются в работе до реализации восстановления сессии, файлового кеша и сквозного сравнения отображения событий в двух оболочках. Реальный API Small не использовался в проверках.

### Восстановление сессии Wails

Сессия, логин и признак истечения сохраняются в отдельном профиле Wails в записи AES-256-GCM. Пароль и access token остаются в памяти на время соответствующей операции или сеанса. Ключ хранится в приватном файле рядом с зашифрованными данными по модели текущего локального хранилища. Профиль блокируется на время работы приложения.

На тестовом Small API проверены восстановление сессии в новом экземпляре сервиса, сохранение записи при временном отказе, истечение сессии после отказа refresh, выход и отказ чтения при потере ключа. Скрытая проверка WKWebView прошла с новым каталогом, переданным через `-user-data-dir`. Импорт существующего профиля Electron относится к этапу переноса данных. Файловый кеш календаря и сквозная проверка входа и повторного запуска в нативном UI остаются открытыми.

### Файловый кеш календаря Wails

Go сохраняет каталоги и ответы по источникам событий в зашифрованных записях с привязкой к сессии, аккаунту и запросу. При недоступности источника можно вернуть сохранённую копию. Адаптер передаёт UI исходное время получения и статус stale. Явное обновление событий сообщает об ошибке сети. Вход, выход и истечение сессии сбрасывают кеш.

`go test -race ./...` прошёл. После создания нового экземпляра Go-сервиса с тем же профилем и успешного восстановления сессии тестовый API вернул 503 на чтение событий. Сервис вернул прежний ответ из файла с исходным временем получения. Тест подтвердил шифрование, изоляцию аккаунтов и источников, отказ от кеша при явном обновлении и очистку при истечении сессии. Сборки Vite и Go, проверка типов адаптера и скрытый запуск WKWebView с пустым профилем прошли.

Пока кеш читается после отказа сетевого запроса, а не сразу с фоновой переоценкой, как в Electron. Проверка восстановления сессии и чтения из кеша выполнена на уровне Go-сервиса. Сквозное сравнение карточек и состояний календаря в WKWebView и Electron ещё впереди. При полностью недоступном Small на старте проверка сессии всё ещё блокирует отображение сохранённых событий.

### Сквозной прогон Wails и Electron

После сборки Vite выполнен `(cd desktop-wails && SMALL_WAILS_WEBVIEW_TEST=1 go test -race -count=1 -v ./...)`. Нативный тест запускает два отдельных процесса Wails со скрытыми окнами и одним временным профилем, обращаясь только к локальному тестовому API. Первый процесс отправляет форму входа и показывает карточку «Синтетическая встреча A». Второй восстанавливает сессию при запуске, выполняет запрос событий с ответом 503 и показывает ту же карточку из кеша. Выход через интерфейс убирает карточку, очищает кеш и оставляет в записи профиля только логин. Прошли все три Go-теста. Номера методов Wails закреплены для одинакового вызова из обычной сборки и тестового процесса.

У Electron в фоне повторно прошли `calendar-cache-restart.spec.ts`, `small-auth.spec.ts` и `window.spec.ts`. Контрольный сценарий подтверждает одинаковый результат входа, отображения синтетической встречи после перезапуска и выхода. Обычный бинарник Wails пересобран, скрытый запуск в новом профиле прошёл. Проверка не охватывает полное визуальное соответствие, все фильтры, фоновую синхронизацию и старт при недоступности самого API сессии. Первый этап остаётся открытым.
