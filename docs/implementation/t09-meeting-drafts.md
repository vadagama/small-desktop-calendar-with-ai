# T09 — Черновик встречи в AI-чате

Исторический отчёт первого среза. Подтверждение и запись реализованы
в [следующем срезе](t09-confirm-meeting.md); ограничения ниже описывают первый срез.

Первый срез T09 готовит разовый черновик личного календаря. Он не создаёт
событие, не резервирует слот и не отправляет приглашения. Показ карточки не
считается подтверждением. Инструмента записи и кнопки отправки пока нет.

## Сценарий

После входа в Small и выбора LLM-профиля попросите подготовить черновик,
указав `Участники: [ID1, ID2]`, дату, время, название и адженду. Используйте ID
из поиска сотрудников. Каждый запрос остаётся самодостаточным, без истории.
Если длительность не передана инструменту, применяется 30 минут.

Main проверяет точное совпадение всего явно указанного состава и повторно
получает доступность через T08. Черновик выдаётся только при совпадении начала
и конца с проверенным слотом. Конфликт, неполные данные, смена аккаунта и отмена
не дают нового успешного результата. Организатор берётся из профиля Small,
модель не может выбрать другой аккаунт или передать поле организатора.

Карточка показывает название, адженду, состав, организатора, начало/конец,
длительность, `Asia/Almaty`, место, конференцию, отсутствие повторения и личный
календарь. Время проверки занятости видно отдельно; оно не гарантирует свободу
слота в будущем. Помещения и дубликаты не проверяются этим срезом.

При `conference.mode: automatic` main формирует отдельный URL
`https://meet.small.kz/<UUID>`. Пользовательская HTTPS-ссылка имеет приоритет
при `custom`; `none` отключает конференцию. URL с логином/паролем и другие
протоколы отклоняются. Комната не открывается и не резервируется. URL показан
текстом для копирования, безопасное открытие внешней ссылки ещё не подключено.

Черновик — снимок результата в памяти чата с новым ID. Нет сохранения на диск,
редактирования версии или переноса слота существующего черновика. Повторная
подготовка создаёт новый снимок и новую автоматическую ссылку; для сохранения
старой ссылки её можно явно передать как пользовательскую. Автоматическое
сохранение ссылки при редактировании остаётся частью следующего среза.

## Контракт и ограничения

`meetingDraftInput` принимает только название, адженду, список участников,
время с UTC-offset, длительность, место и режим конференции. Повторяемость,
публичность, организатор и произвольные поля не принимаются. Ограничения текста
и URL — клиентские защитные границы, не установленные лимиты Small.

Повторно прочитан публичный клиент Small: HTML указывает ту же сборку
`index-Dwj9jIUp.js`, SHA256 совпадает с исследованием T08. `createEvent`
использует `POST /calendar/events` с параметром `force`. Надёжный механизм
сверки неизвестного результата календарной записи в исследованном клиентском
пути не установлен. Наличие idempotency в другом модуле приложения ничего
не доказывает для календаря. Серверный контракт записи ещё требует проверки.

## Проверки 29 октября 2026 года

- `npm test`: 84 теста. Новые случаи: 30 минут по умолчанию, организатор из
  доверенного контекста, три режима конференции, небезопасные URL, неверные
  даты/поля, сокращённый состав, недоступный слот, отмена и поздний ответ.
- `npm run typecheck`, `npm run build`, `npm run build:desktop`,
  `npm run format:check` проходят. Новых зависимостей нет.
- `npm run test:desktop`: 8 сценариев. Расширен сквозной тест provider → SDK →
  utility process → main → сервис доступности → карточка. Проверены все поля
  успешного черновика и отказ для конфликтующего интервала. Консоль чистая.
- Снимок карточки просмотрен. Playwright используется вместо недоступного
  Chrome DevTools MCP. Упакованная сборка отдельно не проверялась.
- Инверсия сравнения начала слота приводит к падению трёх тестов; код восстановлен.

Сетевые границы тестов синтетические. Реальные Small API, GLM, работоспособность
конференций и запись события не проверялись. Пользовательские встречи не создавались.

## Следующий срез T09

1. Версионируемый черновик с устойчивой ссылкой и явным подтверждением именно
   показанной версии, привязанный к аккаунту; изменение снимает подтверждение.
2. Журнал намерения до сетевой записи, защита от параллельного подтверждения
   и сохранение неопределённого исхода после сбоя/перезапуска.
3. Проверенный адаптер создания и последующего чтения, повторная проверка
   занятости и дубликата; отсутствие автоматического повторного приглашения.
4. Синтетические сценарии таймаута и отдельно разрешённая проверка записи
   в тестовом контуре. До установления исхода повторная запись блокируется.
