# Сквозные проверки доступности

Команды из корня после `npm run build:desktop`:

```sh
npm run test:desktop -- tests/desktop/availability-analysis.spec.ts
npm run test:desktop -- tests/desktop/calendar-assistant.spec.ts tests/desktop/agent-settings.spec.ts tests/desktop/layout.spec.ts tests/desktop/people-picker.spec.ts tests/desktop/calendar.spec.ts tests/desktop/assistant-memory.spec.ts
```

Первый тест использует реальный Electron main → utility SDK → main tool → preload → React/Dockview. Модель заменена локальным SSE-сервером, Small — изолированным protocol fixture; DNS production заблокирован. Для визуальной сверки тест сам поднимает временный Vite-сервер прототипа, внешний сервер на 5173 не требуется.

Проверено:

- Промпт автоматически открывает единственную вкладку слева от чата; часовая ось содержит 00–24, явный день — один блок даты.
- Добавление сотрудника снимает выбор; продолжение «Теперь только 30 минут» получает обновлённый состав через typed context и обновляет панель.
- Удаление, пустой состав, день/неделя, 5/7 дат, 20 сотрудников, переключение общих окон и сохранение горизонтальной позиции.
- Повторная проверка включает организатора; закрытие выбора во время ответа не открывает форму. Следующий клик по окну без дополнительной кнопки открывает штатный черновик; проверены заполненные дата 2099-11-10, начало 09:00, окончание 10:00 и состав. `syntheticMeetingWrites = 0`.
- Новый диалог убирает панель; после очистки состава следующий model request не получает прежний контекст как текущий дашборд.
- Missing coverage → unknown без активных слотов; denied → ошибка без выбора. Выходные, размеры, шрифты и обе прокрутки проверены в DOM Electron.
- Все нативные окна скрыты, userData новый и изолированный. Ошибок pageerror нет.

Регрессионный набор из 7 файлов (включая availability) прошёл: **7/7**. Он покрывает настройки навыков, память и подтверждение её изменений, прежние календарные инструменты, чтение/ошибки/выход из календаря, изменение раскладки и штатный picker. После финальных исправлений контекста тест availability выполнен повторно.

Unit-проверки сосредоточены в `availability-analysis.test.ts` и `availability-delivery.test.ts`; предполагаемые в плане отдельные файлы для contracts/intervals/context/source не создавались ради дублирования инфраструктуры. Общая команда `npm test` проверяет и существующие ограничения календаря/памяти/черновиков.

Зелёный SSE-тест подтверждает транспорт и поведение UI, смысл промптов подтверждается [отдельным реальным LLM-прогоном](availability-ai-eval.md), реальный API — [отдельным чтением](availability-source.md).

После исправления источника фикстура find-slots намеренно возвращает минутное предложение, а тест требует непрерывных 09–13/14–18 из полного busy-дня. Это воспроизводит прежнюю ошибку и не позволяет вернуть её при зелёных синтетических проверках.
