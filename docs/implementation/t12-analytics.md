# T12 — Проверяемая аналитика встреч

Реализовано 29 октября 2026 года. Правила подсчёта из
[предложений](../proposals/meeting-rules.md) приняты пользователем для первой
версии вместе с отклонениями, которые вызваны составом данных календаря
(см. ниже). Расчёты выполняет код в main; модель только вызывает инструмент
и объясняет готовый результат (ANA-5).

## Как это работает

Навык `analytics` включает инструмент `meetingAnalytics`. Период задаётся как у
`listMeetings`: `today`, `tomorrow`, `this-week`, `next-week` или `custom`
(`from`/`to` включительно, до 31 дня). Инструмент читает только «Мой календарь»
вошедшего аккаунта; аккаунт и участник берутся из профиля, модель их не выбирает,
лишние поля во входе отклоняются. Запись в Small не выполняется.

Чтение идёт по неделям и возвращает полные события (участники, статусы,
`recurring`). Лимит — 1000 встреч; при превышении или ошибке чтения результат
помечается `complete=false`, а в карточке видны причины.

## Правила подсчёта

- Период — полуоткрытый `[начало, конец)` в Asia/Almaty. Встреча входит, если
  пересекает период; на границе учитывается только пересечение.
- В основной итог входят встречи, где вы организатор или ваш статус `accepted`.
- Группы вне итога: «нет подтверждённого ответа» (любой другой или неизвестный
  статус, включая информирующих), «отклонены» (`declined`, только пересчитываются),
  «возможно, весь день» и «некорректные данные».
- Две метрики времени: сумма длительностей и занятое время (объединение
  интервалов); разница показана как пересечения. Пример: 10:00–11:00 и
  10:30–11:30 дают 120 и 90 минут.
- Регулярные — только `recurring === true`; похожие названия ничего не значат.
- Одно вхождение считается один раз по `key` и по идентичности `lookup`.
- Тема — первое правило из списка, чьё ключевое слово входит в название
  (регистр не важен); иначе «Без категории». Результат содержит сработавшее правило.
- В результате есть состав отчёта: время, название, группа, минуты, тема, правило.
  Он нужен, чтобы пользователь мог проверить каждую цифру.

## Отклонения от предложенных правил

| Правило                     | В T12                                           | Причина                                                                                   |
| --------------------------- | ----------------------------------------------- | ----------------------------------------------------------------------------------------- |
| pending отдельно от unknown | одна группа «нет подтверждённого ответа»        | в коде подтверждены только `accepted` и `declined`; значение «ожидает ответа» не известно |
| отменённые отдельно         | «недоступно по данным»                          | в данных календаря нет признака отмены                                                    |
| весь день                   | эвристика: ≥ 24 часов или обе границы в полночь | отдельного поля нет; такие встречи в часы не входят и помечены                            |
| команды                     | разбивка по организаторам и частым участникам   | нет источника состава команд; «по командам» не выдаётся                                   |
| темы                        | локальные правила по ключевым словам            | в данных нет тегов и категорий; предположения модели фактом не считаются                  |

Поле `unavailable` в результате перечисляет то, чего нет: отмены, команды, теги.

## Правила тем

Кнопка «Правила тем аналитики» в боковой панели открывает редактор. Правила
хранятся локально в `topic-rules.json` (права 0600, атомарная запись, без
содержимого встреч): до 20 тем, у каждой 1–20 слов до 60 символов, названия тем
не повторяются. Невалидное сохранение не заменяет прежний список. Повреждённый
файл блокирует чтение, инструмент возвращает понятную ошибку, а явное сохранение
в редакторе его исправляет. Правила общие для аккаунтов этого компьютера.

## Настройки ассистента

Навык `analytics` добавлен к четырём прежним. Версия настроек поднята до 4:
файлы версии 3 при чтении получают навык `analytics` включённым, свои тексты
навыков, режимы и отключённые навыки не меняются. Версии 1 и 2 получают
`schedule` и `analytics`.

## Проверки

- Unit: 209 тестов, из них 20 по аналитике и правилам тем. Набор с заранее
  известным результатом: пересечения, границы периода, многодневный период,
  статусы, весь день, некорректные интервалы, дубли, регулярные, темы,
  частичное чтение, лимит 1000, отмена, изоляция аккаунта и `participantId`,
  хранилище правил (права, валидация, параллельные записи, повреждённый файл),
  миграция настроек v3→v4.
- Проверка чувствительности (изменялся код, тест должен упасть): клиппинг по
  границе, объединение интервалов, неизвестный статус как принятый, `declined`
  как подтверждённый, подмена `participantId` на `accountId`, отсутствие признака
  усечения, фильтр периода, гейтинг навыка в runtime, маппинг навык→инструмент,
  миграция без `analytics`, права файла, повторы тем, игнорирование правил,
  непроброшенные правила. Все изменения ловятся.
- Electron `analytics.spec.ts` на синтетическом API: отчёт за день (две встречи,
  1 ч 30 мин), исключение отклонённых, перенос с пересечением (сумма 1 ч 30 мин,
  занятое 1 ч, пересечения 30 мин), редактор правил (ошибка дубля, сохранение,
  повторное открытие), темы и правила в карточке, ноль записей в Small.
- `npm run typecheck`, `npm test`, `npm run build:desktop`, `npm run test:desktop`
  (17 сценариев, два последних полных прогона без отказов), форматирование и
  `git diff --check`.

## Ограничения

- Реальная read-only сверка с Small не выполнялась: значения статусов, полнота
  `participants` и поведение `recurring` проверены только на синтетических ответах.
- Дубли виртуального и материализованного вхождения одной серии не определяются:
  у события с `id` нет ссылки на серию. Нужен контракт T13.
- Отмены, команды и теги недоступны; «по командам» появится после подтверждённого
  контракта каталога.
- Пометка «Данные частичные» в карточке проверена unit-тестами расчёта, но не
  Electron-сценарием: синтетический API не даёт неполного чтения «Моего календаря».
- Полный набор Electron нестабилен независимо от T12: на чистом `origin/main`
  в трёх прогонах два раза падал случайный сценарий (по одному из разных). Каждый
  упавший сценарий по отдельности проходит. Причина не установлена.
