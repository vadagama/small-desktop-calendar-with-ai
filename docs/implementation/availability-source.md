# Источник доступности

Уточнено 9 ноября 2026 после ошибки на реальном календаре. Первоначальная проверка подтвердила только формат ответа, но ошибочно приняла минутные результаты find-slots за покрытие времени. Этот подход заменён.

## Подтверждённый контракт

Основной источник сетки — существующий POST `/gate/team/api/calendar/events/busy-intervals`, тело `participant_ids`, `timezone: Asia/Almaty`, `date`. Ответ `data[]`: `type: participant`, `id` или `participant_id`, `busy_slots[{start,end}]`. Проверяется отдельная запись каждого запрошенного сотрудника; пропуск, неверный формат, повтор или посторонний ID не доказывают свободное время.

Контракт проверен по исходнику backend, ревизия `0f2a56e`:

- [TimeSlotFinderService](https://gitlab16.skiftrade.kz/staff/team-small-kz-backend/-/blob/0f2a56e/src/app/Services/TimeSlotFinderService.php): `getEventsForParticipantsAndCalendars` строит отдельный фильтр для каждого participant, собирает обычные события и соответствующие ему экземпляры повторений за день, возвращает запись даже при пустой занятости. Пагинации этого результата нет.
- [Controller](https://gitlab16.skiftrade.kz/staff/team-small-kz-backend/-/blob/0f2a56e/src/app/Http/Controllers/Api/Calendar/TimeSlotFinderController.php): границы суток, проверка participant UUID и входные параметры.
- [TimeSlotValidator](https://gitlab16.skiftrade.kz/staff/team-small-kz-backend/-/blob/0f2a56e/src/app/Services/Validators/TimeSlotValidator.php): рабочие часы 09–18, обед 13–14. Эти подтверждённые правила отражает `smallWorkingIntervals`, пользовательское окно поиска дополнительно их ограничивает. Синтетический обед прототипа 12–13 не является рабочим правилом.

Для валидной полной записи доступность — рабочие интервалы минус объединённая занятость. `busy_slots: []` означает отсутствие блокирующих событий в подтверждённом дне; отсутствие самой записи означает unknown. Буфер расширяет busy организатора. При необходимости проверяется соседний день. Прошлое и время вне рабочего/поискового окна не предлагаются.

## Почему find-slots не используется для сетки

`findAvailableSlots/generateSlots` возвращает предложения фиксированной длительности с шагом начала, а не максимальные непрерывные свободные интервалы. Также есть лимит предложений/has_more. Минутные предложения нельзя превращать ни в полное покрытие, ни в признак, что всё между ними неизвестно или занято. Сетка и точная перепроверка выбранного окна теперь не зависят от этого списка. Прежний подбор предложений без exactInterval сохраняется для совместимости.

Для exactInterval повторно читается полная занятость фактического состава, проверяются рабочая политика, дата/границы, длительность, будущее, organizer и buffer. Приглашения не отправляются этим чтением.

## Права и ограничения

Используется штатный `SmallAuth.readCalendar` с проверкой аккаунта и смены сессии. Credentials остаются в main/изолированной session. Renderer получает только интервалы и ID без названий/описаний встреч. Произвольный URL, force и календарная запись не разрешены.

20 сотрудников, максимум 7 последовательных дней: один запрос занятости дня вместо персональных запросов find-slots. Ответы проверяются Zod; неизвестные схемы/отказы не превращаются в free. Защитный лимит занятости 5000 интервалов на день; соседние дни буфера также имеют ограниченные массивы. Полнота подразумевается только для верифицированного метода busy-intervals, а не для произвольного пустого массива событий.

Чтение исправленного адаптера и контрольного запроса заняло 1373 мс. Контроль отбирает только запрошенный день и допустимое окно: сервер может прислать предложения за более широкий диапазон. Все окна по-прежнему требуют повторной проверки перед черновиком.

Проверяющий Electron-процесс не создавал окон, имел новый временный userData и использовал действующую сессию для штатного чтения. Встречи/пользовательские настройки не изменялись. Сохранены только агрегаты; имена, реальные ID, payload, cookie и токены не записаны. Это проверка собственного календаря; права на чужие данные регулирует сервер, отказы проверены синтетически.
