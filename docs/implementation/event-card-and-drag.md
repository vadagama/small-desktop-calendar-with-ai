# Карточка события и изменение времени

Карточка рабочего календаря использует структуру пользовательских макетов:
заголовок и меню, дата и интервал, участники с инициалами и статусами,
раскрытие списка после пяти участников, ссылка подключения с копированием,
ответ на приглашение. Названия и статусы участников берутся из ответа Small;
неизвестный статус не обозначается как согласие.

Информируемые показываются отдельным списком из `notification_recipients`,
без статусов приглашения, с раскрытием после пяти человек. Переговорные
определяются пересечением `calendar_ids` события с каталогом доступных
переговорных (`/calendars/public`). Личные и неизвестные календари не показываются
как переговорные; при пустом пересечении блок отсутствует. Ссылка подключения и место
встречи сохраняются отдельно от переговорных.

Для серий, включая виртуальные вхождения, блок «Повторяется» показывает
`recurrence_rule`: ежедневную или еженедельную частоту, `INTERVAL` (по умолчанию
1) и `BYDAY`; один день недели отображается, например, как «Каждую субботу».
Значок повторения виден также в сетке дня, недели и месяца. Если вхождение
с `original_event_id` не содержит правила, main пробует прочитать его из исходной
серии отдельным GET. Переговорные, участники и файлы остаются данными самого
вхождения. Без доступного правила или при неподдерживаемой частоте используется
«Повторяющееся событие». Это отображение не расширяет разрешения на запись
серий. Поля сопоставлены с публичным клиентом Small `index-Cwe5QV54.js`
30 октября 2026 года; авторизованные production-ответы не проверялись.

Прикреплённые файлы из `attachments` показываются компактным списком: имя из
`path`, иконка типа, расширение и размер в Б/КБ/МБ. Нажатие открывает файл через
существующий HTTPS bridge в системном браузере. Относительные пути разрешаются
только под `https://minio.skiftrade.kz:9000/team/`, как в клиенте Small;
внешние URL и обход каталогов отклоняются. Файл без безопасной ссылки остаётся
виден с подписью «Ссылка недоступна». Содержимое удалённых файлов автоматически
не загружается.

Тултип общего компонента Calendar включён для рабочего календаря, включая
события без права редактирования. Отображаются только название,
время начала и окончания, длительность и организатор.

В представлениях дня и недели организатор может перемещать разовое событие
и растягивать его верхнюю/нижнюю границу. Шаг — 15 минут, минимальная
длительность — 15 минут. Многодневные события, серии и виртуальные вхождения
не переносятся этим жестом. Это предотвращает неявный выбор области изменения
серии и изменение обрезанного дневного фрагмента вместо исходного интервала.

## Контракт сохранения

- `calendar.reschedule` получает идентификатор события, прежний и новый интервалы.
- Main повторно читает карточку, проверяет организатора по participantId
  сессии, тип события и совпадение прежнего времени.
- `PUT /gate/team/api/calendar/events/{id}?force=false` сохраняет остальные
  поля карточки: название, описание, место, часовой пояс, публичность,
  календари, участников, информируемых и вложения. Отсутствие обязательных
  данных блокирует запись, чтобы пустые значения не стирали состав встречи.
- Успех подтверждается повторным чтением времени. При ошибке календарь
  перечитывается; запись не повторяется автоматически и конфликт не обходится.
- Проверка времени до PUT не является атомарным серверным условием обновления;
  клиентский контракт не предоставляет подтверждённого ETag/If-Match.
- `calendar.respond` передаёт собственный ответ участника через PATCH
  `/calendar/events/{id}/participant-status` с `accepted` или `declined`.
- `calendar.copyLink` и `calendar.openLink` принимают HTTPS-ссылки без
  встроенных учётных данных, проверяют отправителя IPC и используют Electron
  clipboard/shell. Разрешения браузерного clipboard API не расширяются.

Контракт повторно сопоставлен с обслуживаемым Team Small bundle
`index-Dwj9jIUp.js` 29 октября 2026 года: `Tf.editEvent`, `Tf.joinEvent`,
`Tf.declineEvent`, mapping формы `yGa` и формат ссылки `qG`.
Проверка реальных записей в пользовательском календаре не выполнялась.

## Границы

«Редактировать» разового события открывает общую с созданием форму, заполненную
данными события. Можно изменить название, описание, ссылку, участников,
информируемых, переговорную, дату, время и файлы. «Сохранить» отправляет PUT
существующего события; POST создания не вызывается. Неизменённые поля берутся
из свежей карточки сервера, конфликт в изменённом поле блокирует запись.
Скрытые параметры (включая публичность и часовой пояс) сохраняются. Новые файлы
принимаются только из загрузок текущей сессии; существующие файлы можно удалить.
Неизменённые timestamps сохраняются точно, включая секунды. Изменение
повторяемости в этой форме недоступно: для серий действует отдельный контракт.
Отмена запрашивает подтверждение при несохранённых правках. «Удалить» сразу отправляет DELETE для
разовой встречи. Промежуточного предпросмотра и подтверждения нет. Перед записью
проверяется организатор и тип события; параллельные операции блокируются.
Журнал T10 блокирует повторную запись после неизвестного исхода, включая
перезапуск. Повторное действие сначала сверяет прежний результат чтением.
[Условия сверки и ограничения](t10-event-mutations.md). Серии и их вхождения не изменяются этими действиями.
«Новая встреча с этими участниками» открывает форму с выбранным составом,
создание выполняется её обычным действием пользователя.

## Проверка

- `npm run typecheck`
- `npm test`
- `npm run build:desktop`
- `npx playwright test -c playwright.desktop.config.ts tests/desktop/calendar.spec.ts`

Модульные тесты проверяют сохранение полей, чужого организатора, серии,
устаревшее время, неполную карточку, конфликт, неподтверждённую запись,
отсутствие повторной отправки и JSON-тела PUT/PATCH.
Тултип появляется только при наведении без нажатых кнопок мыши; нажатие
скрывает его и отменяет отложенный показ, включая перемещение и изменение границ.

Electron-сценарий проверяет тултип при наведении, карточку и меню, оба края
события, перемещение целиком, отсутствие лишнего открытия после жеста,
раскрытие участников, копирование ссылки, ответ на приглашение и выход.
Для изоляции от параллельных сборок этот сценарий принимает
`SMALL_TEST_APP_ROOT` — каталог копии приложения с package.json, out,
node_modules и prototype/public/app-icon.png.

## Уведомления об операциях

Результаты создания, изменения названия, переноса, удаления и ответа на приглашение
показываются компактными уведомлениями справа. Успех — зелёный, ошибка — красная;
технические ответы сервера не выводятся. Успех скрывается через пять секунд
(таймер приостанавливается при наведении и фокусе), ошибки закрываются крестиком.
Ошибки заполнения форм и локальные ошибки остаются у соответствующих полей.
Уведомления доступны поверх активного модального окна и поддерживают reduced motion.

Отсутствующий признак повторения в кратком списке событий считается неизвестным,
а не серией. Жест организатора разрешён; полная карточка перед записью по-прежнему
проверяется на повторение и актуальность времени.

Повестка находится под заголовком, перед датой. По умолчанию видны две строки;
для переполненного текста доступно «Показать полностью» / «Свернуть».
Переносы строк сохраняются, короткий текст не получает лишнюю кнопку.

Доступность переноса и изменения границ проверяется по тому, что исходное событие
целиком входит в отображаемый день, а не по равенству точной длительности и
округлённой длительности сетки. Секунды в серверном времени не блокируют жесты.
Desktop-проверка покрывает перенос и обе границы 30-минутной карточки, в том числе
с ненулевыми секундами начала.

Фильтры боковой панели разделены по вкладкам: «Календарь» показывает «Мой
календарь», «Переговорные» — список доступных переговорных. Выбор переговорных
сохраняется при переключении вкладок; ошибки загрузки этого списка отображаются
только во вкладке переговорных.

Перенос/растягивание сохранённого повторяющегося события с собственным id
передаёт исходное правило повторения и `recurring_edit_type: single` (контракт
редактирования Team). Изменяется только текущее вхождение. Виртуальные вхождения
без id пока не материализуются. Переименование и удаление серий остаются
недоступными.

События, начавшиеся в предыдущие календарные дни Asia/Almaty, нельзя менять или
удалять. Проверка выполняется в UI и main перед записью. Перенос в предыдущий
день также запрещён; сегодняшнее прошедшее время не считается прошлым днём.


Обновление полного редактора проверено на синтетическом API в Electron:
заполнение, изменение описания/ссылки/переговорной/времени/информируемых,
сохранение текущего события, отмена, удаление на сервере и уведомление о
параллельных изменениях. Проверены computed-размеры полей 14 px и заголовка
18 px. Реальные встречи при проверке не изменялись.
