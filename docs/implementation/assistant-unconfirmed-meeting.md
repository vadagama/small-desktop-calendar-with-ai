# Подтверждение выбранного времени через ассистента

Если пользователь настаивает («всё равно поставь», «именно в это время»),
ассистент вызывает `prepareMeetingDraft` с `allowUnconfirmed:true`. Повторная
подготовка ранее отклонённого интервала в следующем ходе диалога также показывает
карточку подтверждения. Повтор инструмента внутри одного хода не считается
повторной просьбой пользователя. Время, длительность и полный состав сохраняются.

Карточка показывает предупреждение:
«Выбранный интервал не подтверждён для всех участников. Вы действительно хотите
поставить встречу?» и кнопку «Да, поставить встречу». До нажатия записи нет.
Инструмент модели не принимает согласие на создание: main требует отдельный
`allowUnconfirmed:true` в IPC подтверждения для текущих аккаунта, ID и версии.
Обычная карточка продолжает использовать кнопку «Создать встречу».

Перед отправкой занятость читается заново. Ошибки доступа, неполные ответы и
сбой загрузки не обходятся. Для подтверждённого пользователем неподтверждённого
интервала допускается отсутствие общего слота. Сохраняются проверки переговорных,
памяти, дубликатов, сессии, журнал операции и запрет повтора неизвестного POST.
Ручная форма не принимает флаг `allowUnconfirmed`.

После согласия используется строго определённый
`POST /gate/team/api/calendar/events?force=true`. Контракт проверен по backend
`ebb8eb9622b568ac9d4610cbb815df3a97000fac`:
`src/app/Http/Requests/Calendar/CreateEventRequest.php`, метод `withValidator`,
сначала проверяет пересечения календарей, затем при `force=true` пропускает только
проверку участников. Это также покрыто backend-тестом
`can_force_create_event_with_conflicts`. Проверки авторизации и тела остаются.
Ссылка на [исходник backend](https://gitlab16.skiftrade.kz/staff/team-small-kz-backend/-/blob/ebb8eb9622b568ac9d4610cbb815df3a97000fac/src/app/Http/Requests/Calendar/CreateEventRequest.php).

Проверки используют синтетические данные: unit-тесты подготовки, повторной просьбы,
согласия, старой версии и чужого аккаунта, ошибок занятости, дубликатов и режима
отправки; скрытый Electron E2E — предупреждение, отсутствие записи без согласия,
подтверждение клавиатурой, один POST с `force=true` и отсутствие дубля.
Реальные встречи для проверки не создаются.
