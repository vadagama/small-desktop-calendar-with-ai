# Проверка нативной доставки macOS

29 октября 2026 года, macOS 15.1 arm64, Electron 45.1.0.

## Воспроизводимая локальная сборка

`npm run package:mac:local` собирает `.app` с постоянным bundle ID
`kz.small.desktop-calendar` и локальной ad-hoc подписью. Скрипт использует
существующий Electron Packager и его osxSign, затем выполняет
`codesign --verify --deep --strict`. Hardened Runtime для этой локальной подписи
выключен; настройки безопасности renderer и сетевые ограничения не меняются.

Результат: `release/Small Calendar-darwin-arm64/Small Calendar.app`.
Запуск: `open 'release/Small Calendar-darwin-arm64/Small Calendar.app'`.
Перед запуском завершить старый dev-экземпляр через Cmd+Q: один профиль допускает
только один процесс. `npm start` по-прежнему запускает dev/preview Electron,
а не эту локальную сборку.

`npm run package:mac` оставлен для упаковки без подписи, с тем же bundle ID.
Ни один из этих режимов не предназначен для публичного распространения.
Developer ID, Hardened Runtime и нотарификация остаются отдельной задачей:
на этом Mac `security find-identity -v -p codesigning` не нашёл сертификатов.
Ad-hoc подпись не заменяет Developer ID, но реальная локальная доставка
на этой машине подтверждена.

## Проверка в приложении

В окне колокольчика добавлен блок «Уведомления macOS»:
- «Отправить тестовое уведомление» создаёт нативное уведомление из main.
- Состояние «ожидаем» не выдаётся за успешную доставку.
- Доставка подтверждается только при нахождении ID теста в
  `Notification.getHistory()`, не только по событию `show`.
- `failed` показывает ошибку. Поддержка API не выдаётся за разрешение macOS.
- Тестовая кнопка «Открыть календарь» открывает фиксированный адрес
  `https://team.small.kz/calendar`, не подключает к реальной конференции.
- «Настройки macOS» открывает System Settings. Пользователь выбирает
  Уведомления → Small Calendar. Кнопки не принимают произвольные URL или команды.

Диагностика не зависит от входа в Small и доступности календаря. Повторный тест
заменяет предыдущее тестовое уведомление; реальные напоминания не удаляются.
Нативный адаптер переиспользуется настоящими напоминаниями с действием
«Подключиться», которое сохраняет проверку аккаунта и повторное чтение события.

## Фактические результаты

- Локальная `.app` успешно подписана; строгая проверка codesign прошла.
- Реальный нативный тест получил `show`, а `Notification.getHistory()` вернул
  его ID. Затем реальная кнопка в UI показала подтверждённую доставку.
- В System Settings для Small Calendar проверены: Allow Notifications — on,
  стиль Banner, Show in Notification Center — on. Настройки не изменялись.
- 125 unit-тестов и все 13 Electron-сценариев проходят. Проверки доставки
  и планировщика используют синтетическую нативную границу: delivered, failed, callback
  действия и разрешённый фиксированный URL. Типы и сборка проходят.
- Само появление в истории ОС не подтверждает видимость баннера: Focus и
  настройки отображения действуют независимо. Проверка пользователем
  визуального показа и реального нажатия системной кнопки учитывается отдельно.

Источники: [Electron Notification](https://www.electronjs.org/docs/latest/api/notification),
[Electron code signing](https://www.electronjs.org/docs/latest/tutorial/code-signing).
