# T10 — Изменение и удаление разовой встречи

Клиентская реализация завершена и проверяется на изолированном API. Сохранение
названия, перенос и изменение длительности выполняются действием пользователя;
удаление — кнопкой «Удалить». Дополнительный экран подтверждения не вводится.
Серверные права, формат PUT и реальные приглашения требуют отдельной проверки
на разрешённой тестовой встрече Small.

## Перед записью

Main проверяет текущий аккаунт, полную карточку, id и организатора. Нельзя
переименовать или удалить серию/вхождение или событие за прошедший календарный
день Asia/Almaty. Перенос сверяет исходный интервал, запрещает прошлый день и
сохраняет установленное поведение одиночного переноса серии с собственным id.
Неполные данные не заменяются пустыми списками. PUT использует `force=false`.

Название, описание, место, время, часовой пояс, публичность, календари, участники,
информируемые и вложения передаются вместе. После PUT проверяется весь этот набор,
а не только изменённое название или время. Порядок id в списках и эквивалентные
часовые смещения дат не влияют на сравнение. Серверный ETag/If-Match не подтверждён:
чтение перед записью не обеспечивает атомарную защиту от чужой конкурентной правки.

## Журнал и неопределённый результат

`userData/event-mutations/` содержит по записи на пару аккаунт/событие. Имена
файлов и отпечатки запросов/ожидаемых результатов — SHA-256; содержимое встреч
и ключи в журнал не попадают. Доступ к каталогу 0700, файлам 0600.
Эксклюзивное создание и fsync файла/каталога происходят до сетевой записи.
Повреждение журнала блокирует запись, а не сбрасывает историю.

Параллельные действия над одним событием блокируются в main. После таймаута,
ошибки проверки или перезапуска следующая попытка сначала сверяет прежний
результат чтением. Другой вид действия или новое название не обходят блокировку.
Совпавший результат снимает блокировку; если пользователь запросил другое
действие, интерфейс просит обновить календарь и повторить его отдельно.

Успешное удаление требует ответа DELETE 2xx и последующего GET 404 в проверенной
сессии. Small удаляет мягко: на реальном сервере после DELETE карточка остаётся
читаемой (GET 200) со статусом `cancelled`, поэтому подтверждением считается и
такой ответ с тем же id события; любой другой статус или чужой id — исход
неизвестен. Если ответ DELETE потерян, один GET 404 (как и `cancelled`) не доказывает успех: операция
остаётся неизвестной и повторный DELETE не отправляется. При восстановлении
связи подтверждённый ранее DELETE можно сверить без повторной записи.
Если исход невозможно установить, автоматического сброса журнала нет; требуется
внешняя проверка серверной операции. Успешно сверенная запись журнала удаляется.
Явные HTTP-отказы 400/401/403/404/409/422 освобождают запись для исправленного
действия; сеть, 5xx и неподтверждённый результат этого не делают.

## Проверки

- Модульные тесты: права, серии, прошлые дни, неполные данные, сохранение полей,
  конфликт, потерянный ответ, восстановление после перезапуска, изменённый запрос,
  изоляция аккаунтов, эксклюзивная запись и повреждение журнала.
- Проверка чувствительности теста: удаление условия подтверждённого DELETE
  приводит к падению сценария «timeout, затем 404».
- Electron: переименование, жесты переноса/длительности, удаление с исчезновением
  события, ошибки прав, смена аккаунта и уведомления об исходе.
- `npm run typecheck`, `npm test`, `npm run build:desktop`, форматирование
  изменённых файлов и `git diff --check`.

Реальные встречи сотрудников в ходе этих проверок не создавались, не изменялись
и не удалялись. Проверки не доказывают серверную семантику реального Small.

Изолированная проверка PR от 29 октября 2026: 179 модульных тестов и пять
Electron-сценариев календарных изменений проходят. Общая проверка типов,
сборка и форматирование изменённых исходников проходят. Проверка выполнена
на копии коммита T10 без незакоммиченных изменений настроек и ассистента.
