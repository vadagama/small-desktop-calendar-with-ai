# Участники существующей встречи и ответ на приглашение

## Ожидаемое поведение

- Ассистент находит существующую разовую встречу организатора и сотрудников по подтверждённым данным
  Small, предлагает добавление участников и сохраняет его после подтверждения.
- Добавление сохраняет прежних участников и остальные поля встречи. Повторное
  добавление того же человека не создаёт дубликатов.
- Права организатора, изменения встречи на сервере и конфликты проверяются
  существующим путём редактирования. Конфликт не обходится автоматически.
- Карточка приглашения показывает «Придёте?» и кнопки «Да» / «Нет» в компактной
  типографике приложения. Отсутствие `is_informed` в деталях не скрывает контрол,
  если текущий пользователь есть в составе участников.
- Сохранённый отказ, как и согласие, остаётся выбранным после повторного открытия.
  Организатор и информируемый сохраняют свои отдельные роли.

## Проверка

`npm test`, `npm run typecheck`, `npm run test:desktop`,
`npm test --prefix prototype`, `npm run test:ui --prefix prototype`.
Все записи в автоматических тестах выполняются на синтетическом API.
Electron запускается скрыто с отдельными временными профилями.

## Границы

Изменение состава повторяющейся серии через ассистента пока не поддержано.
Ответ на приглашение доступен для встречи с собственным ID; виртуальное
вхождение серии без ID требует отдельного контракта материализации.

## Слои при обновлении календаря

Ответ на приглашение обновляет событие без временного удаления из сетки.
Пока открыт модальный диалог, изменения календаря применяются без View Transition:
снимки этой анимации рисуются поверх top layer и могут перекрывать диалог.
После закрытия диалога анимация изменений календаря снова используется.
Это проверяется для обоих ответов и для фоновых изменений сервера.
