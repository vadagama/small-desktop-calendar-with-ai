# T07 — Настраиваемая компоновка

## Результат

Desktop использует Dockview Community (`dockview-react` 8.7.1, MIT) согласно
ADR-002. Ассистент можно расположить справа, слева, сверху или снизу от
календаря через «Настройки пространства» внизу иконной панели или
перетаскиванием заголовка к краю другой панели. Кнопка в заголовке календаря
«Поменять панели местами» сохраняет ось компоновки. Размеры меняются
перетаскиванием границы; кнопки −/+ в настройках позволяют менять размер
ассистента с клавиатуры.

Обе панели остаются видимыми: объединение вкладок, закрытие и плавающие окна
не предлагаются. Для мыши используется pointer DnD. `renderer: "always"`
сохраняет компоненты при перемещении; календарь продолжает получать обновления
через React context. История, черновик, потоковый ответ и выбранный период
не сбрасываются при изменении компоновки. Смена аккаунта по-прежнему сбрасывает
чат через ключ аккаунта.

Сохранение компоновки между запусками **не реализовано**: по T07 сначала нужно
согласовать эту деталь ADR-002 и формат сохранения. При запуске ассистент справа.
Настройки layout на диск не записываются, новых привилегированных IPC нет.

## Ограничения

Chrome DevTools MCP недоступен в этой сессии; runtime, DOM, консоль и снимки
проверены через Playwright в Electron на текущем Mac. Упакованная `.app`
для этого среза отдельно не пересобиралась и не проверялась. Настоящие Small
API и LLM не использовались; открытые интеграционные проверки T04–T06
остаются открытыми. Производительность по числовому SLA не измерялась.

Основание интерфейса Dockview: [options](https://dockview.dev/docs/api/dockview/options/),
[API](https://dockview.dev/docs/api/dockview/overview/),
[drag and drop](https://dockview.dev/docs/core/dnd/dragAndDrop/).
Фактические сигнатуры сверены с установленными TypeScript declarations 8.7.1.

## Соответствие стилям прототипа

По запросу пользователя интерфейс Dockview приведён к текущему
`prototype/src/styles.css` и снимку `.impeccable/review/desktop.png`:

- Убрана отдельная строка технических контролов; четыре варианта компоновки
  перенесены в диалог с существующими классами `modal`, `layout-options`,
  `selected`, `form-note` и `secondary` из прототипа.
- Единая полоса заголовка каждой панели — 36px, фон `--soft`, текст 12px,
  отступ 11px и иконка захвата. Настройки модели и название активного профиля
  отображаются в этой полосе через React portal; второй заголовок не создаётся.
- Начальная доля календаря — 68%, зазор между панелями — 6px с видимой ручкой.
  Фильтры используют отступы боковой панели прототипа. Функциональность чтения
  календаря и настройки модели сохранена.
- Настройки используют нативный modal dialog с Escape и возвратом фокуса.
  E2E проверяет новый путь через иконную панель и ожидает фактическую геометрию
  после обновления отложенных overlay-элементов Dockview.

Повторно прошли 53 теста ядра, 6 Electron E2E, проверка типов, desktop-сборка
и форматирование. Скриншоты `style-initial.png`, `style-settings.png` и
`layout-900.png` в `test-results/desktop/` просмотрены; ошибки и предупреждения
консоли renderer в сценарии компоновки отсутствуют. Демонстрационные встречи
и функции прототипа, ещё не подключённые к API, в desktop не добавлялись.

Боковая панель также использует мини-календарь и цветные отметки из прототипа.
Выбор даты синхронизирован с основной сеткой, стрелки листают только
мини-календарь, «Сегодня» возвращает обе панели к текущей дате Almaty.
Вкладка «Переговорные» использует существующий каталог публичных календарей;
отдельной классификации помещений в API-контракте нет. Регрессионный тест
проверяет повторное включение ранее выбранного публичного календаря после
просмотра личного: сохранённый выбор больше не снимается первым кликом.
