# T06 — Чтение календаря Small

Дата: 29 октября 2026 года. Реализован desktop-сценарий чтения календаря.
Проверка с синтетическим сервером выполнена; реальное авторизованное чтение
Small и сверка встреч остаются открытыми. Этап разделён на ветки
`codex/t06-calendar-read` (API и сессия) и `codex/t06-calendar-ui` (интерфейс).

## Поведение

Desktop больше не подставляет демонстрационные встречи. До входа показано
приглашение открыть профиль; после входа доступны личный календарь, выбор
публичных календарей и виды день/неделя/месяц. «Сегодня» вычисляется в
`Asia/Almaty`. Смена периода загружает соответствующий диапазон, месяц
включает соседние дни видимой сетки. Кнопка «Обновить» повторяет чтение.

Карточка перечитывается из API и показывает начало, окончание, часовой пояс,
организатора, место и описание. Значения без HTML-интерпретации; отсутствующие
поля явно отмечены. События нельзя переносить, менять или отменять в этом
срезе. Исходный демонстрационный стенд в `prototype/` остаётся отдельным.
Ассистент по-прежнему выполняет безопасный SDK-сценарий, календарные данные
ему не передаются.

Пустой ответ отличается от сбоя. При частичной загрузке отображаются доступные
события и предупреждения по источникам. Если все источники недоступны,
пустая сетка не объявляет период свободным. Ошибки списка публичных календарей
видны отдельно и не скрывают доступные личные события.

При смене периода старый результат скрывается сразу. При выходе или смене
аккаунта очищаются события, список календарей, выбранная карточка и диалог
ассистента. Календарные ответы не сохраняются в файлы или localStorage;
серверные запросы использует отдельная непостоянная Chromium session T05.

## Контракт и ограничения

Повторно исследована публичная сборка
[index-Dwj9jIUp.js](https://team.small.kz/assets/index-Dwj9jIUp.js): `Tf`, `sht`,
`gse`, `ktr`, `Fza`, `Pe` и `ltr`.

- `GET /gate/team/api/calendars/public`: массив `data` с `id` и `name`.
- `GET /gate/team/api/calendars/my/events` и `/calendars/{id}/events`:
  параметры `start_date`, `end_date`, ответ `data` — массив или объект событий.
- Используются `id`, `original_event_id`, `title`, `starts_at`, `ends_at`,
  `calendar_ids`, `creator_name`, `description`, `location`.
- Обычная карточка читается через `/calendar/events/{id}`; виртуальное
  вхождение без собственного ID — через `/calendar/events/generated` с
  `original_event_id` и локальной датой. `/from-template` не вызывается.

Границы периода передаются ISO timestamps с явным UTC offset; конец диапазона
исключительный, как у видимой сетки FullCalendar в клиенте Small.
Временные значения без timezone, неверные интервалы и неизвестные форматы
помечаются как неполные данные. Собственный ID материализованного события
сохраняет его идентичность; у виртуального — ID серии плюс момент начала.
События, пересекающие полночь, разделяются на дневные отрезки для сетки,
а карточка сохраняет исходный интервал. Повторные копии из календарей удаляются
по идентичности события. Карточка с другим ID/датой в ответе отклоняется.

Лимиты desktop: одновременно до восьми выбранных календарей, до 5000 записей
из каждого ответа, до 8 MiB на ответ. При превышении или наличии метаданных
пагинации появляется предупреждение о неполноте. Серверная пагинация пока
не подтверждена; клиент не придумывает запросы продолжения.

Сессия сериализует чтение и смену аккаунта. Каждый запрос связан с текущим
пользователем; запрос другого аккаунта отклоняется. Смена аккаунта помечает
незавершённый результат недействительным. При 401 допускается один refresh;
отозванная сессия возвращает вход. Токен не выходит за пределы main.
IPC предоставляет только список календарей, события и карточку, проверяя
отправителя и входную схему. Transport разрешает только фиксированные GET
пути и параметры чтения; произвольные URL и операции записи недоступны.

Остаётся подтвердить на реальном сервере: точную форму ответов, права,
полноту выдачи и пагинацию, границы периода и идентичность перенесённых
вхождений. Исследование клиентской сборки не заменяет серверный контракт
и не подтверждает корректность реальных серий.

## Проверки

- `npm test`: 53 теста, включая 14 календарных и 11 тестов auth.
- Проверены временные границы, полночь, повторные копии, виртуальные
  и материализованные события, формат/права/частичный ответ, лимит размера,
  несовпадающая карточка, инъекция пути и изоляция аккаунтов.
- Инверсия признака неполных данных обнаружена тестами; исходный код восстановлен.
- `npm run typecheck`, `npm run build`, `npm run format:check` прошли.
- В `prototype/`: `npm run test` (5 тестов), `npm run check`,
  `npm run test:ui` (13 тестов) прошли, включая перенос демо-событий,
  tooltip, компоновки и адаптивность исходного стенда.
- `npm run package:mac` собрал arm64 `.app`. Сохраняются предупреждения
  зависимостей о `use client` и packager о дополнительном формате `.icon`.
- `SMALL_APP_EXECUTABLE="$PWD/release/Small Calendar-darwin-arm64/Small Calendar.app/Contents/MacOS/Small Calendar" npm run test:desktop`:
  пять E2E в упакованном приложении с PATH без Node. Проверены день, неделя,
  месяц, обычная и виртуальная карточки, права, сбой, неполный и пустой ответ,
  выход и смена двух синтетических аккаунтов; регрессии чата, LLM и изоляции окна.
- Auth и calendar E2E используют общий синтетический protocol handler, явную
  синтетическую cookie и настоящий Keychain. В этих тестах DNS для
  `team.small.kz` блокируется. Это не тест production Set-Cookie или входа Small.
  Синтетические Keychain-записи удаляются при завершении.

## Реальная проверка

В приложении открыть профиль и войти непосредственно в форме. Сверить день,
неделю, месяц, публичный календарь и несколько карточек с Team Small;
проверить выход и повторный вход. Не сохранять реальные payload или скриншоты
с персональными данными в репозиторий. Пока это не выполнено, критерии T06
и контрольная точка B остаются открытыми.
