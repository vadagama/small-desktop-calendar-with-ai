# Локальный кэш календаря и фоновая синхронизация

Календарь показывает последнее подтверждённое состояние сразу, обновляет его в фоне
без кнопки «Обновить» и подсвечивает то, что изменилось. Запись остаётся онлайн:
каждое изменение по-прежнему подтверждает Small, а журнал мутаций (T10) не менялся.

## Решения

- Опрос раз в 60 с, только диапазона, который смотрит пользователь; при скрытом окне и
  без сети опрос пропускается, при фокусе окна догоняет. Push и `updated_at`/ETag у
  Small не подтверждены, поэтому диф считается по отпечатку содержимого.
- События кэшируются в main (renderer в прод-сборке не ходит в сеть, CSP
  `connect-src 'none'`). Окно недели плюс просмотренные диапазоны; события живут 7 суток.
- Справочники (список календарей, поиск людей) живут 24 часа. Пустой результат поиска
  не кэшируется. Ручное «Обновить» перечитывает список календарей.
- Ассистент: коллеги из кэша, **встречи всегда из сети** (свободный слот оценивается по
  живым данным). Запись встреч и расчёт слотов кэш не используют.
- Перенос и изменение длительности показываются сразу (оптимистично). Удаление и правка
  названия остаются пессимистичными.

## Устройство

**Main**

- `event-cache.ts` — кэш событий и справочников. На диске только шифртекст
  (`safeStorage`, асинхронные методы), файлы 0600, каталоги 0700, имена — хэши, каталог
  на аккаунт. Привязка записи к аккаунту, ключу и сроку проверяется при чтении; битый,
  чужой, просроченный файл — промах и удаляется. Без доступного шифрования (на Linux —
  и при бэкенде `basic_text`) кэш только в памяти. Запись, начатая до очистки или
  инвалидации, отменяется счётчиком «эпохи». Размер значения ограничен 4 МБ.
- `calendar-sync.ts` — «показать из кэша, обновить в фоне». Любое подтверждённое чтение
  обновляет кэш и рассылает push `calendar:changed` (события с диффом и статусы
  `online` / `offline` / `auth-expired`). Фоновый неполный ответ (один из источников
  недоступен) не заменяет полный снимок и считается потерей связи; на явный запрос
  пользователя неполные данные показываются как есть. Один запрос на диапазон, backoff
  до 10 мин, 401 останавливает опрос.
- `calendar-catalog.ts` — кэш справочников, `assistantCalendarSource` — маршрутизация
  для ассистента.
- Инвалидация после записи (`write-target.ts`, `series-invalidation.ts`,
  `shared/calendar-invalidation.ts`): сбрасываются только диапазоны, которые запись
  могла затронуть (пересекают её время или содержат событие; вхождение серии
  сопоставляется с исходным событием). Если запись не удалось описать, а также после
  операции над серией, сбрасывается всё. Вход и выход очищают кэш полностью, до смены
  состояния и после неё.
- `calendar:events` принимает `allowStale`; без него чтение идёт в Small, как раньше.
- Ответ записи получил признак `unknownOutcome`: явный отказ (400/409/422) и
  «исход неизвестен» раньше были неразличимы для renderer.

**Renderer**

- `useSmallCalendar` хранит до 8 просмотренных диапазонов (возврат без экрана загрузки),
  принимает push, отдаёт `stale`, `offline`, `fetchedAt` и последний диф. Логика вынесена
  в чистые модули `shared/calendar-view-state.ts`, `calendar-freshness.ts`,
  `calendar-change-marks.ts`.
- Плашка свежести только при ошибке обновления или потере связи, с кнопкой «Обновить» (`aria-label="Обновить календарь"`); подсветка
  карточек `data-change`; `ViewTransition` для сетки дня и недели (запускается только
  при реальном изменении, при `prefers-reduced-motion` — статичная рамка).
- Оптимистичный перенос (`shared/optimistic-move.ts`): `saving` → `awaiting` /
  откат при отказе / `unknown`. Исход `unknown` решают только данные Small,
  прочитанные после него. Журнал мутаций не затронут.
- `EventDetails`: баннер, если событие изменилось на сервере; перезагрузка карточки не
  теряет набранное в форме; блокировка действий только после ответа `not-found`.

## Проверка

- Юнит-тесты (`npm test`): отпечаток и диф, кэш (шифрование, права, TTL, изоляция
  аккаунтов, гонки записи с очисткой, лимиты), синхронизация (опрос, backoff, 401,
  дедупликация, неполные ответы), инвалидация, состояния оптимистичного переноса.
- Сквозные сценарии (`npm run test:desktop`): изменения на сервере без обновления,
  один переход на реальное изменение и ни одного на тихих опросах, возврат к
  просмотренному диапазону без загрузки, перенос в четырёх исходах, точечная
  инвалидация, баннер на открытой карточке, справочники из кэша, потеря связи и
  возврат, возврат ко входу при 401, `prefers-reduced-motion`, кэш после перезапуска
  (Small недоступен); на реальном `safeStorage`: шифртекст, права, очистка при выходе
  и смене аккаунта.
- Ключевые защиты проверены мутациями (поломка условия роняет тест).
- Сквозные тесты входят в аккаунт, и запись сессии в Keychain принадлежит процессу
  Electron: удалить её снаружи нельзя, убирает её только выход из аккаунта в приложении.
  Поэтому новые спеки завершаются `signOutOfApp` (`tests/desktop/fixtures/keychain.ts`).

## Ограничения

- Блокировки записи при отсутствии сети нет: попытка уходит в Small и сообщает об исходе.
- Для справочников нет оффлайн-запасного варианта: просроченная запись скрыта.
- Кэш выдаётся без сверки аккаунта с сессией (сверка стоила бы сетевого запроса на каждое
  чтение); защита держится на очистке при входе и выходе.
- `ViewTransition` не включён для месячного вида.
- Вывод «не применён» после неизвестного исхода сделан по одному свежему чтению и не
  доказывает, что запись не дойдёт позже; повтор по-прежнему блокирует журнал.
- Удаление, правка названия и отмена остаются пессимистичными.


После подтверждённого создания встреча в видимом загруженном периоде добавляется
в сетку сразу, успешное удаление сразу убирает карточку. Повторное чтение уточняет
полные данные. Это не офлайн-запись: до подтверждения сервера сетка не выдаёт
создание или удаление за успех. Для собственного создания серверное уточнение
не вызывает повторной анимации; используются алиасы вхождения.
