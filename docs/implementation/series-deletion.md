# Удаление серий из UI и Ассистента

В карточке повторяющейся встречи организатор выбирает «Удалить», затем область:
«Только это вхождение» или «Это и последующие». Та же форма выбора есть в
карточке удаления Ассистента. Инструмент `prepareMeetingDeletion` только читает
данные и готовит карточку: запись происходит по кнопке пользователя. Для явной
просьбы удалить серию инструмент принимает `scope: following`; без области
карточка начинает с одного вхождения. Прошедшие дни удалять нельзя.

Оба интерфейса используют `SeriesController` и `SeriesDeletionService`.
Перед записью main заново читает карточку, проверяет аккаунт, организатора,
серию, дату и совпадение времени с подтверждением. Виртуальное вхождение сначала
материализуется POST `/calendar/events/from-template`; полученный ID повторно
проверяется чтением. Для одного вхождения отправляется POST `/{id}/cancel`,
для этого и последующих — DELETE `/{id}`. Это тот же путь, который использует
диалог удаления текущего публичного клиента Small `index-Cwe5QV54.js`,
проверенный 30 октября 2026 года. Запросы не используют `force` и не повторяются
автоматически. Транспорт разрешает только строгие формы materialize/cancel.

До первого запроса изменения сохраняется запись в `userData/series-mutations`:
хэши запроса и ожидаемого результата, область сверки, отметка подтверждённого
ответа. Названия, участники и содержимое встреч в журнал не записываются.
Неизвестный исход блокирует новую отправку для серии, в том числе после
перезапуска и при выборе другой области. Повторное действие только сверяет
состояние. Явный отказ сервера снимает запись и разрешает осознанную повторную
попытку. Подтверждённая операция возвращает `already-applied` без повторной записи.

После ответа проверяется окно от 14 дней до выбранной даты до 84 дней после:
затронутые вхождения отсутствуют, остальные в этом окне не изменились. Эта сверка
не доказывает состояние бесконечной серии вне окна. При несовпадении приложение
показывает неизвестный исход, а не успех. Кэш всех периодов сбрасывается после
любого результата записи, включая ошибку.

Проверки используют синтетические события: тесты main покрывают права,
материализацию, обе области, сохранение предыдущих вхождений, неполные чтения,
устаревшее подтверждение и блокировку повторов. Electron проверяет удаление из
карточки и через Ассистента с реальными preload/IPC/transport и тестовым API.
Удаление реальных production-встреч не выполнялось; серверная семантика за
пределами воспроизведённого клиентского пути отдельно не подтверждалась.
