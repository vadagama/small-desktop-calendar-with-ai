# Диалог календарного ассистента

Согласованная карта: [assistant-dialogue-map](../proposals/assistant-dialogue-map.md).

## Пользовательский сценарий

«Создай встречу завтра после обеда с Олегом и Витей» запускает поиск людей.
Ассистент уточняет неоднозначных кандидатов, название и длительность, если они
неизвестны. Ответы «второй» и «на полчаса» продолжают тот же чат. Промежуточные карточки и таблицы поиска сотрудников скрыты; неоднозначность ассистент уточняет обычным сообщением.
После проверки всего состава показываются до пяти слотов; пользователь выбирает
один, получает черновик и создаёт встречу отдельной кнопкой. Выходные допустимы
по запросу. Точные ID, ISO-даты и UTC-offset остаются внутренним контрактом.

## Контекст и инструменты

- Vercel AI SDK `ToolLoopAgent` выполняет до 20 шагов; main допускает до 24
  календарных вызовов и ограничивает ход 120 секундами.
- Renderer передаёт новый текст и conversationId. История поступает из main,
  не из renderer: он не может подделать результаты инструментов в истории.
- Worker возвращает `responseMessages` всех шагов. `response.messages` относится
  только к последнему шагу и для истории не подходит.
- История хранится в оперативной памяти: до 12 целых ходов, старые целые ходы
  удаляются при превышении 100 тыс. символов. Последний ход остаётся целым.
  Полный архив переписки после перезапуска не сохраняется.
- На каждом ходе добавляются текущее время, местные «сегодня», «завтра» и
  ближайшие восемь дней с названиями дней недели в Asia/Almaty.
- Main сохраняет результаты каталога и выбранный состав. `selectParticipants`
  принимает только найденные ID. При нескольких кандидатах в первом поиске
  требуется следующий пользовательский ход; смысл уточнения распознаёт модель.
  Исключение — rememberedAliases, сверенное с сохранённым подтверждённым
  прозвищем и заново найденным ID. Частота выбора этого права не даёт.
- `findSlots` и `prepareMeetingDraft` требуют весь выбранный состав. Имена
  карточки фиксируются вместе с проверяемыми ID до асинхронной проверки.
- `timeFrom/timeTo` фильтруют полные интервалы в Алматы. Выходные включаются
  явно. Черновик и запись повторно проверяют занятость; журнал повторов сохранён.
- Новый чат, выход и смена аккаунта изолируют историю. Отменённые/ошибочные ходы
  не записываются в историю. Контекст начатого запроса не переносится к другому аккаунту.

## Память

`participant-memory/<sha256 account>.json` в Electron userData хранит до 100
участников: ID, имя, должность, подтверждённые прозвища, число выборов и дату.
Файлы имеют права 0600; запись сериализована и атомарна. Токенов и встреч нет.

Частота увеличивается при выборе состава (не при создании встречи). Она помогает
ранжировать людей, но не доказывает, кого имел в виду пользователь. Прозвище
сохраняется через `participantMemory remember` по просьбе пользователя после
выбора. Повторное сохранение того же прозвища исправляет прежнее соответствие.
Перед использованием памяти человек повторно ищется в актуальном каталоге.

«Забудь Виктора» удаляет его запись, «очисти память участников» удаляет все
записи текущего аккаунта. Очистка восстанавливает работу и после повреждения
файла памяти. Удаление памяти не удаляет текст уже открытого диалога: для этого
начните новый чат. Облачной синхронизации памяти нет.

## Шаблоны без редактора в приложении

Поставляемые файлы: `src/agent/content/templates/`. Локальные переопределения:
`<userData>/assistant-templates/`. На macOS при обычном запуске это
`~/Library/Application Support/Small Calendar/assistant-templates/`; корень определяется
Electron `app.getPath("userData")` и может меняться при `--user-data-dir`.
Создайте папку, скопируйте нужные файлы, отредактируйте и перезапустите приложение.
Отсутствующие файлы берутся из поставки. Размер одного файла — до 16 тыс. символов.

| Файл | Поля |
|---|---|
| `welcome.md` | Свободный Markdown приветствия |
| `suggestions.md` | Один готовый запрос на строку |
| `people.md` | `{{name}}`, `{{position}}` |
| `slots.md` | `{{date}}`, `{{duration}}`, `{{participants}}` |
| `draft.md` | `{{title}}`, `{{time}}`, `{{duration}}`, `{{participants}}`, `{{organizer}}`, `{{location}}`, `{{agenda}}` |

Переменные экранируются как данные. Поддерживается CommonMark через react-markdown;
HTML не исполняется, внешние изображения не загружаются, Markdown-ссылки
отображаются текстом. Кнопки выбора/создания и результат проверки остаются
типизированными React-компонентами. Шаблон меняет представление, а не права или
параметры записи. Инструменты загрузки скиллов/справочников показаны свёрнутыми
служебными строками, не карточками арифметики.

## Mood

Настройки AI-помощника содержат выбор neutral/strict/youthful/alpha/technical.
Русские названия: нейтральный, строгий, молодёжный, альфа, технарь. Описания
поставляются отдельно в `src/agent/content/moods/*.md`. Настройка сохраняется
между запусками и применяется со следующего хода. Стиль меняет тон и структуру
ответа, но не факты, выбор людей и подтверждение создания.

## Проверка и пределы

Команды: `npm test`, `npm run typecheck`, `npm run build`, `npm run build:desktop`,
`npm run test:desktop`. Целевые E2E: `calendar-assistant.spec.ts`,
`agent-settings.spec.ts`, `assistant.spec.ts`.

Тесты проверяют историю tool calls через настоящие utility/main/preload процессы,
выбор кандидатов и слотов, Markdown, computed font-size 14/13px, локальные
шаблоны, сохранение Mood, память после перезапуска, изоляцию аккаунтов, выходные,
границы времени, редактирование, устаревшую ревизию, повторную запись и неизвестный
исход. В E2E сетевые границы Small и LLM заменены синтетическими серверами.

Распознавание смысла свободного текста зависит от выбранной модели и её поддержки
tool calling. Дополнительно 29 октября 2026 года выполнена проверка выбранного
`vllm/glm-5.3-flash` с вымышленным каталогом: запрос «завтра после обеда на Олега
и Витю» привёл к уточнению двух Викторов, затем ответ «из отдела Б, на 30 минут»
сохранил Олега, выбрал нужного Виктора и вызвал findSlots с датой 2026-10-30 и
диапазоном 14:00–18:00. Реальные календарные чтения/записи в этой проверке не
выполнялись. Это проверка одного сценария, не гарантия всех формулировок. Поиск полного состава подразделения, публичные/повторяющиеся
встречи, изменение/отмена через AI и обзор недели инструментами пока не поддержаны.

### Карточка создания и обновление календаря

Черновик использует отдельный Markdown-шаблон `templates/draft.md`: дата с
интервалом, участники, организатор, формат и повестка разделены визуально.
В обычном состоянии доступна одна кнопка создания. Технические пояснения и
дублирующий текст модели скрыты; при ошибке проверки причина остаётся видимой.
Неизвестный результат допускает только сверку, без повторной записи.

После подтверждённого успеха интерфейс выводит отдельное сообщение с деталями,
перечитывает календарь текущего аккаунта и переходит к дате созданной встречи.
Electron E2E проверяет конфликт перед записью, успешное создание, появление
события в календаре, единственную запись при повторе и неизвестный результат.
29 октября 2026 также пройден реальный UI-сценарий с настроенной моделью и API
Small: тестовая встреча только с организатором создана и появилась в календаре
без ручного обновления. Сбой записи из пользовательского сообщения в этом
сценарии не воспроизведён; отсутствие автоматического обновления устранено.

### Явный отказ API при создании

HTTP 400/401/403/404/409/422 на запрос создания теперь обрабатываются как отказ,
а не неизвестная отправка: карточка показывает причину и остаётся черновиком.
Только подтверждённый отказ позволяет освободить собственную запись журнала;
повтор возможен по следующему нажатию после новых проверок, не автоматически.
Ошибки транспорта, 5xx и неполный успешный ответ сохраняют блокировку дублей.
Старые попытки без ответа/ID не разблокируются по одному отсутствию события
в списке. Electron E2E проверяет отказ 409, последующее явное подтверждение и
неизвестный исход; модульные тесты отдельно проверяют классификацию HTTP.

### Организатор в составе участников

Реальный отказ 422 выявил обязательное правило Small: текущий пользователь должен
входить в `participant_ids`. Теперь при подборе времени и подготовке черновика
добавляется `profile.participantId` (GUID физлица), а не ID аккаунта. Организатор
учитывается в проверке занятости и payload, без дублей и без исключения гостей.
Карточка показывает полный состав. Регрессии проверяют оба варианта входа —
с организатором и без него — и запрещают потерю выбранного гостя.
Реальный запрос после исправления вернул 201; полученное событие прошло сверку
деталей. Персональные данные и payload этой проверки в репозитории не сохраняются.

## Просмотр личного расписания

Навык `schedule` и read-only инструмент `listMeetings` используют существующий
`CalendarService.events` для личного календаря аккаунта, закреплённого в main.
Запросы «сегодня за весь день», «завтра», «на этой неделе», «на следующей
неделе» не требуют выбора участников. Относительные периоды вычисляются в
Asia/Almaty; неделя начинается в понедельник, включает воскресенье и прошедшие
часы. Произвольный период `custom` включает обе даты и ограничен 31 днём.

Чтение выполняется по неделям с фильтрацией по точным границам периода,
сортировкой и дедупликацией переходящих встреч. Ответ ограничен 200 встречами;
лимит или ошибки источника отмечают `complete: false`. Ассистент показывает
один Markdown-список по дням без промежуточной карточки инструмента. Пустой
неполный ответ не означает отсутствие встреч. Названия и места событий
рассматриваются как данные, а не инструкции; описания событий не передаются.

Настройки версии 1/2 мигрируют в версию 3: добавляется включённый навык
расписания, сохраняются пользовательские тексты, Mood и выключенные навыки.
Проверки покрывают границы года и часового пояса, полный день, переходящие
события, неполные данные, отмену, привязку аккаунта и путь utility/main/UI в
Electron с тестовым API.

## Личный слот без приглашённых

«Создай личную встречу», «запланируй слот для меня на 2» и «без участников»
задают состав только из организатора. Если пользователь явно называет гостей,
ассистент учитывает их. Время «на 2» не трактуется как число участников;
неоднозначные дату, время и длительность ассистент уточняет.

`selectParticipants({ participantIds: [] })` явно очищает прежних приглашённых.
Пустой список в `findSlots` и `prepareMeetingDraft` допустим после этого выбора
и при известном `profile.participantId`. Main добавляет организатора и проверяет
его занятость. В черновике и запросе создания остаётся GUID организатора.

## Удаление через ассистента

Навык `meeting-delete` использует расписание для выбора конкретного события.
При нескольких совпадениях ассистент уточняет выбор. `prepareMeetingDeletion`
принимает ключ события и местную дату, заново читает личное расписание и получает
проверенное превью через `EventChangeService`. Неполные данные, чужие встречи,
серии и их вхождения не дают карточку удаления.

Инструмент подготовки не пишет в календарь. Карточка в чате показывает название,
дату, время и кнопку «Удалить встречу». Только нажатие вызывает существующий
`calendar.applyChange` с `cancel`: сервис заново проверяет организатора и тип
события, использует журнал операций и проверяет удаление на сервере. После
успеха календарный кеш инвалидируется. При неизвестном исходе журнал блокирует
повторную запись до сверки; интерфейс не сообщает об успехе заранее. Для
повторяющихся встреч выбор вхождения/серии доступен через календарь.

Настройки версии 5 добавляют включённый навык удаления. Стандартные тексты
подбора времени и подготовки встречи обновляются по точному совпадению со
старыми; пользовательские тексты и выключенные навыки сохраняются.
При переносе события полоса «Сохраняю время встречи…» над сеткой не выводится;
состояние сохранения остаётся на самой карточке события.
