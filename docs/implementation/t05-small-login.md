# T05 — Вход в Small

Текущее хранение секретов описано в [локальном хранилище](local-credential-storage.md).
Keychain в описании исходного этапа ниже больше не используется: требуется
повторный вход и сохранение API-ключа, автоматического импорта нет.


Дата проверки: 29 октября 2026 года. Клиент реализован и проверен на
синтетическом сервере в упакованном arm64-приложении. Реальный вход,
серверный отзыв сессии и два реальных тестовых аккаунта ещё не проверены.

## Поведение и границы

Кнопка профиля внизу левой панели открывает вход по логину и паролю.
После входа отображаются имя и логин сотрудника, доступны проверка сессии
и выход. Пароль очищается из формы после отправки и не сохраняется.
Календарь остаётся демонстрационным до T06.

Основной процесс обращается только к четырём фиксированным путям
`https://team.small.kz`: `/gate/auth/login`, `/gate/auth/refresh`,
`/gate/auth/logout`, `/gate/team/api/user/info`. Редиректы запрещены;
таймаут каждого запроса — 15 секунд. В renderer доступны только
`read`, `login`, `logout`, с проверкой доверенного отправителя IPC.
Ассистент не получает сессию, пароль или персональный профиль.

Для cookie используется отдельная непостоянная Electron session, без окна,
preload и общего с renderer хранилища. Снимок cookie и идентификатор `X-K-Csrf`
сохраняются в существующем Keychain namespace приложения под отдельным именем.
Access token остаётся в памяти основного процесса. Домен и атрибут Secure
проверяются при сохранении и восстановлении cookie. Новых зависимостей нет.
Это продолжает подход T04: секреты находятся в Keychain, привилегии — в main.
Встраивание удалённой страницы входа потребовало бы дополнительного контракта
передачи сессии из web content; локальная форма использует подтверждённый API.

При перезапуске refresh восстанавливает access token; профиль проверяется
чтением `/user/info`. После 401 выполняется один refresh и одна повторная
проверка. Отказ refresh возвращает форму входа. Сетевой сбой сохраняет
восстановимую сессию, но не показывает прежний профиль как подтверждённый.
Все переходы выполняются последовательно, чтобы refresh не отменил выход.

Выход сначала пытается отозвать серверную сессию, затем обнуляет токен,
перезаписывает Keychain пустым значением и очищает cookie. Если удалить запись
Keychain физически не удалось, пустое значение блокирует восстановление.
Отказ перезаписи Keychain выводится как ошибка: успешный долговременный выход
в этом случае не заявляется. При недоступности сервера локальный выход
сопровождается предупреждением о неподтверждённом отзыве.

## Подтверждённый клиентский контракт

Повторно прочитана публичная сборка
[index-Dwj9jIUp.js](https://team.small.kz/assets/index-Dwj9jIUp.js).
Она передаёт `{username, password, remember_me}` в login, `{}` в refresh/logout,
читает `data.access_token`, использует cookie и `Authorization: Bearer`.
Для отображения профиля официальный клиент читает JWT claims
`uid`, `preferred_username`, `name`; desktop использует их только после
успешного `/user/info`, без выдачи прав по JWT claims.

Серверная схема профиля пока неизвестна. Проверяется объект `data`, но
не предполагаются поля сотрудника в этом объекте. Требуется проверка
cookie, `X-K-Csrf` (в desktop используется UUID), claims и серверных ошибок
с реальной учётной записью. Синтетический результат не подтверждает
совместимость с production Small или его правила отзыва сессий.

## Проверки

- `npm test`: 37 тестов, включая девять тестов auth: refresh, отзыв,
  смена аккаунта, неверный пароль, отказ Keychain, неизвестные поля,
  выход без сети, сбой очистки cookie и очередь refresh/выход.
- Тест ошибки очистки cookie сначала воспроизвёл сохранение старой сессии;
  исправление сначала обнуляет Keychain. Инверсия условия валидации входа
  обнаружена тестами, исходный код восстановлен.
- `npm run typecheck`, `npm run build`, `npm run format:check` прошли.
- `npm run package:mac`: arm64 `.app` собрана. Bundler предупреждает о
  директивах `use client` в зависимостях; packager — об отсутствии нового
  формата `.icon`, при наличии существующего `.icns`.
- `SMALL_APP_EXECUTABLE="$PWD/release/Small Calendar-darwin-arm64/Small Calendar.app/Contents/MacOS/Small Calendar" npm run test:desktop`:
  четыре E2E проходят с PATH без Node: окно/изоляция, чат, LLM-профили,
  вход Small. Проверены неправильный пароль, очистка формы, профиль,
  Keychain, восстановление после перезапуска и выход.
- В auth E2E сервер заменяется обработчиком Electron protocol, а login
  явно устанавливает синтетическую cookie. Это проверяет путь UI → IPC →
  main, cookie jar и настоящий Keychain, но не получение production Set-Cookie.
  DNS для `team.small.kz` отключён в этом тесте. Персональных данных нет;
  синтетическая запись Keychain удаляется в завершающей очистке.

## Следующая проверка

Открыть профиль в приложении и ввести собственные данные непосредственно
в форме. Проверить вход, перезапуск, «Проверить сессию» и выход; затем
изоляцию второго разрешённого тестового аккаунта и серверный отзыв.
Не переносить ответы с персональными данными в репозиторий или чат.
До этого T05 и контрольная точка B остаются открытыми.
