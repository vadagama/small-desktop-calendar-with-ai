# Поиск участников и ссылки конференций

Поиск участников и информируемых запускается через 300 мс после ввода.
Кнопка поиска и Enter запускают его сразу. Выдача содержит полное имя,
инициалы и должность; однофамильцы различаются по ID каталога. Сотрудник
добавляется нажатием на строку, без чекбоксов. После выбора запрос очищается,
выдача закрывается, остаётся чип; фокус возвращается в поле для следующего
поиска. Выбранные люди не показываются повторно в выдаче. Чипы позволяют
удалять приглашённых; организатор фиксирован и не имеет кнопки удаления.
Он включается и при переданном начальном составе, и при редактировании;
его ID и имя берутся из события, а для новой встречи — из текущего аккаунта.

Следующая страница дополняет выдачу. Каждый ввод сбрасывает таймер 300 мс;
Enter и кнопка выполняют поиск сразу и отменяют отложенный запуск. Пустой
ввод, выбор и закрытие формы отменяют ожидающий таймер; ответы на старый
или очищенный запрос игнорируются. Стрелки переводят фокус между строками,
Enter/пробел добавляют сотрудника, Escape скрывает выдачу. Используется
существующий employee API и его проверка авторизации.

## Ссылка и календарный API

Календарь генерирует адрес только из простых английских слов:
`https://meet.small.kz/funky-monkey-party`.
Первые два слова — готовая созвучная пара, третье выбирается из
локального словаря без повторов внутри адреса. В словаре 878 слов и 47 созвучных пар. Нет цифр, UUID или случайных
букв. Словарь и пары находятся в `src/shared/conference-words.ts` и составлены
для проекта, без загрузки внешних словарей и обращения к LLM.

Выбор криптографический (`crypto.getRandomValues`), с отбрасыванием значений,
которые давали бы смещение при делении по модулю. Ровно три слова образуют короткий адрес
без технического суффикса; словарь даёт около 41 тысячи сочетаний. Генератор общий для ручной формы
и черновиков ассистента; существующая ссылка сохраняется при редактировании.
История последних 4096 адресов в каждом процессе предотвращает недавние
локальные повторы. При совпадении выбирается новый адрес, максимум 32 попытки.
Ошибки источника случайности не заменяются предсказуемым адресом.

История не сохраняется на диск и не синхронизируется между процессами,
установками или пользователями. Глобальная уникальность не гарантируется;
генерация адреса не резервирует конференцию на сервере. Текущий веб-клиент
Team использует другой локальный формат `xxx-xxxx-xxx`; календарь намеренно
использует читаемые слова по запросу пользователя.

При создании и редактировании URL передаётся в `location`, как в Team;
`description` содержит повестку. Переговорная задаётся отдельно в
`calendar_ids`. Существующие URL, включая UUID, сохраняются при открытии
редактора. Старые записи со ссылкой в описании поддерживаются: при изменении
ссылки/повестки/переговорной URL переносится в `location`. Пользовательское
описание с другой ссылкой не очищается. Одно изменение заголовка не меняет
расположение старой ссылки.

## Проверенный источник

Проверка 9 ноября 2026 года: публичная сборка
[Team](https://team.small.kz/assets/index-C-sR5Ask.js), функции `Uwn`, `Clu`,
`Slu`, `xlu`, обработчик с `Z("location", Ht, …)`. В обработчике генерации
нет HTTP-запроса регистрации комнаты. Это наблюдение текущего клиента,
а не гарантия устройства закрытого backend API.

[meet.small.kz](https://meet.small.kz) обслуживает Jitsi Meet: конфигурация
указывает XMPP/BOSH, отдельный гостевой и авторизованный домены; клиент
создаёт конференцию через `initJitsiConference` при подключении.
[Документация Jitsi](https://jitsi.github.io/handbook/docs/devops-guide/authentication/)
описывает создание комнаты авторизованным организатором и подключение гостей.
Подключение к рабочей конференции и права конкретного пользователя не
проверялись. HTTP-ответ страницы комнаты не доказывает доступность звонка.

## Проверки

`tests/desktop/people-picker.spec.ts` проверяет поиск без кнопки, выбор с
клавиатуры, дополнение страниц, сохранение чипов, пустую выдачу и 13 px.
`tests/agent/conference-link.test.ts` проверяет формат и размещение URL в API.
Сценарии создания и редактирования проверяют сохранение полей в Electron
через синтетический транспорт; запросы к production при этом не отправляются.


## Фоновые E2E

`playwright.desktop.config.ts` по умолчанию задаёт `SMALL_E2E_BACKGROUND=1`.
В Electron, включая проверку готового пакета, окна остаются скрытыми при старте и действиях
уведомлений; Dock скрывается, таймеры renderer не замедляются, календарная
синхронизация продолжает работать. Без этой переменной обычный запуск приложения не меняется. `SMALL_E2E_BACKGROUND=0` разрешён для видимой отладки
только по явному запросу пользователя согласно `AGENTS.md`.
