# Память ассистента

Дата проверки: 30 октября 2026 года. Реализованы активные этапы A–C
[плана](../../tasks/assistant-memory/plan.md): предпочтения, произвольные записи
контекста, группы участников и форматы встреч. Архив чатов остаётся
[в бэклоге](../../tasks/assistant-memory/backlog.md).

## Пользовательское поведение

В нижней части бокового меню находятся мозг «Память ассистента» и кнопка
«Настройки AI-помощника». Форма памяти использует компоненты и плотность прототипа:
отдельные предпочтения, список текстовых записей, добавление, редактирование,
удаление, источник и дата. Группы и форматы используют поиск сотрудников Small;
вводить идентификаторы вручную не требуется. Очистка категории и всей памяти
требует подтверждения. Ошибка сохранения оставляет текст в редакторе; конфликт
версий требует обновить данные.

Фраза «запомни» запускает проверку смысла будущей записи. Ассистент читает
актуальную память через `recall`, проверяет людей, область применения,
точность времени и единиц, исключения, временный или постоянный характер,
дубликаты и противоречия. Затем вызывает `review` с точным изменением и
оставшимися вопросами. Не нужно выяснять параметры, которые не меняют смысл
сохраняемого факта: например, длительность для записи только состава команды.

Пока есть вопросы, карточка не создаётся. Ассистент задаёт короткий вопрос
и ждёт следующего сообщения. После ответа снова проверяет запись, передавая
точную цитату ответа в `evidence`. Исходная просьба запомнить действует в рамках
этого уточнения; повторять её не нужно. Неполный ответ оставляет вопросы открытыми.
`cancel` отменяет незавершённую проверку. Уточнение хранится только в RAM,
привязано к окну, сессии, revision и ходу, действует до десяти минут.

Main не разрешает `propose` без проверки, с открытыми вопросами или изменённым
после проверки текстом. Смена аккаунта, сессии, revision или истечение срока
требуют новой проверки. Эти правила распространяются также на запись прозвищ
через `participantMemory`. Оценку смысловых неоднозначностей выполняет модель:
программная проверка последовательности не гарантирует их полного обнаружения.
Ручное сохранение в настройках остаётся прямым действием пользователя.

После уточнения создаётся карточка с точным изменением. До нажатия
«Подтвердить изменение памяти» запись отсутствует в хранилище. Main связывает
карточку с аккаунтом, окном, сессией входа, сообщением, revision и request ID.
Карточка действует десять минут; повторное подтверждение идемпотентно.
Обычная просьба назначить встречу постоянную память не меняет.

Для новых записей, групп и форматов `propose` принимает изменение без `id`:
идентификатор создаёт хранилище. Редактирование использует существующий `id`
из актуального `recall`. Неизвестный `id` отклоняется до показа карточки;
инструмент возвращает модели причину и способ исправить вызов. Удалённая запись
не становится новой автоматически. Перед предложением группы или формата
с отдельными участниками нужны поиск в каталоге и `selectParticipants`.
Условные предпочтения (например, после обеда только для встреч с коллегами)
передаются модели как текстовый контекст `entry`, а не как общее окно времени.

Память локальна, хранится до явного удаления, сохраняется после выхода и
разделена по аккаунтам. После выхода доступ к ней закрыт. Нужный контекст
передаётся выбранному поставщику модели: это явно указано на экране.
Текст памяти считается данными, а не разрешением исполнять инструменты.
Чаты остаются в RAM и после перезапуска не восстанавливаются.

## Хранилище и границы

`AssistantMemoryStore` в main использует существующий `LocalSecrets` с ключом
`assistant-memory:v1:<account>`. В файловом vault имя ключа хешируется;
содержимое зашифровано AES-256-GCM, файлы имеют права 0600, каталог 0700.
Ключ шифрования расположен отдельно от шифротекста в том же профиле ОС.
Это защита файлов на диске, не изоляция от процессов того же пользователя ОС.

Один версионированный конверт на аккаунт содержит предпочтения, источники,
записи, группы, форматы, прежние сведения об участниках и последние 100 request ID.
Очередь сериализует чтение и запись; revision предотвращает потерю изменений,
атомарная замена файла переиспользует `LocalSecrets`. Дополнительных зависимостей,
SQLite и сетевой синхронизации нет. Использование существующего namespace
секретов сохраняет защиту от создания нового master.key поверх зависимых данных.
Это осознанный выбор вместо отдельных файлов категорий из первоначального плана.

Повреждённый конверт или неизвестная версия не заменяются пустыми данными.
Интерфейс позволяет явно сбросить всю память текущего аккаунта с подтверждением;
восстановление отдельных повреждённых категорий из одного конверта не выполняется.
Потерянный ключ нельзя заменить через этот экран: необходимо восстановить
профиль vault из резервной копии. Ошибки не содержат текст записей и ключи.

Первое чтение импортирует `participant-memory/<sha256 account>.json`:
ID, имя, должность, все прозвища, частоту и дату. Прозвища также становятся
редактируемыми текстовыми записями с источником «Из прежней памяти участников».
При длинном списке карточка показывает первые 12 прозвищ и количество остальных;
внутренние соответствия сохраняются полностью. Старый файл удаляется только
после записи и контрольного чтения нового конверта. Последующие чтения не
импортируют его повторно, даже после очистки памяти.

Редактирование или удаление записи прозвища снимает прежнее соответствие
человеку. Произвольный текст сам по себе не подтверждает личность. При изменении
revision из рабочего контекста удаляются целые ходы с результатами memory-tools;
старый результат не возвращает удалённую запись. Видимый текст открытого чата
не удаляется. Выход или смена аккаунта сбрасывает рабочий контекст.

## Применение к встречам

Main разрешает каждый параметр отдельно: явное указание текущей задачи →
формат встречи → предпочтения → стандартные значения. Разовые параметры
переживают следующий ход текущей задачи; новая задача или аккаунт их сбрасывает.
Модель извлекает их инструментом `assistantMemory task`, указывая точную цитату
текущего запроса. Конкретное время вне предпочтительного окна снимает окно для
задачи; перерыв снимается только по отдельной явной просьбе.

Перерыв применяется только к организатору. Занятость остальных участников
проверяется на обычные пересечения. Точная граница допустима; при пересечении
полуночи дополнительно читается занятость организатора соседней даты. Неполный
ответ или неизвестный организатор останавливает проверку, не даёт свободный слот.

Черновик содержит снимок ограничений и revision. Перед подтверждённой записью
повторно проверяются память, занятость, переговорная и дубликаты. Изменение
памяти требует нового черновика. Защита журнала от повторной отправки при
неизвестном исходе сохраняется. Применение предпочтений относится к подготовке
через ассистента; ручная форма создания встречи сохраняет собственные явные поля.

Группа и формат используют конкретные ID, без вложенных групп. При сохранении
и каждом использовании участники сверяются с текущим сетевым каталогом, включая
лимит 20 вместе с организатором. Исчезнувший участник требует уточнения; имя,
совпадающее с человеком, требует уточнить смысл. Удаление группы оставляет
видимую сломанную ссылку в формате, а не создаёт пустой состав. Слово
«еженедельный» в имени формата не включает повторение.

Сохранённый контекст, группы и форматы ограничены 100 записями каждой категории;
текст контекста — 2000 символами. Чтение моделью имеет бюджет 12000 символов
для записей, групп и форматов и сообщает о неполноте; query позволяет уточнить
выборку. Полный список остаётся доступен в форме.

Формат может хранить название до 500 и повестку до 8000 символов согласно
требованиям памяти. Действующий календарный контракт принимает название до
200 и повестку до 5000: перед созданием длинный формат нужно сократить.
Данные не обрезаются автоматически; расширение календарного контракта здесь
не выполнялось.

## Проверки

- Unit: миграция, шифрование, перезапуск, аккаунты, request ID/revision,
  сбой записи, повреждение, потеря ключа, границы схем, предложения и подтверждения.
- Интеграционные unit: предпочтения в аргументах tools, разовые исключения и
  следующий ход, удаление старого контекста, группа, формат и приоритет длительности,
  сломанная ссылка, совпадение имени, инвалидирование черновика перед записью.
- Занятость: точная граница перерыва, обычные пересечения приглашённых,
  соседняя дата и отказ на неполных данных.
- Electron E2E `assistant-memory.spec.ts`: форма, источники, предпочтения,
  контекст, группа, формат, явное подтверждение из чата, рестарт, изоляция
  аккаунтов, сохранение после выхода, отмена и подтверждение очистки.
  Computed размеры заголовка, текста записи и поля — 18, 13 и 14 CSS px.
- Прототип: 30 браузерных тестов прошли, включая редактирование, удаление,
  фокус, Escape и узкое окно.

Синтетический OpenAI-compatible HTTP endpoint проверяет SDK → worker → main →
renderer, но не качество поведения реальной модели. Реальная настроенная LLM
для этой приёмки не использовалась; автоматические проверки не создают встречи
в реальном Small. Это отдельное ограничение проверки, допустимое M09 плана.
Итоговые проверки: `npm test` — 441/441; `npm run typecheck`,
`npm run build:desktop`, `npm run format:check` и `git diff --check` — без ошибок.
Полная регрессия `npm run test:desktop` — 41/41; после заключительного усиления
очистки исторических черновиков повторный focused E2E памяти также прошёл.
В прототипе `npm test` — 12/12, `npm run test:ui` — 30/30,
`npm run build` — успешно. Vite сохраняет предупреждения зависимостей о
директиве `use client`; сборку они не блокируют.

В длинном регрессионном тесте календаря обнаружена гонка синтетического ввода
с незавершённым React View Transition после записи. Helper теперь ожидает
отрисовку и конечные анимации перед вводом; полный прогон после этого зелёный.
Временная диагностическая печать удалена.

## Откат

Перед откатом сохранить весь каталог userData, включая master.key и шифротекст;
копия одного файла не восстанавливает память. Старая версия приложения не читает
новый конверт и после успешной миграции не найдёт удалённый legacy-файл.
Для возврата к прежнему writer восстановить согласованную резервную копию
профиля; не экспортировать расшифрованную память в репозиторий. Обновление
приложения поверх сохранённого vault продолжает читать схему v1.
