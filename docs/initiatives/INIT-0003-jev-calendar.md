# Jev в календаре и ассистенте Small

Начать после [миграции на Go и Wails](INIT-0001-wails-migration.md). Проверить, помогает ли Jev пользователю выразить несколько действий одной русской фразой. Для каждого решения приложение задаёт допустимые варианты с учётом открытого экрана, включая возможность уточнения. Календарный сервис разрешает имена, проверяет права и занятость, вычисляет интервалы. Запись в Small и сохранение предпочтений проходят через подтверждение пользователя. Для первого эксперимента использовать API Jev и синтетические данные. Возможность автономного запуска на Mac требует отдельного подтверждения. [Публикация TypeSafe о Jev](https://typesafe.ai/blog/introducing-system-one-models-and-jev).

## Первые проверки после миграции

1. **Уточнение открытого подбора времени.** «Давай на полчаса, без Анны, лучше после обеда». Jev определяет изменения длительности и состава, различает пожелание и обязательное ограничение. Если в группе две Анны, приложение предлагает выбрать человека. Первым проверить этот сценарий от ввода фразы до появления правильной сетки: исходные параметры известны, пользователь сразу видит результат.
2. **Разовая просьба или постоянное предпочтение.** «На этой неделе оставь утро свободным» действует в заданный период. «Обычно оставляй утро свободным» открывает предложение сохранить правило. Это самый компактный тест понимания контекста: ожидаемый результат можно разметить как текущий подбор, период, предложение сохранить или вопрос пользователю.
3. **Черновик из переписки.** Из фразы «В четверг после обеда обсудим остатки с закупками. Дашу подключим, если потребуется» заполнить тему, день, окно и группу. Участие Даши оставить открытым вопросом. Проверять заполненные поля и то, какие решения приложение оставило пользователю.
4. **Повтор встречи по образцу.** «Собери такую же через две недели, только на 30 минут». Показать отдельный черновик с темой и составом открытой встречи, новой датой и длительностью. Проверить доступность участников. Вместе с черновиком из переписки это первый эксперимент для формы создания: пользователь может проверить каждое поле до отправки приглашений.

## Следующие сценарии

| Сценарий | Пример и проверяемый результат |
| --- | --- |
| Поиск встречи по описанию | «Открой созвон про остатки перед инвентаризацией». Индекс отбирает доступные встречи, Jev ранжирует кандидатов. Проверить случаи с одним, несколькими и ни одним подходящим событием. |
| Ранжирование свободных окон | «Хочу успеть подготовиться после планёрки». Jev выделяет пожелание оставить перерыв. Календарь ранжирует допустимые окна и показывает рассчитанную длительность перерыва. |
| Просмотр вариантов или подготовка переноса | «А если на пятницу?» открывает варианты. «Перенеси на пятницу» готовит черновик переноса. Проверить обе реплики при одной и той же открытой встрече. |
| Анализ недели по категориям | «Сколько времени ушло на собеседования?» Jev классифицирует встречи, включая вариант «неясно». Календарь суммирует длительности и показывает исходный список. |
| Область изменения серии | «Только в этот четверг начнём на час позже» и «Теперь по четвергам начинаем на час позже». В подтверждении показать затронутые даты. При двусмысленности уточнить, относится ли изменение к одному экземпляру или к серии. |
| Обзор изменений с прошлого просмотра | «Что поменялось в завтрашних встречах с закупками?» Синхронизация выявляет переносы, отмены и изменения состава. Jev отбирает относящиеся к вопросу изменения. Показать прежнее и новое значения и ссылку на встречу. Для этого в [инициативе локального индекса](INIT-0002-calendar-local-index.md) потребуется учесть историю подтверждённых изменений и версию, которую пользователь видел. |
| Подготовка по повестке | «К каким встречам завтра мне нужно подготовиться?» Найти явные поручения пользователю в доступных описаниях. Для каждого показать встречу и исходную фразу, по которой можно проверить вывод. |

## Как оценить результат

Подготовить синтетические русские реплики с ожидаемыми решениями, полями и допустимыми уточнениями. Включить пары «без Анны / без Анны нельзя», «лучше утром / только утром», «на полчаса / на полчаса позже». На одинаковых исходных данных сравнить с текущим поведением клиента после миграции.

Для каждой задачи измерять долю правильных решений, число лишних уточнений и исправлений, а также время от конца фразы до правильной сетки, карточки или черновика. В измерение включать сетевые проверки и раздельно фиксировать первый и повторный запрос. Ошибки в выборе участника, охвата серии и срока предпочтения учитывать отдельно. Решение о внедрении принимать по результатам каждого сценария.
