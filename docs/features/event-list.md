# Представление «Список» и поиск событий ассистентом

## Цель и границы
Пользователь просматривает события сплошной хронологической лентой, сгруппированной по дням, и открывает в ней результаты запроса из чата. Четвёртый режим рядом с «День», «Неделя», «Месяц». Реализовано в основном Electron-приложении. Прототип и приложение используют общий компонент списка.

## Анализ решения
Предоставленные референсы полезны одинаковыми колонками времени и названия, общей датой группы и кликабельностью всей строки. Переносим эту структуру в существующий компактный UI Small, сохраняя его шрифты, цвета, кнопки, диалог события и тултип. Отдельные большие карточки ухудшили бы сканирование; таблица с множеством колонок отнимает место у названий. Выбираем заголовок дня и строки под ним: это сохраняет ширину названия даже рядом с чатом.

Обычный список показывает выбранный календарный месяц. Стрелки переключают месяцы, «Сегодня» возвращает текущий месяц. Пустые дни пропускаются. Поиск ассистента задаёт явные начало и конец; период указан в ответе ассистента, фильтр виден над списком. Полей «С / По» и кнопки сброса периода нет; переход стрелками возвращает обычный список выбранного месяца. Бесконечную прокрутку не используем: скрытая граница загрузки мешает понять, найдены ли все события.

## Требования и критерии приёмки
- Четыре режима находятся в одном переключателе. Выбор дня/недели/месяца не меняет данные события.
- В группе есть полная дата и день недели. Сортировка дней по возрастанию, событий — по началу, затем названию и стабильному ключу. Пустые даты отсутствуют.
- В строке время начала–окончания в формате 24 часа, маркер календаря, название; организатор — вторичная подпись. Цвет не является единственным носителем информации.
- В текущем контракте Small не подтверждён признак all-day, поэтому показывается фактическое время; «Весь день» из длительности не выводится. Переход через полночь показывает дату окончания; в списке одна строка на экземпляр, в группе даты начала. Событие, начавшееся до периода и пересекающее его, входит в первую видимую группу с исходной датой начала.
- Нажатие строки, Enter или Space открывает существующий диалог. Наведение показывает существующий тултип. Esc закрывает тултип; фокус виден.
- Обычный список учитывает выбранные календари и тип участия. Поиск ассистента использует явно согласованную область: личный либо все доступные календари. Изменение ручных фильтров возвращает обычный список месяца. Поля поиска по названию в списке нет. Чипы активных фильтров расположены отдельной строкой под навигацией по месяцам; снимаются крестиком. Организатор не равнозначен участнику. Пользователь видит число результатов и активный фильтр; период и область поиска указаны в ответе ассистента.
- Пустой результат объясняет, что совпадений нет в заданном периоде и выбранных календарях. Ошибка и отказ доступа не выдаются за отсутствие событий. При загрузке используется существующее состояние календаря.
- Шрифт строки 13 CSS px, вторичной подписи 11 px, тултипа 12 px. Используются общие токены; длинное название переносится. В узкой панели поля фильтра переносятся, горизонтальная прокрутка не нужна.

## Сценарий ассистента
1. «Найди все события, где организатором была Жанна».
2. Ассистент разрешает личность через каталог. При нескольких Жаннах предлагает имена и подразделения, не выбирает автоматически и не использует совпадение по участникам.
3. Если период отсутствует в запросе и контексте: «За какой период искать?» Предлагает месяц, неделю, конкретные даты. «Все» означает все совпадения внутри согласованного периода, а не всю историю.
4. Выполняет чтение, получает события и полноту результата. Переключает календарь в «Список» только после успешного поиска. Явно сообщает область поиска.
5. Кратко сообщает количество и период. Сами события показывает в календаре, без второй длинной копии в чате. Пользователь открывает любую строку.
6. Изменение фильтра вручную обновляет результат. При отмене уточнения старый список не меняется. Новый диалог сбрасывает незавершённое уточнение.

## Реализованный контракт

`showEventList({from, to, scope, organizerId?})` выполняет чтение и открывает проверенный снимок. Даты включительны в Asia/Almaty, диапазон до 366 дней. `scope`: `my` или `all-accessible`. ID организатора берётся из `searchPeople`; при неоднозначности main требует следующий ход уточнения. Фильтрация идёт по `creator_id`, не участникам и не совпадению имён.

Main читает существующий API недельными порциями по доступным календарям, объединяет экземпляры по occurrence key. Лимиты — 96 чтений и 1000 результатов. Ошибки источников, отсутствие ID организатора и достижение лимитов дают `complete=false` и предупреждение. Автоматической кнопки «ещё» нет: пользователь уточняет запрос. Сетевые операции используют существующие таймауты сервиса; отмена проверяется между чтениями, отменённый ответ не открывает список.

Полный результат `{kind, accountId, query, organizer?, events, complete, issues, fetchedAt}` передаётся из main в renderer через узкий канал `calendar:event-list`. Модель не передаёт произвольные события или HTML. Снимок связан с аккаунтом; выход и смена аккаунта удаляют его. Изменения календаря помечают снимок устаревшим. Для актуализации нужно повторить запрос. Стрелки месяцев и удаление чипа возвращают обычный список.

Навык находится в `src/agent/content/skills/event-list/SKILL.md`. Миграция настроек до версии 6 добавляет его, сохраняя прежние пользовательские инструкции и выключенные навыки. Навык можно выключить; инструмент проверяется и в worker, и в main.

## Файлы и проверка

- `src/renderer/ui/EventList.tsx`: общий UI для приложения и прототипа.
- `src/renderer/event-list-meetings.ts`: одна строка на экземпляр, включая переход через полночь и пересечение границы периода.
- `src/main/event-list.ts`: ограниченное чтение, точный фильтр, полнота и дедупликация.
- `tests/agent/event-list.test.ts`: фильтрация, частичные данные, отмена, границы и лимиты.
- `tests/desktop/event-list.spec.ts`: Electron-сценарий списка и поиска через ассистента на синтетическом API.

Команды: `npm test`, `npm run typecheck`, `npm run build:desktop`, `npm run test:desktop -- tests/desktop/event-list.spec.ts`. Реальные данные и секреты не включаются в fixtures.

## Проверка реализации

Основная логика: 522 теста прошли; TypeScript и сборка Electron прошли. Проверены шесть desktop-сценариев: список с поиском, настройки, аналитика, фильтры, карточки/перетаскивание и анимация обновления. Прототип: 15 unit-тестов и два сценария списка прошли. Интеграционные проверки используют синтетические Small API и LLM; реальный аккаунт в тестах не использовался.

В Electron проверены 13 CSS px для строк, тултип, кликабельность, частичная выдача, снятие чипа, навигация месяцев и очистка результатов после выхода. Новый профиль проверен на отсутствие входа и ключей, нейтральное настроение, пустые инструкции, предпочтения, записи, группы и форматы.

## Известное ограничение предварительного релиза

В реальном окружении поиск по всем доступным календарям может долго оставаться в состоянии «Выполняется». Чтение сейчас последовательное по календарям и неделям; общий таймаут ассистента — 120 секунд. Ускорение и показ промежуточного прогресса не завершены. Для проверки можно явно ограничить запрос личным календарём и коротким периодом; это не исправление широкого поиска.
