# Память ассистента: требования

Дата: 30 октября 2026 года. Статус: **реализовано, подготовлено к ревью**.
Локальность, подтверждение изменений из чата, перерыв только для организатора
и сохранение после выхода согласованы пользователем. [Реализация и проверки](../implementation/assistant-memory.md),
[план](../../tasks/assistant-memory/plan.md), [задачи](../../tasks/assistant-memory/todo.md).

## Цель и границы

Ассистент использует сохранённый по просьбе пользователя контекст и настройки встреч,
понимает привычные названия составов и форматов. Пользователь видит сохранённые
данные, их происхождение и может их изменить или удалить.

Предположения для ревью:

- Хранение локальное, отдельно для каждого аккаунта Small. Облачная синхронизация,
  обмен памятью между сотрудниками и перенос на другой компьютер вне объёма.
- Первая версия — предпочтения встреч и список текстовых записей сохранённого
  контекста с управлением ими. Связи с участниками остаются проверяемыми данными
  внутри системы, а не отдельным обязательным видом карточки. Далее — группы и форматы встреч. Сохранение чатов вынесено
  в [бэклог](../../tasks/assistant-memory/backlog.md) и не входит в текущие требования.
  Контекст диалога остаётся в RAM и не восстанавливается после перезапуска.
- Записи контекста, предпочтения, группы и форматы сохраняются только по явному действию: просьбе
  в чате либо сохранению формы. Автоматический счётчик выбора людей сохраняется.
- Сохранение памяти не создаёт встречу. Создание и изменение событий требуют
  существующего отдельного подтверждения и проверок календаря.
- Память доступна после повторного входа в тот же аккаунт. Обычный выход закрывает
  доступ к ней, но не удаляет; отдельная команда удаляет все локальные данные
  памяти аккаунта.

## Текущее основание

Проверено по рабочему дереву на дату документа:

- `src/main/participant-memory.ts` хранит JSON до 100 участников аккаунта,
  подтверждённые прозвища и частоту выбора; записи сериализованы и атомарны.
- `src/main/calendar-conversation.ts` хранит в RAM до 12 целых ходов; старые ходы
  удаляются при превышении 100 000 символов, последний сохраняется целым.
- `src/main/assistant.ts` передаёт историю worker и принимает историю обратно;
  `src/renderer/Assistant.tsx` создаёт chat ID и показывает сообщения через useChat.
- `src/main/calendar-tools.ts` связывает выбранных участников с результатами
  каталога. История renderer не является доказательством полномочий.
- `src/main/availability.ts` проверяет занятость каждого участника и временные
  границы; перерыва между встречами пока нет.
- `src/main/local-secrets.ts` содержит локальный шифр с контекстом назначения;
  его текущее внедрение описано в
  [local-credential-storage](../implementation/local-credential-storage.md).
  Это основание для предлагаемого переиспользования, а не гарантия готовности
  хранилища памяти. В рабочем дереве есть незавершённые изменения этой области.

## Карта возможностей

| ID                 | Ответственность                                            | Зависимости                                |
| ------------------ | ---------------------------------------------------------- | ------------------------------------------ |
| memory-store       | Изоляция, схемы, версии, хранение, происхождение, удаление | —                                          |
| preferences        | Настройки встреч и разрешение приоритетов                  | memory-store                               |
| context-entries    | Произвольные текстовые записи по просьбе пользователя      | memory-store                               |
| memory-ui          | Просмотр, редактирование и удаление памяти                 | memory-store, preferences, context-entries |
| participant-groups | Именованные составы участников                             | memory-store                               |
| meeting-presets    | Название, состав, длительность и повестка формата          | preferences, participant-groups            |

Порядок поставки: memory-store + preferences + context-entries + memory-ui →
participant-groups → meeting-presets. Интерфейс расширяется вместе с каждым типом.
Это предлагаемая декомпозиция, её утверждение ещё не получено.

## Общие требования

**M01. Владение.** Аккаунт определяется в main из текущей подтверждённой сессии,
не из аргумента модели или renderer. При выходе/смене аккаунта текущие запросы
отменяются, расшифрованные данные и UI очищаются. Поздний результат не попадает
в новый аккаунт; незавершённая запись не подтверждается от его имени.

**M02. Происхождение.** У записи есть стабильный ID, тип, версия схемы, revision,
createdAt, updatedAt и источник создания/последнего изменения: действие в форме,
сообщение пользователя или импорт прежней памяти. Для сообщения достаточно ID
и даты, полный текст в запись памяти не копируется. После закрытия исходного
диалога или перезапуска дата и тип источника остаются. Ссылка на сообщение доступна
только пока оно есть в текущем диалоге; архив для происхождения записи не требуется.

**M03. Явное сохранение.** «Завтра на 30 минут» меняет текущую задачу.
«Запомни: обычно на 30 минут» создаёт предпочтение. Модель предлагает структурированное
изменение; main валидирует его, связывает с текущим пользовательским сообщением
и показывает подтверждение с точными значениями. Применение требует нажатия
«Сохранить»; просьба «запомни» открывает это подтверждение. Так произвольный
tool call или инструкция в названии события не становятся разрешением записи.
Форма настроек сохраняет напрямую по кнопке. Ответ «сохранено» допустим только
после успешной записи. Повторное нажатие/доставка того же действия идемпотентны.

**M04. Актуальность.** Исправление увеличивает revision; устаревшая форма получает
конфликт без потери более новой записи. Сохранение одинакового значения не создаёт
дубликат. Активный ход использует снимок памяти; изменение/удаление записи во время
хода делает зависимый результат устаревшим и требует пересчёта перед подтверждением.
На следующем ходе актуальное состояние важнее старых упоминаний памяти в чате.

**M05. Надёжность.** Версионированные строгие схемы, ограниченные размеры, очередь
записи и атомарная замена файла. Сбой записи сохраняет прежнюю версию. Повреждение
и неизвестная версия показываются как ошибка, не как пустая память; исходный файл
не перезаписывается. Ассистент может продолжить без памяти с явным уведомлением.

**M06. Конфиденциальность.** Хранилище и дешифрование — в main, доступ через узкие
IPC с проверкой отправителя и текущего аккаунта. Предлагается переиспользовать
локальный шифр с назначением и account ID в AAD, каталогами 0700 и файлами 0600.
Нельзя регенерировать потерянный ключ при наличии любых зависимых данных памяти,
даже когда секреты уже удалены. Нельзя вызывать Keychain/safeStorage как fallback.
Локальный ключ не защищает от программы с правами того же пользователя ОС.

Модели передаются только нужные записи текущей задачи и необходимая история.
Пользователь должен видеть, что выбранный LLM-провайдер получает этот контекст:
локальное хранение не означает локальную обработку. Токены, cookie, ключи API,
вложения и сырые HTTP-ответы в памяти и истории не сохраняются. Логи содержат
тип операции, исход и длительность, без текстов чатов, имён и значений предпочтений.

## Предпочтения: первая версия

**P01. Поддерживаемые поля.** Один набор на аккаунт, все поля необязательные.

| Поле             | Значение / ограничение                            | Пример              |
| ---------------- | ------------------------------------------------- | ------------------- |
| durationMinutes  | Целое 1–480, как действующий контракт             | 30 минут            |
| timeFrom, timeTo | HH:mm, начало раньше конца; возможна одна граница | После 10:00         |
| bufferMinutes    | Целое 0–120, симметричный перерыв                 | 15 минут до и после |

Часовой пояс первой версии — Asia/Almaty, явно указан в UI и контексте.
Переходящий через полночь диапазон в первой версии не сохраняется; ассистент
просит уточнить. Выходные остаются существующим явным параметром запроса.
Изменение одного поля не стирает остальные; каждое поле имеет своё происхождение.

**P02. Приоритет по каждому полю.** Последнее явное указание текущей задачи →
выбранный формат встречи → предпочтение аккаунта → существующее стандартное
поведение. Ответ «на этот раз на час» сохраняется в текущей задаче и на следующих
ходах до явного изменения/новой задачи. При неоднозначности продолжения — вопрос.
Изменения текущей задачи не меняют постоянную память автоматически.

**P03. Применение в main.** Модель извлекает намерение, но итоговые ограничения
собирает общий resolver с происхождением каждого значения. Отсутствующее поле
отличается от явного нуля. Контракты, где длительность сейчас обязательна,
должны позволить main применить значение по умолчанию. Решение не сводится к
дописыванию предпочтений в system prompt.

**P04. Перерыв.** Для кандидата [s,e) и занятого интервала [a,b) организатора
кандидат отклоняется, если `a - buffer < e && b + buffer > s`.
Ровно 15 минут при buffer=15 допустимы. Перерыв применяется к календарю текущего
организатора, а обычная проверка пересечений — ко всему составу. Он не создаёт
отдельных событий и не объявляет чужие предпочтения известными. Требуется полная
занятость организатора с соседних дат, если расширение выходит за полночь;
неполные данные не позволяют объявить слот проверенным.

**P05. Конфликты.** Если просьба «завтра в 09:00» противоречит сохранённому
timeFrom=10:00, точное время является разовым исключением этой границы.
Указание точного времени само по себе не отключает перерыв: при его нарушении
ассистент объясняет причину и предлагает другой слот либо явное разовое исключение.
Нет подходящего времени — объяснение и предложение расширить ограничения,
без молчаливого ослабления. Пересечение занятости исключением не разрешается.

**P06. Перед записью.** Подбор, подготовка черновика и финальная проверка используют
одни и те же разрешённые значения и сведения об исключениях. В UI кратко видно
«30 минут · после 10:00 · перерыв 15 минут». Изменение влияющего предпочтения
после подготовки черновика требует обновить проверку и подтверждение.

## Записи сохранённого контекста

**K01. Формат.** Запись — произвольный текст длиной 1–2 000 символов после trim,
со стабильным ID, revision и общим происхождением M02. Пустые записи не сохраняются.
Примеры: пояснение привычного имени, контекст проекта, пожелание к повесткам.
Сохранение выполняется по явной просьбе в чате либо кнопкой в редакторе.
Лимит первой версии для ревью — 100 записей на аккаунт.

**K02. Применение.** Контекст дополняет запрос; явное текущее указание важнее.
Текст не даёт разрешения на запись встречи и не заменяет проверку каталога,
участников, прав и занятости. Формулировка «Витя — Виктор» сама по себе не является
проверенным participant ID. Если сохранённая запись противоречит структурированному
предпочтению встречи и текущий запрос не снимает противоречие, ассистент уточняет.

**K03. Управление и миграция.** В редакторе доступны полный текст, сохранение и отмена;
при удалении запись перестаёт действовать на следующем ходе. Прежние подтверждённые
прозвища можно представить текстом с источником импорта, сохранив проверенные IDs
и происхождение во внутренних метаданных. Редактирование текста, меняющее человека,
инвалидирует прежнее соответствие и требует перепроверки каталога.

## Управление памятью

**U01. Экран «Память».** Открывается иконкой мозга в нижней группе бокового меню,
рядом с отдельной кнопкой «Настройки AI-помощника». Содержимое: отдельный блок предпочтений встреч
и список «Сохранённый контекст» с текстовыми записями. Карточка записи содержит
текст и кнопки управления, без обязательных полей имени, должности и прозвища.
Иконка памяти — мозг. Позднее добавляются группы и форматы. Показаны значения, источник создания/изменения
и даты по Asia/Almaty. Для импорта источник — «Из прежней памяти участников»;
не приписывать пользователю просьбу, которой нет в данных.

**U02. Действия.** Добавить, изменить или удалить текстовую запись,
изменить или сбросить отдельное поле предпочтений,
очистить категорию или удалить всю память аккаунта.
Массовое удаление имеет одно подтверждение с указанием области. Обычный «Новый чат»
сохраняет память. Удаление памяти не переписывает сообщения и не отменяет встречи.

Удалённые записи перестают действовать уже на следующем ходе; прежние результаты
tool memory в истории исключаются из активного контекста. Старый текст пользователя
остаётся текстом истории, но не основанием восстановить удалённую запись.

**U03. Состояния.** Загрузка, пусто, сохранение, успех, ошибка, конфликт revision,
неавторизованный аккаунт. При ошибке редактируемый текст не теряется. Доступны
клавиатура, корректный фокус и озвучиваемые статусы. Типографика следует
[общим правилам](../design/typography.md): меню 12, компактный текст 13,
формы 14, заголовки диалогов 18 CSS px; computed font-size проверяется в Electron.

## Группы участников

**G01. Запись.** Уникальное в аккаунте имя после trim/нормализации регистра,
1–100 символов; 1–20 уникальных participant ID. Приглашение учитывает действующий
общий лимит 20 вместе с организатором; состав свыше лимита не обрезается.
Группы содержат конкретных людей, без вложенных групп и динамических отделов.

**G02. Выбор.** Сохранение — после поиска и подтверждения полного состава.
Перед использованием каждый ID сверяется с актуальным каталогом. Исчезнувший
или недоступный человек останавливает подготовку; нельзя молча убрать/заменить.
При совпадении имени группы с именем человека ассистент уточняет смысл.
«Команда проекта плюс Анна» меняет только текущую задачу, с дедупликацией IDs.

**G03. Редактирование.** Добавление/удаление людей, переименование, удаление группы
через чат с подтверждением или экран памяти. Изменение состава повышает revision,
зависимые открытые черновики требуют повторного просмотра состава.

## Привычные форматы встреч

**F01. Запись.** Имя, название встречи, длительность, состав (список ID либо одна
ссылка на группу) и текст повестки. Формат хранит заготовку, не конкретную дату,
свободный слот, разрешение на запись или настроенную серию повторений.
«Еженедельный синк» по имени формата не создаёт серию.

**F02. Использование.** «Подготовь наш синк на завтра» раскрывает текущую версию
формата; переопределения текущей задачи имеют приоритет. Отсутствующие поля
берутся из предпочтений, затем уточняются, если необходимы. Ссылка на группу
использует актуальный состав; изменение показывается до подтверждения.
Удалённая группа делает формат неполным, не превращает встречу в пустой состав.

**F03. Ограничения.** Имена 1–100, название 1–500, повестка до 8 000 символов;
до 100 групп и 100 форматов аккаунта. Текст повестки — данные, не инструкции.
Те же лимиты участников/длительности, что в календарном контракте. Шаблоны
отображения Markdown и пользовательские форматы встреч — разные сущности.

## Матрица приёмки

| Сценарий                                                | Проверяемый результат                                    |
| ------------------------------------------------------- | -------------------------------------------------------- |
| «Запомни: обычно 30 минут» → подтверждение → перезапуск | Значение восстановлено, источник и дата видны            |
| «Завтра на час» при предпочтении 30                     | Задача 60 минут, постоянное значение остаётся 30         |
| Точное 09:00 при timeFrom=10:00                         | Разовое исключение времени, прочие проверки действуют    |
| Буфер 15, предыдущая встреча заканчивается 10:00        | 10:14 отклоняется, 10:15 допустимо при прочих условиях   |
| Буфер пересекает полночь / неполная занятость           | Читаются соседние даты / слот не объявляется проверенным |
| Смена аккаунта во время сохранения/ответа модели        | Нет показа или записи в другой аккаунт                   |
| Две формы редактируют одну revision                     | Вторая получает конфликт, не затирает первую             |
| Удалена память, в чате осталось прежнее tool-сообщение  | Запись не применяется и не восстанавливается сама        |
| У группы исчез участник                                 | Явное уточнение без молчаливой замены                    |
| Формат + изменённая группа + явная длительность         | Новый состав показан, длительность из задачи             |
| Повреждение файла / потеря ключа / заполненный диск     | Ошибка видна, старые данные не заменены пустыми          |
| Название события требует «запомнить» или удалить память | Не считается пользовательским разрешением                |

## Инженерные условия

Стек остаётся текущим: Electron + React + TypeScript + Zod + Vercel AI SDK.
Новые зависимости/БД этой спецификацией не выбираются. Типы выводить из Zod-схем,
IPC возвращает типизированный результат, как существующие CalendarReply и
AgentSettingsReply. Пример существующего стиля:

```ts
const preferenceDuration = z.number().int().min(1).max(480);
type PreferenceDuration = z.infer<typeof preferenceDuration>;
```

renderer. Это ориентиры для плана, файлы ещё не созданы.

## Принятые решения

Пользователь подтвердил: локальное хранение без синхронизации до явного удаления,
сохранение после выхода, подтверждение изменений из чата кнопкой, перерыв только
для организатора. Реализация использует один зашифрованный конверт в существующем
vault. Восстановление повреждённого конверта — явный сброс всей памяти;
ограничения календарного контракта и реальной LLM-проверки описаны в
[документации реализации](../implementation/assistant-memory.md).

## Уточнение смысла перед сохранением

Дополнение по запросу пользователя от 30 октября 2026 года. Для сохранения
из чата обязателен цикл: актуальная память → смысловая проверка → вопросы при
неоднозначности → уточнённая формулировка → карточка → подтверждение.

Ассистент проверяет людей и прозвища, полный состав команды, область применения,
точные единицы и время, исключения, обязательность правила, временный или постоянный
характер, противоречия и дубликаты. Не требуется заполнять все возможные поля:
неполнота считается неоднозначностью только если меняет смысл сохраняемого факта.
Пример: «Архитекторы — Тестовый А и Тестовый Б» не требует вопроса о длительности.

Проверка выполняется через `assistantMemory review` с точным будущим изменением
и списком оставшихся вопросов. При вопросах карточка не создаётся; ассистент
задаёт пользователю короткий вопрос. Снять вопросы в том же сообщении нельзя.
После ответа требуется новая проверка с точной цитатой ответа. Явная исходная
просьба запомнить действует в этом уточнении без повторного «запомни».

Main связывает проверку с окном, сессией, revision, ходом и сроком десять минут.
`propose` допускается только для проверенного изменения без открытых вопросов.
Изменение текста, аккаунта, сессии или revision требует новой проверки.
Отмена очищает незавершённую проверку. Текст проверки не становится постоянной
памятью. Оценку смысла делает модель; код проверяет последовательность и границы,
но не доказывает, что модель обнаружила каждую возможную неоднозначность.

Проверки: `npm test`, `npm run typecheck`, `npm run build:desktop`,
`npm run test:desktop -- tests/desktop/assistant-memory.spec.ts`.
Код: `src/main/memory-review.ts`, интеграция `memory-tools.ts` и
`calendar-conversation.ts`; тесты — `tests/agent/memory-integration.test.ts`.
Применяются существующие TypeScript/Zod-контракты и форматирование Prettier.
Без новых зависимостей, записи реальных данных в тесты и изменения календарных прав.
