# Открытие карточки встречи из ассистента

Статус: спецификация для согласования; реализация ещё не выполнена.

## Цель

Команды «Открой встречу …», «Покажи карточку …» и «Открой её» открывают
существующую карточку EventDetails в календаре. Пользователю не нужно искать
встречу в списке и нажимать на неё вручную. Открытие — операция чтения,
не требующая подтверждения и не меняющая встречу.

## Поведение ассистента

1. Новый встроенный навык `meeting-open` описывает выбор встречи и вызов
   инструмента `openMeeting`. Одного текста навыка недостаточно: нужен
   исполняемый переход от инструмента к календарю.
2. Название, дата, время и организатор берутся из запроса и контекста текущего
   диалога. «Открой её» относится к единственной явно обсуждаемой встрече.
   Последний элемент выдачи не считается автоматически выбранной встречей.
3. Если контекст уже содержит однозначную ссылку на событие, повторно спрашивать
   название и период не нужно. Перед открытием данные перечитываются.
4. Если ссылки нет, ассистент ищет встречи в явно указанном или уже обсуждаемом
   периоде. Без периода и подходящего контекста задаёт один вопрос о дате;
   не ограничивает поиск молча текущей неделей. Даты вычисляются в Asia/Almaty.
5. При нескольких совпадениях показывает нумерованные варианты: название,
   дата, время, организатор. До ответа пользователя календарь не переключается.
   Ответ «вторую» разрешается относительно этой выдачи в текущем диалоге.
6. Для повторяющейся встречи выбирается конкретное вхождение с датой,
   включая перенесённые исключения. Один ID серии не определяет карточку.
7. Ноль результатов: сообщить, что в выбранном периоде встреча не найдена,
   предложить уточнить дату или название. Неполная выдача или ошибка чтения
   не выдаётся за отсутствие встреч либо однозначный результат полного поиска.
8. После подтверждённого открытия ответ краткий: «Открыта встреча
   „Планирование“ на 12 ноября, 14:00». Не дублировать описание и участников.
   Если UI не подтвердил открытие, не утверждать, что карточка открыта.

## Поведение календаря

- Открывается штатная EventDetails с обычными правами и действиями пользователя.
  Панель календаря становится видимой; чат и история сохраняются.
- В сетке сохраняется текущий режим день/неделя/месяц, дата переводится на день
  выбранного вхождения. Если оно уже в видимом диапазоне, лишнего перехода нет.
- В списке, содержащем встречу, сохраняются выдача и прокрутка. Если событие
  вне текущего списка, открывается обычный список его месяца без поискового
  фильтра; пользовательские настройки источников и участия не перезаписываются.
- Карточка доступного события открывается даже при скрывающем его фильтре.
  При необходимости кратко сообщается, что событие скрыто текущими фильтрами;
  фильтры не включаются автоматически.
- Повторное открытие той же встречи не создаёт второй диалог. При открытии другой
  встречи карточка заменяется. Несохранённый редактор не закрывается молча:
  применяется штатная защита несохранённых изменений, при её отсутствии переход
  возвращает понятный отказ до завершения редактирования.
- Закрытие карточки оставляет календарь на выбранной дате, без возврата назад.
  Фокус переходит в календарь; Escape работает как у штатной карточки.
- Удалённое событие, потеря доступа, истёкшая сессия, ошибка сети дают понятный
  результат без пустой карточки и без заявления об успехе. Старые данные
  не представляются актуальными. Повтор возможен после восстановления доступа.

## Контракт и границы

Предлагаемый вход инструмента: `{ key: string, date: string }`.
`key` берётся только из проверенных результатов чтения текущего аккаунта;
`date` — местная дата вхождения YYYY-MM-DD. Основной процесс разрешает ключ
в серверный lookup и проверяет доступ заново. Модель не передаёт готовый HTML,
произвольный URL либо содержимое карточки в renderer.

Сообщение открытия связывается с аккаунтом, запросом и конкретным вхождением.
Renderer подтверждает открытие или отказ. Тайм-аут не равен успеху.
После смены аккаунта, отмены запроса или более нового запроса открытия
запоздалое сообщение не открывает карточку. Обработанный requestId не
открывается повторно после перерендера или восстановления истории.

Всегда: сохранять права доступа, валидировать IPC, использовать штатную карточку,
учитывать дату экземпляра серии и текущий аккаунт.
Согласовать отдельно: новые зависимости, изменение серверного API.
Никогда: создавать/изменять/удалять встречи этой командой, подбирать закрытые ID,
исполнять инструкции из названий событий, сохранять реальные данные встреч
или секреты в тестах. Коммиты, публикация и выпуск не входят в эту спецификацию.

## Существующий код и стиль

- `src/agent/content/skills/` — встроенные навыки ассистента.
- `src/agent/calendar-runtime.ts` — доступность навыков и определения tools.
- `src/shared/calendar-tools.ts` — строгие Zod-контракты.
- `src/main/calendar-tools.ts` — проверенные операции текущего аккаунта.
- `src/renderer/DesktopWorkspace.tsx` — дата, режим и выбранное событие.
- `src/renderer/EventDetails.tsx` — существующая карточка.
- `tests/agent/`, `tests/desktop/` — проверки логики и Electron.

Сохранять принятый TypeScript-стиль: именованные типы, строгие схемы,
ранний выход при несовпадении аккаунта, например:

```ts
if (!accountId || next.accountId !== accountId) return;
```

Не менять плотность и оформление карточки; использовать существующие токены
типографики из `docs/design/typography.md`.

## Проверка и критерии приёмки

Unit/integration: доступность навыка и инструмента, строгий контракт, неизвестный
ключ, доступ и аккаунт, повторяющийся экземпляр, ошибки чтения, подтверждение UI,
тайм-аут, повтор и запоздалый ответ. Проверить сценарии уточнения и контекстной
ссылки; тесты tools сами по себе не доказывают качество выбора живой моделью.

Electron: команда с однозначной встречей открывает штатную карточку; переход
между датами, список, фильтры, повторное открытие, закрытие, несохранённый
редактор, смена аккаунта. Использовать синтетические встречи. Проверить computed
font-size и отсутствие ошибок в консоли.

Команды из package.json:

```sh
npm test
npm run typecheck
npm run build:desktop
npm run test:desktop -- tests/desktop/calendar-assistant.spec.ts
```

Каждый запуск пересобранного приложения — с новым изолированным
`--user-data-dir`. До заполнения тестовых данных проверить выход из Small,
пустые credentials, инструкции, предпочтения, контекст, группы и форматы,
нейтральное настроение. Личные профили не используются и не удаляются.

Открытых продуктовых вопросов нет: перечисленные правила являются предложением
для согласования. Тесты и реализация выполняются после согласования спецификации.
