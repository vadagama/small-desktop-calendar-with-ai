# Предложения: серии, аналитика и напоминания

Дата: 28 октября 2026 года. **Предлагается для ревью**, кроме явно отмеченных
пользовательских решений. Основание: [исследование Team Small](../research/team-small-api.md).

## Повторяющиеся встречи

> Клиентская часть реализована в [T13](../implementation/t13-series-scope.md): области
> «Только это вхождение» и «Это и последующие», запись закрыта до подтверждения
> контракта ([протокол проверки](../research/series-contract-probe.md)).

1. Для редактирования по умолчанию выбирать «Только эта встреча»;
   отдельно предложить «Эта и последующие». Полную серию показывать отдельным
   выбором только после подтверждения соответствующего серверного контракта.
2. В карточке подтверждения явно показывать область, дату выбранного вхождения
   и изменение. Прошедшие встречи не менять неявно при редактировании будущих.
3. Для первой версии записи повторений поддержать проверенный набор Team Small:
   еженедельно по выбранным дням с окончанием. Более сложные правила не заменять
   приблизительными; сохранить доступное чтение и объяснить ограничение записи.
4. Сервер остаётся источником вхождений и исключений. При просмотре, подсчётах
   и напоминаниях не вызывать `from-template`. Материализация допускается
   только как часть подтверждённой записи.
5. Хранить идентичность серии, исходную дату/ключ вхождения и актуальные времена;
   перенесённое вхождение не считать второй встречей. Реальный ключ зависит
   от серверной схемы, его нельзя подменять одним новым `starts_at`.
6. После таймаута материализации/редактирования сначала сверять состояние;
   не повторять запись автоматически. При неподтверждённом контракте блокировать
   конкретную операцию, не все действия с обычными встречами.

## Правила аналитики

> Приняты пользователем для первой версии 29 октября 2026 года. Отклонения
> из-за состава данных календаря описаны в [отчёте T12](../implementation/t12-analytics.md).

| Вопрос | Предлагаемое правило |
| --- | --- |
| Какие события входят? | Личные встречи с участием пользователя; declined и отменённые исключаются из основного итога, pending показываются отдельной группой. Неизвестный статус не объявляется принятым. |
| Период | Полуоткрытый интервал `[начало, конец)` в выбранном часовом поясе. Указывать границы и полноту загрузки. |
| Количество | Считать отдельные вхождения, пересекающие период; серию-шаблон отдельно не считать. Дедуплицировать фактическое и виртуальное представление одного вхождения. |
| Длительность | Для встречи на границе периода учитывать только пересечение с периодом. Длительность исходной встречи доступна в деталях. |
| Пересечения | Показывать две величины: сумму длительностей встреч и уникальное занятое время по объединению интервалов. Например, 10:00–11:00 и 10:30–11:30 дают 2 часа встреч и 1,5 часа занятости. |
| Регулярные | Вхождения подтверждённой серии. Похожее название у разовых встреч не означает доказанную повторяемость. |
| Весь день / без времени | Считать отдельно в количестве; не превращать автоматически в 24 часа встреч. |
| Команды | Определять по каталогу участников; встречу нескольких команд относить в «Межкомандные», сохраняя список команд. Общий итог не умножать на число команд. |
| История команд | Если доступен только текущий состав, прямо указывать «по текущей оргструктуре», не выдавать за историческую принадлежность. |
| Темы | Сначала явные категории/теги, затем пользовательские правила; предположение модели помечать как предложенную категорию с возможностью исправления. Нераспознанное — «Без категории». |
| Проверяемость | Из каждой группы доступен список встреч, время и правило включения. При неполных данных результат помечается как частичный. |

Первый отчёт: количество и часы регулярных встреч за месяц; распределение
по темам и командам; отдельно пересечения, pending и отмены. Модель понимает
запрос и объясняет сводку; расчёты выполняет код. Точность классификации
проверяется независимо от точности подсчётов.

## Напоминания и новая встреча

**Подтверждено пользователем:** напоминание по умолчанию за 5 минут,
длительность новой встречи по умолчанию 30 минут. Явный запрос пользователя
имеет приоритет. Значения видны в черновике до подтверждения.

**Предложение:** при пробуждении сначала сверить календарь; если встреча ещё
идёт и напоминание не доставлялось, показать одно уведомление. Для завершённой
или отменённой встречи пропущенное напоминание не доставлять. При нескольких
одновременных встречах уведомлять о каждой, не выбирать за пользователя.
Автозапуск при входе в macOS предложить отдельным выключенным переключателем.

Идентификатор напоминания связывается с аккаунтом и стабильным ключом вхождения;
при переносе меняется время доставки, при отмене напоминание убирается.
После полного выхода и до следующего запуска доставка не обещается.
Focus, системные разрешения и настройки macOS могут влиять на показ.

**Подтверждено пользователем:** ссылку конференции не проверяем сетевым запросом,
комнату не открываем заранее. Уведомление содержит действие «Подключиться»,
открывающее URL; при отсутствии ссылки действие недоступно с объяснением.
Проверка формата и разрешённой схемы URL остаётся частью безопасного открытия
и не является проверкой работоспособности конференции.
