# Свободные слоты — спецификация разработки фронтенда

Редакция 1.11 · обновлено 9 ноября 2026.

Статус: реализовано в React/Electron/Dockview по согласованному прототипу Small. Проверены реальный read-only источник (собственный день/неделя), скрытые Electron E2E и 6/6 запросов реальной модели. Отчёт и границы проверки: [реализация](../implementation/availability-analysis.md). Сборка установочного релиза и публикация в эту задачу не входят.

Заголовок даты использует оформление панели календаря без кнопки «Сегодня». Кнопка «Переговорные» временно скрыта в общей шапке календаря и свободных слотов.

## Зафиксированный результат

- Слева от AI-Ассистента открывается раздел «Свободные слоты»; ручной переход — иконкой календаря с часами в левом меню. Дублирующая верхняя вкладка отсутствует.
- По X — часы 00–24 с горизонтальной прокруткой; по Y — даты, внутри каждой даты строки участников.
- Имена закреплены слева, часовая шкала сверху; одна позиция прокрутки применяется ко всем датам.
- Состав меняется через поиск сотрудников с должностями и выбранные имена с крестиками. Фиксированного набора чекбоксов нет.
- Изменение состава пересчитывает доступность и общие окна; выбор времени передаётся в существующий черновик после повторной проверки.

Рабочая панель получает подтверждённые персональные интервалы через существующие методы Small. Непокрытые участки остаются unknown; данные прототипа применяются только в тестах.

Ручное переключение «Календарь / Свободные слоты» выполняется через левое меню, активный раздел подсвечивается и имеет aria-current. Состав, фильтры и прокрутка свободных окон сохраняются при возвращении. AI-запрос по-прежнему автоматически открывает раздел. Закрытие/смена диалога и аккаунта очищают задачу; уход в календарь отменяет незавершённое открытие черновика. Это уточнение заменяет описанное в первоначальном прототипе переключение верхними вкладками.

## Цель и границы

По запросу AI-Ассистенту пользователь получает отдельную вкладку **«Свободные слоты» слева от чата** и сравнивает доступность одного сотрудника или группы на неделе. По горизонтали расположены часы от 00:00 до 24:00. По вертикали — блоки дат в хронологическом порядке; внутри каждого дня повторяются строки выбранных участников. Горизонтальная прокрутка общая для всех дней, имена участников закреплены слева.

Результат помогает найти окно и передать его в существующий черновик встречи. Анализ сам по себе не создаёт события и не отправляет приглашений. Источник истины — календарные данные и расчёт доступности, AI формулирует запрос и пояснение.

В MVP: одна вкладка анализа, 1–20 человек с организатором, день или неделя, рабочие часы, длительность, выходные, выбор интервала, повторное обновление. История отчётов, экспорт, новые бизнес-правила календаря и редактирование встреч в сетке за рамками MVP.

## Артефакты и запуск

- Интерактивный прототип: [открыть локально](http://127.0.0.1:5173/availability.html?v=horizontal), исходник `prototype/availability.html`.
- Стили и сценарии: `prototype/src/availability-demo.css`, `prototype/src/availability-demo.js`, `prototype/src/availability-people-picker.js`.
- Снимок: `docs/design/availability-prototype.png`.
- Запуск из корня: `npm --prefix prototype run dev`, затем открыть `http://127.0.0.1:5173/availability.html`.
- Проверка оформления: `cd prototype && npx prettier --check availability.html src/availability-demo.css src/availability-demo.js src/availability-people-picker.js`.
- Проверка JS из корня: `node --check prototype/src/availability-demo.js` и `node --check prototype/src/availability-people-picker.js`.

Прототип изолирован от основного приложения. Использует общие CSS-токены через `prototype/src/styles.css`. Вымышленный справочник из шести сотрудников (первоначально выбраны трое), локальный поиск по имени и должности и фиксированная неделя 9–13 ноября 2026; переключение недель меняет синтетические данные. Персональные данные, авторизация и сетевые запросы отсутствуют. Подсказки чата демонстрируют только несколько сценариев, это не интерпретатор естественного языка. Статический HTML служит дизайн-артефактом; включение в production Vite bundle не настроено.

## Сценарий и размещение

1. Пользователь: «Покажи свободные слоты [сотрудников / группы] на следующей неделе, нужна встреча на час».
2. Ассистент разрешает имена в устойчивые `participantId`, группу раскрывает в список. При неоднозначном имени уточняет сотрудника; состав группы показывает до расчёта.
3. После разрешения сотрудников открывается вкладка слева, чат остаётся справа. Появляется загрузка, затем результат с явными составом, периодом, часовым поясом и длительностью. Фокус остаётся в чате; под отдельным аккордеоном показана информационная карточка с кнопкой «Открыть свободные слоты» и текстом ответа.
4. Новый запрос обновляет эту вкладку, не порождает дубликат. Переключение на календарь сохраняет состояние анализа в рамках текущего аккаунта и сессии.
5. Изменение параметров в панели пересчитывает результат без обязательного сообщения AI. Уточнение в чате изменяет те же параметры. Параметры отчёта — единое состояние.
6. Выбор общего окна подготавливает черновик для всех выбранных сотрудников; выбор индивидуального — для сотрудника строки и закреплённого организатора. Состав и время заполнены в открывшейся форме и доступны для редактирования.
7. Перед передачей в черновик доступность проверяется заново. Конфликт отменяет переход и предлагает обновление; создание встречи проходит через существующее подтверждение формы.

Область результата использует существующую систему вкладок рабочего пространства (`src/renderer/DockWorkspace.tsx`, `DesktopWorkspace.tsx`), сохраняет соседние вкладки и раскладку. При запросе из иной раскладки обеспечить анализ слева и видимый чат справа без закрытия контента. В `DockWorkspace.tsx` уже есть реестр компонентов и добавление панелей через `addPanel`. Добавить компонент аналитики и устойчивый ID вкладки, активировать существующую вкладку при повторном открытии. Регистрация панели не должна менять сохранённую раскладку при обычном запуске без запроса аналитики.

## Обязательное соответствие прототипу

Иконка доступности слотов — `CalendarClock` из Lucide (календарь с часами): в навигации 20 px, во вкладке 16 px. Название и доступная подпись — «Свободные слоты». Значок графика `ChartNoAxesCombined` предназначен для отдельной будущей аналитики и здесь не используется.

Визуальный и интерактивный эталон — `prototype/availability.html` с `prototype/src/availability-demo.css`, `prototype/src/availability-demo.js` и `prototype/src/availability-people-picker.js`. Использовать **последний вариант**: горизонтальные часы 00–24, даты вниз, строки участников внутри даты, поиск с удаляемыми именами, существующий стиль Small. Снимок `docs/design/availability-prototype.png` — вспомогательная фиксация; интерактивный прототип и явные требования этой спецификации имеют приоритет.

Приёмка frontend включает сопоставление с прототипом при одинаковых данных, viewport, масштабе и позиции прокрутки: компоновка вкладки/чата, ширина часа и колонки имён, плотность строк, типографика, палитра, состояния picker, выбор интервала и обе прокрутки. Реализовать на текущих React-компонентах и общих токенах; копирование отдельной HTML-оболочки в приложение не требуется. Несовпадения по геометрии, составу действий или расположению панелей исправляются до приёмки. Другая ориентация осей, возврат к чекбоксам или новая стилистика требуют отдельного изменения требований.

## Требования к AI-Ассистенту

### Когда открывать дашборд

Распознавать намерение найти/сравнить доступность, свободные слоты или время встречи по смыслу запроса. Пользователю не нужны слова «аналитика» или «открой страницу». Одинаковый результат для имён, подтверждённых прозвищ, списка участников, сохранённой группы, запроса на день или неделю и продолжений диалога.

| Пример                                                     | Ожидаемое действие                                                                     |
| ---------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| «Найди свободные слоты на этой неделе для Анны и Ивана»    | Разрешить людей, открыть дашборд текущей недели с указанным составом                   |
| «Найди свободное время для встречи с тимлидами во вторник» | Разрешить группу и дату, открыть дашборд с фильтром конкретного вторника               |
| «Когда мы с Анной можем встретиться завтра на полчаса?»    | Текущий пользователь + Анна, завтра, 30 минут, открыть дашборд                         |
| «Покажи занятость этих сотрудников»                        | Использовать явно подтверждённый состав текущей задачи; если его нет — уточнить состав |
| «А теперь в четверг», «Добавь Елену», «Только на 30 минут» | Уточнить параметры текущего анализа, обновить ту же вкладку без дублирования           |
| «Сколько у меня встреч на неделе?»                         | Существующая аналитика встреч, без открытия дашборда свободного времени                |

### Разрешение параметров

1. **Участники:** актуальная память и сохранённые группы/форматы → проверка через существующие `useGroup`/`usePreset` → каталог и `selectParticipants`. Для «тимлидов» использовать сохранённую группу, если она однозначна. Если группы нет, проверить возможность достоверного поиска по роли и полноту пагинации; не считать первую страницу или совпадение слова в имени полным составом. При отсутствии достоверного состава спросить, кого включить, и позволить выбрать сотрудников в picker. Не создавать и не сохранять группу без явного поручения.
2. **Состав анализа:** организатор из авторизованного профиля всегда включён первым и видим в picker и сетке. AI передаёт подтверждённых приглашённых; приложение добавляет организатора без дублей, независимо от includeSelf. Лимит — 20 человек вместе с организатором (до 19 остальных). Самого пользователя не нужно искать в каталоге. При неизвестном ID организатора анализ не подменяется произвольным составом.
3. **Даты:** вычислять по текущему времени и `Asia/Almaty`, не по часовому поясу хоста. «Эта неделя» — неделя с понедельника; «во вторник» — конкретная дата согласно существующему scheduling-контексту. Показывать вычисленную дату. Явный день ограничивает поиск этим днём, а не всей неделей; дашборд отображает один блок даты. Недельный запрос показывает дни выбранной недели с учётом выходных. Для неоднозначной даты уточнить её; прошлые интервалы не предлагать.
4. **Длительность:** явно заданная в сообщении → параметры текущей задачи/исходной встречи → сохранённый формат/предпочтения. Если ничего не задано, открыть анализ с 60 минутами и явно видимым значением; отсутствие длительности не блокирует открытие. Это новое правило для сценария дашборда; обновить прежнюю инструкцию availability, требующую обязательного уточнения неизвестной длительности.
5. **Временное окно:** учитывать явное «с 14 до 18», утро/после обеда по подтверждённым правилам. Полные сутки 00–24 остаются шкалой; интервал поиска обозначается отдельным фильтром/подписью, результаты вне него не выдаются за подходящие. Сохранённые ограничения не отменять молча.
6. **Неоднозначность:** неизвестный/неоднозначный сотрудник, группа или дата требуют короткого уточнения. После ответа продолжить исходную задачу, не просить переписать весь промпт. Не открывать заполненный догадками результат; после разрешения параметров открывать вкладку автоматически. Для пустого состава доступен выбор в панели, но никаких вымышленных строк.

### Надёжное открытие и синхронизация

Нужен узкий read-only инструмент (предлагаемое имя `showAvailabilityAnalysis`), а не просьба модели вывести особый текст. Основной процесс проверяет параметры/аккаунт/полномочия и отправляет renderer типизированное событие открытия с `requestId`, `conversationId`/идентификатором задачи, ревизией и нормализованными параметрами. Название инструмента и IPC-канала окончательно фиксируется задачей контракта; это не существующий API.

После разрешения состава и дат вкладка открывается **до завершения сетевой проверки**, показывает loading, затем ready/empty/partial/error. Успешное открытие не означает подтверждённую доступность. Событие направляется только в окно/аккаунт инициатора, дедуплицируется и не исполняет произвольный URL/HTML/JavaScript. Повторное открытие активирует ту же вкладку слева, чат остаётся видимым. Поздние события отменённой/заменённой задачи не меняют новую панель.

Редактирование участников/параметров в панели обновляет контекст этой аналитической задачи, чтобы «добавь ещё…» не восстанавливало устаревший состав из истории. Новый независимый запрос начинает новую ревизию задачи и заменяет параметры в существующей вкладке. После закрытия вкладки поздний ответ не открывает её заново; новый явный запрос пользователя может открыть снова.

Ответ ассистента короткий: «Открыл свободные слоты на … для …», действие «Открыть свободные слоты» для возврата и выбор окна в панели. Не дублировать расписание Markdown-таблицей, длинным списком или прежними карточками слотов. Ошибки и недоступные данные объяснять честно. Отключённый навык/истёкшая авторизация не обходятся; показать причину и штатное действие восстановления. Поиск/открытие аналитики не создаёт встреч, черновиков или записей памяти.

### Матрица AI-приёмки

Фиксировать время теста: **9 ноября 2026, 10:00 Asia/Almaty**. «На этой неделе» даёт 9–15 ноября (видимые рабочие дни 9–13), «во вторник» — 10 ноября, «завтра» — 10 ноября; интервалы до текущего времени исключены. Дополнительно проверить прошедший день недели, следующую неделю, явный выходной и границу смены даты.

Проверить перефразирования без ключевого слова «слот», сохранённую группу «Тимлиды», отсутствие/несколько одноимённых групп, частичный каталог, двух сотрудников с одинаковым именем, продолжение после уточнения, отмену, повтор инструмента, смену аккаунта, отключённый навык и устаревший ответ. Отдельный регрессионный набор: просмотр встреч, создание/подтверждение/удаление встречи и память. Структурированные схемы и транспорт проверяются детерминированной моделью на границе SDK; смысловое распознавание — дополнительно контрольным прогоном с поддерживаемой LLM в изолированном тестовом контуре. Прохождение одного набора не подменяет другой.

Над фильтрами показан компактный заголовок по последнему образцу: для недели полный диапазон понедельник–воскресенье, например «9 ноября — 15 ноября» (независимо от показа выходных строк); для дня — одна дата. Стрелки переключают на ±7 дней либо ±1 день и синхронно обновляют выделение в мини-календаре. В диапазоне через границу года указан год. Шрифт — общий --font-body 14 CSS px, без увеличения по Retina-снимку.

Шкала отображения: полные сутки 00:00–24:00. Начальные UX-допущения: неделя с понедельника; рабочие часы 09:00–18:00; Asia/Almaty; шаг разметки 30 минут; длительности 30/60/90 минут, начальная — 60. Явные параметры запроса имеют приоритет; рабочие часы и зона из действующих правил календаря имеют приоритет над демонстрационными значениями. Эти допущения не утверждают новые правила сервиса.

## Выбор сотрудников

- Вместо фиксированных чекбоксов — поле «Участники» по паттерну `MeetingPeoplePicker`: выбранные имена внутри поля, крестик удаления, строка поиска и кнопка с лупой. Организатор из текущего профиля всегда закреплён первым, без крестика удаления. Удалять можно только приглашённых; при удалении всех остальных остаётся организатор.
- Все чипы используют общий компонент формы события: высота 32 CSS px, padding 3×8 px, текст 13 px; кнопка удаления 24×24 px. У организатора та же геометрия без кнопки удаления. Длинное имя обрезается многоточием, полное имя доступно в подсказке.
- При фокусе/вводе или нажатии лупы открывается список доступных сотрудников с именем и должностью. В рабочем приложении поиск по непустому тексту использует текущий сервис поиска с задержкой 300 мс; нажатие лупы запускает его сразу. При пустом тексте показывать подсказку «Введите имя сотрудника», не загружать весь корпоративный справочник. В демо при пустом тексте допустима выдача оставшихся синтетических сотрудников. Выбор добавляет сотрудника и очищает строку поиска. Выбранные исключаются из выдачи; дубликаты определяются по ID.
- Крестик удаляет сотрудника. Каждое изменение состава сразу пересчитывает сетку и общие окна, сбрасывает выбранный интервал, сохраняет неделю, длительность и горизонтальную позицию.
- Пустой состав показывает «Выберите хотя бы одного сотрудника для анализа». Поиск остаётся доступен. Отдельные состояния выдачи: «Сотрудники не найдены» и «Все найденные сотрудники уже добавлены».
- Клавиатура: стрелки перемещают активный результат, Enter добавляет его, Escape закрывает выдачу, Tab продолжает обычный переход. Клик вне поля закрывает выдачу. После добавления/удаления фокус возвращается в поиск.
- При достижении 20 участников запретить добавление и показать «Можно выбрать не более 20 сотрудников»; удаление остаётся доступным. При изменении запроса сбрасывать страницу выдачи, поздний ответ предыдущего поиска игнорировать. Загрузка/ошибка поиска не скрывают уже выбранные имена и рассчитанную сетку.
- В production повторно использовать поиск и состояния существующего `MeetingPeoplePicker` (загрузка, ошибка, следующая страница, ограничение 20 сотрудников); демо использует только локальный синтетический справочник. Учётная запись берётся из доверенного состояния приложения. Пользовательский текст не выводится как HTML.
- Поле поиска — `--font-body` 14 px, выбранные имена — `--font-compact` 13 px, выдача и должности — `--font-menu` 12 px. Поле переносит выбранных участников на новые строки при недостатке ширины, выдача не выходит за границы панели.

## Геометрия и визуальные правила

- В desktop-режиме панель анализа занимает оставшуюся ширину, чат около 320–380 CSS px; использовать существующий разделитель и допустимые размеры приложения.
- Закреплённая колонка участников — 184 CSS px, час — 64 CSS px. Ширина временной области — 1536 px для 24 часов. Строка участника — 44 px, заголовок даты — 34 px. Временная область прокручивается горизонтально, её масштаб не сжимается под ширину окна.
- Каждый день содержит заголовок даты и одинаковый состав строк участников. Порядок строк соответствует порядку выбранных имён; добавленный сотрудник появляется последним во всех днях. Удаление сохраняет относительный порядок остальных. Геометрия интервала: left = минуты от полуночи / 60 × 64 px; width = длительность в минутах / 60 × 64 px. Метка 24 означает правую границу суток, а не начало нового интервала этого дня. После 24:00 следующий день начинается отдельным блоком ниже.
- Дизайн наследует Small: белая рабочая поверхность, серо-чёрная навигация, чёрные основные действия и голубые интервалы. Светло-голубой без рамки — индивидуально свободно; нейтральная серая заливка — занято; голубой с контуром — подтверждённое общее окно. Окна показывают границы времени, тултип/фокус — статус и состав. Цвет дополняется текстом; неизвестное состояние имеет штриховку и текст «Нет данных». Вне рабочих часов — отдельная светлая штриховка с подписью в легенде; эти часы не считаются свободными.
- Токены: подписи `--font-caption` 11 px; меню и тултипы `--font-menu` 12 px; сотрудники/детали `--font-compact` 13 px; поля и основной текст `--font-body` 14 px; заголовок `--font-dialog-title` 18 px. Источник — `src/renderer/ui/styles.css`, см. `docs/design/typography.md`.
- Метки часов — `--font-menu` 12 px, названия интервалов — `--font-caption` 11 px. Для короткого окна показать только начало, если полный диапазон не помещается; для ещё более короткого оставить блок без текста. Полный диапазон, статус и состав доступны по фокусу/нажатию. Не увеличивать геометрическую ширину интервала ради текста.
- При первом открытии горизонтальная позиция показывает начало рабочего дня (в демо — начиная с 08:00). Прокруткой доступны 00:00 и 24:00. Общая позиция сохраняется при смене фильтров и недели; вертикальная прокрутка не сбрасывает горизонтальную. При прокрутке вправо имена остаются на месте, при прокрутке вниз шкала часов остаётся сверху.
- Для компактного окна панели складываются вертикально либо переключаются средствами текущего workspace. Не увеличивать минимальную ширину всего окна ради таблицы. Никакого горизонтального скролла документа при 320/768/1024/1440 px; внутренний скролл сетки разрешён.

## Правила времени и расчёта

1. Расчёт использует точные timestamps и IANA timezone; визуальный шаг 30 минут не округляет занятость. Встреча 10:10–10:25 блокирует этот точный интервал.
2. Интервалы полуоткрытые `[start, end)`: окончание в 11:00 допускает начало следующей встречи в 11:00. Перекрывающиеся интервалы объединяются перед расчётом.
3. Свободное время сотрудника — рабочие интервалы за вычетом блокирующей занятости. Общие окна — пересечение доступности всех выбранных сотрудников. Текущий контракт backend задаёт единые 09–18 с обедом 13–14; индивидуальный график не выдумывается.
4. Считать максимальные непрерывные общие окна длиной не меньше запрошенной длительности. Окно 10:00–12:00 при длительности 60 мин — одно окно на два часа, а не три «слота» со сдвигом 30 мин. Сводка подписана «общих окон».
5. Прошедшее время исключать из предложений на текущей неделе. Календарные даты недели определять в зоне анализа, не через системную зону браузера. Смена зоны сдвигает видимые границы согласно timestamps.
6. Обед, выходные, праздники, события на весь день, отменённые/отклонённые события, tentative/free статусы и исключения повторений трактовать по подтверждённым правилам backend. Не выводить новые правила из демо-генератора.
7. Отсутствующие данные, закрытый доступ, ошибка загрузки и пустой список событий — разные состояния. Свободный интервал подтверждён только при полном покрытии времени источником. При неизвестной доступности хотя бы одного сотрудника общее окно не подтверждено.
8. Повторяющиеся встречи учитывать по конкретным экземплярам с переносами/отменами; интерфейс анализа не редактирует серию. Пересечение полуночи обрезать по границам отображаемого дня.

## Выбор времени и черновик

Нажатие на свободный интервал одним действием запускает повторную проверку и открывает существующую форму редактирования черновика «Новое событие». Промежуточной панели выбора и кнопки «В черновик встречи» нет. Участники, дата и время заполнены; название и другие поля пользователь редактирует в форме. Для окна 10:00–12:00 и длительности 60 минут форма получает встречу 10:00–11:00. Начало по умолчанию — начало выбранного окна; произвольный drag-selection и изменение длительности растягиванием не входят в MVP.

Голубое окно с контуром выбирает весь состав анализа, независимо от строки, в которой нажали. Индивидуально свободное окно без контура выбирает сотрудника этой строки и закреплённого организатора. Кликабельность требует подтверждённого пересечения их свободного времени нужной длительности. Личная свобода сотрудника без доступности организатора остаётся видимой, но не является кнопкой; подсказка объясняет причину. Для личного фрагмента начало встречи совпадает с началом нажатого фрагмента, а не исходного широкого интервала: клик 12:00–13:00 открывает 12:00–13:00 при длительности 60 минут. Общий интервал сохраняет выбор всего состава с начала общего окна. В режиме «Общие окна» внутри каждого дня остаётся одна строка «Свободны все»; прочие фильтры и расчёты не меняются. Busy, outside-hours, unknown и окна короче нужной длительности не передаются в черновик.

Во время повторной проверки выбор других интервалов блокируется. Нижняя панель или видимый статус загрузки не появляются, геометрия сетки не меняется; состояние занятости доступно через aria-busy, отмена — через Escape. Ошибка/конфликт не открывает форму, отображает причину и позволяет обновить доступность. Escape, отмена, изменение параметров и закрытие вкладки инвалидируют ожидающий ответ. Повторное нажатие/ответ не создаёт второй черновик. Открытие формы не отправляет приглашения: событие создаётся только штатной кнопкой «Создать».

## Состояния и гонки запросов

| Состояние                 | UI и разрешённые действия                                                                                                          |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| Только организатор        | Организатор закреплён, поиск остальных доступен; анализ собственного календаря                                                     |
| Первичная загрузка        | Каркас сетки, `aria-busy`, подпись проверки; никаких временно свободных клеток                                                     |
| Успех                     | Сетка и рассчитанная сводка; локальный выбор доступен                                                                              |
| Нет общих окон            | Персональная сетка остаётся; сводка 0; предложить меньшую длительность/другую неделю/состав                                        |
| Частичное покрытие        | У конкретного сотрудника/дня штриховка и причина; общая доступность «Не подтверждена»; индивидуально подтверждённые окна доступны  |
| Ошибка                    | Пояснение, «Повторить»; при наличии старого результата явно отметить его как устаревший, запретить передачу в черновик до проверки |
| Истекла сессия            | Существующий сценарий авторизации; очищать данные при смене аккаунта                                                               |
| Обновление                | Показать прежний снимок с меткой обновления, заблокировать передачу выбора; при успехе сбросить выбор                              |
| Конфликт перед черновиком | «Это время уже занято», обновить сетку, оставить пользователя в анализе                                                            |

Смена состава, недели, зоны, длительности или аккаунта инвалидирует выбор и предыдущий запрос. Применяется только ответ последней ревизии параметров; поздний ответ не меняет актуальный экран. При удалении вкладки отписаться от результатов. Повторный `requestId` не открывает вторую вкладку. Истечение актуальности: предложенный предел 60 секунд до повторной проверки при действии, окончательно согласовать с политикой существующего кэша.

## Интеграция и контракт данных

Авторитетные runtime-схемы и типы: `src/shared/availability-analysis.ts`. Используются следующие структуры:

```ts
interface AvailabilityOpening {
  kind: "availability-analysis";
  query: AnalysisQuery;
  people: CalendarPerson[];
}
interface AnalysisQuery {
  accountId: string;
  participantIds: string[]; // уникальные, 1–20
  date: string; // YYYY-MM-DD в Asia/Almaty
  period: "day" | "week";
  durationMinutes: number; // 1–480, default 60
  includeWeekends: boolean;
  bufferMinutes: number;
  organizerParticipantId?: string;
  timeFrom: string; // default 09:00
  timeTo: string; // default 18:00, позже начала
}
interface AvailabilityAnalysis {
  query: AnalysisQuery;
  fetchedAt: string;
  days: Array<{
    date: string;
    participants: Array<{
      participantId: string;
      issue?: string;
      intervals: Array<{
        start: string;
        end: string;
        state: "free" | "busy" | "outside-hours" | "unknown";
      }>;
    }>;
    commonWindows: Array<{ start: string; end: string }>;
  }>;
}
```

`showAvailabilityAnalysis` не принимает accountId, buffer и organizerId от модели: их разрешает main. До загрузки отправляется `calendar:availability-open`, чтение идёт через `calendar:availability-analysis`, изменения UI — через `calendar:availability-context`. IPC проверяет владельца/аккаунт; requestId/callId остаются в main, ревизии и отмена реализованы локальными поколениями запросов, не дублируются в JSON результата. Зона фиксирована Asia/Almaty.

Общие `SlotsResult` не используются для догадок о персональной занятости. Адаптер читает полную персональную занятость busy-intervals за каждый день и вычитает её из подтверждённых рабочих интервалов backend (09–18, обед 13–14). Отсутствующая запись сотрудника означает unknown. Список стартов find-slots не является покрытием времени и в сетке не используется. Контракт, права, лимиты и фактическая read-only проверка описаны в [availability-source.md](../implementation/availability-source.md). Названия и описания чужих событий для сетки не запрашиваются.

### Состояние и ответственность frontend

Единое состояние панели содержит: текущий `accountId`, идентификатор AI-задачи/диалога, упорядоченные `participantIds`, режим периода `day | week`, нормализованные даты начала/окончания периода, отображаемую неделю, `timezone`, `durationMinutes`, `includeWeekends`, явное временное окно при его наличии, режим `participants | common`, номер ревизии запроса и выбранный интервал. Отдельно хранятся последний успешный снимок, состояние загрузки/ошибки и позиции прокрутки. Текст поиска и страница выдачи относятся к picker, не меняют состав до выбора результата.

Ответ применяется только к совпадающим аккаунту, параметрам и ревизии. При смене аккаунта очищаются снимок, выбранные сотрудники, выдача поиска и выбор времени. Смена режима меняет только отображение; состав, снимок и горизонтальная позиция сохраняются. Изменение состава/периода/длительности/выходных инвалидирует выбор; новая доступность не показывается до получения подтверждённых данных. Инвалидации календаря должны помечать затронутый снимок устаревшим, а не оставлять его подтверждённым.

| Компонент/модуль            | Ответственность                                                                       |
| --------------------------- | ------------------------------------------------------------------------------------- |
| `AvailabilityAnalysisPanel` | Состояние, загрузка, ошибки, ревизии запросов, связь с аккаунтом и workspace          |
| `AvailabilityFilters`       | Неделя, длительность, выходные, режим; контролируемые параметры                       |
| `MeetingPeoplePicker`       | Повторно используемый поиск/удаление, разрешённый состав с закреплённым организатором |
| `AvailabilitySummary`       | Число максимальных общих окон, их длительность, ближайшее окно                        |
| `AvailabilityWeekGrid`      | Общая горизонтальная шкала, группы дат, строки участников, закрепление и прокрутка    |
| `AvailabilitySelection`     | Детали окна/встречи, состав, повторная проверка, переход в черновик                   |
| Адаптер доступности         | Проверка/нормализация подтверждённых интервалов; данные отдельно от координат и JSX   |

Размещать рабочие компоненты в `src/renderer/`, общие типы — в `src/shared/`; функции преобразования интервалов сделать чистыми. Синтетический адаптер изолировать от рабочего источника. Переносить из HTML-прототипа поведение и геометрию, а реализацию включать в текущий React/TypeScript и существующую систему вкладок. Имена компонентов PascalCase, явные типы, токены общего CSS. Новая UI-зависимость не требуется.

Событие открытия от ассистента должно нести структурированные параметры/идентификатор запроса, а не HTML или распарсенную Markdown-таблицу. Дашборд — основной результат любого запроса подбора свободного времени, в том числе «найди время для встречи» без слова «аналитика». Для таких запросов прежние карточки `findSlots` не должны оставаться единственным ответом или дублировать дашборд. Прочие сценарии ассистента сохраняются.

## Доступность и производительность

- Часы, даты и сотрудники имеют семантические заголовки. Каждое выбираемое непрерывное окно доступно с клавиатуры, имеет имя: сотрудник/весь состав, дата, начало, конец, статус, зона.
- В рабочем компоненте не превращать каждую получасовую клетку в отдельную Tab-остановку: один фокус на окно либо roving tabindex со стрелками; Enter выбирает, Escape снимает выбор. Детали доступны по фокусу и нажатию, не только hover.
- Короткие интервалы имеют расширенную область взаимодействия без искажения их геометрии; все основные кнопки не меньше 24×24 CSS px. Прототип показывает непрерывные интервалы вместо отдельных получасовых кнопок. В демо минимальный получасовой интервал имеет ширину 32 px и высоту 34 px; короткие подписи сокращаются до времени начала, полный диапазон доступен в описании и деталях выбора.
- Выбор остаётся видимым после прокрутки: закрепить панель деталей внизу области анализа. Загрузка/ошибки объявляются через live region без повторного чтения всей сетки.
- Контраст текста не меньше 4.5:1; фокус различим; статусы не кодируются одним цветом. Сохранять масштабирование приложения.
- На 20 сотрудниках и 7 днях фильтр/режим реагирует без заметной блокировки; ориентир p95 локального обновления ≤200 мс на согласованном тестовом устройстве. При необходимости виртуализировать блоки сотрудников, сохраняя заголовки и фокус. Сетевой SLA измеряется отдельно после выбора источника.

## Критерии приёмки функционала

1. Запрос аналитики для одного/нескольких разрешённых сотрудников открывает ровно одну вкладку слева; чат виден, календарь остаётся доступен.
2. По X идут часы 00–24; по Y — даты, а внутри каждой даты строки участников. Горизонтальная прокрутка синхронна для всех дней; имена закреплены слева и шкала часов сверху. Интервалы 10:10 и 10:25 имеют правильные горизонтальные координаты.
3. Состав и зона явно видны. Новый запрос и фильтры панели приводят к одному и тому же состоянию; выбор сбрасывается при изменении параметров.
4. Общие окна — точное пересечение подтверждённой доступности всего состава. Для 10:00–12:00 при длительности 60 мин сводка показывает 1 окно / 2 ч.
5. Unknown/denied не становятся свободным временем. При частичном покрытии нельзя выбрать неподтверждённое общее окно.
6. Выбор голубого окна с контуром включает весь состав; индивидуального — конкретного сотрудника. Детали явно показывают состав и время будущей встречи.
7. Перед черновиком выполнена повторная проверка; конфликт не создаёт встречу. Повторное нажатие не создаёт дубликат черновика.
8. Ошибка, загрузка, пустой состав, отсутствие общих окон, истёкшая сессия и поздние ответы проверены; данные разных аккаунтов не смешиваются.
9. Сетка работает при прокрутке, длинных именах, 1/20 сотрудниках и 5/7 днях, без горизонтального скролла всего окна. В одном столбце времени все строки соответствуют одной минуте; на концах доступны 00 и 24.
10. Поиск показывает имя/должность; выбор добавляет строку во все дни и пересчитывает общие окна. Уже выбранный ID повторно не добавляется. Удаление крестиком убирает все строки сотрудника и сбрасывает выбор интервала.
11. Пустой состав, пустой результат поиска, уже добавленные результаты, загрузка, ошибка и лимит 20 участников имеют разные состояния. После удаления последнего сотрудника можно добавить нового без перезагрузки.
12. Стрелки/Enter выбирают сотрудника, Escape закрывает выдачу, клик снаружи закрывает её. Удаление и добавление возвращают фокус в поле; клавиатурный выбор свободного окна и Escape работают отдельно от picker.
13. Неделя, длительность и горизонтальная позиция сохраняются при изменении состава; старый ответ поиска/доступности не возвращает удалённого сотрудника. Смена аккаунта не показывает данные предыдущего.
14. Промпты поиска времени автоматически открывают дашборд: имена на текущую неделю, «с тимлидами во вторник», «мы с Анной завтра на полчаса». День/группа/длительность соответствуют разобранному запросу; при неоднозначности после уточнения анализ открывается без повторного полного промпта.
15. Параметры панели и контекст AI-задачи синхронизированы. Повторное событие не дублирует вкладку, позднее/отменённое не восстанавливает закрытую панель и не смешивает аккаунты.
16. Визуальное сопоставление с последним прототипом выполнено при одинаковых данных и viewport; обязательная геометрия, палитра, поиск участников и взаимодействия сохранены.
17. В Electron проверены computed font-size по общим токенам, клавиатура и фокус. E2E запускаются скрыто, с отдельным тестовым профилем.

## Проверки при разработке

| Уровень          | Обязательные случаи                                                                                                                    |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| Чистые функции   | Пересечения, соседние границы, интервалы 10:10–10:25, недостаточная длительность, обрезка по дню, unknown и outside-hours              |
| Состояние/bridge | Поздние ответы, повторный requestId, смена аккаунта, инвалидация календаря, ошибка повторной проверки перед черновиком                 |
| Picker           | Добавить/удалить/добавить снова, одинаковые имена с разными ID, дубликат ID, пустой поиск, ошибка/пагинация, лимит 20, клавиатура      |
| UI в Electron    | 00/24, обе прокрутки, закреплённые имена/шкала, 1/20 участников, 5/7 дней, длинные имена, выбор и состав черновика, computed font-size |

Unit-тесты рабочей логики размещать в `tests/agent/` с текущим Node test runner; Electron-сценарии — в `tests/desktop/`. Фикстуры исключительно синтетические. Выполнять из корня:

```sh
npm run typecheck
npm test
npm run test:desktop -- tests/desktop/availability-analysis.spec.ts
```

`tests/desktop/availability-analysis.spec.ts` — предполагаемый новый файл, его предстоит создать; последняя команда применима после его добавления. Браузерные проверки прототипа — Playwright headless; Electron-тесты — скрытый запуск всех окон и отдельный профиль согласно `AGENTS.md`. Проверки production-интеграции не заменяются успешными демо-сценариями.

Всегда: общие токены, точные интервалы, существующие права и черновик, изоляция аккаунтов. Согласовать отдельно: новый backend endpoint/изменение схем API, новые зависимости, изменение рабочих правил календаря. Никогда: генерировать фиктивную занятость в рабочем приложении, открывать credentials удалённому контенту, создавать встречу только по клику на сетку.

## Выполненная проверка и ограничения

Прототип остаётся изолированным дизайн-артефактом. Рабочий интерфейс проверен отдельно в скрытом Electron с чистым профилем: [E2E](../implementation/availability-e2e.md), [визуальная сверка](../implementation/availability-visual.md), [реальная LLM](../implementation/availability-ai-eval.md), [источник](../implementation/availability-source.md).

Персональная read-only интеграция подтверждена для собственного календаря. Доступ к другим сотрудникам регулирует сервер: denied и unknown не подменяются свободой. Полный состав произвольного подразделения не выводится из первой страницы каталога; нужны сохранённая группа с перепроверкой ID либо уточнение. Внешние LLM могут интерпретировать промпты иначе; контрольный набор не заменяет проверку нового провайдера. Черновик всегда проходит повторную проверку фактического состава, включая организатора.
