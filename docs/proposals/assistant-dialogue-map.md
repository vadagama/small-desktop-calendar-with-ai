Статус: границы согласованы; пользователь поручил реализацию 2026-10-29.
Устройство и проверка реализации: ../implementation/assistant-dialogue.md.

## Результат исследования

- `src/renderer/transport.ts` отправляет только последнее сообщение пользователя.
- `src/main/calendar-tools.ts` допускает участников только из буквального
  `Участники: [ID1, ID2]` в текущем сообщении. Правка Markdown это не исправит.
- `src/agent/content/system.md` требует ISO-дату, запрещает выходные и сообщает
  об отсутствии истории. Текущая дата в runtime не добавляется.
- `src/shared/calendar-tools.ts` не предоставляет агенту границы времени суток
  и настройку выходных при подборе.
- `src/renderer/MessageList.tsx` выводит текст через span без Markdown;
  неизвестный инструмент, включая loadSkill, попадает в оформление сложения.
- `src/renderer/CalendarToolResult.tsx` снова требует от пользователя ID и дату.
- Vercel AI SDK и ToolLoopAgent уже используются. Установленный SDK принимает
  messages; оснований менять движок по этим дефектам не найдено.

Локальный Codex-скилл `small-team-meeting-create` уже описывает относительные
даты, интервалы «после обеда», поиск по каталогу, уточнение кандидатов, выбор
слота и финальное подтверждение. Переносить следует эти сценарии, а не его
зависимые от Codex транспорт, доступ к файлам и персональные сведения.

## Карта возможностей

| ID | Ответственность | Зависимости |
|---|---|---|
| dialogue | История текущего чата, дата/часовой пояс, состояние уточнений и проверенные результаты инструментов; отмена и изоляция аккаунтов | — |
| calendar-skills | Каталог скиллов и загрузка references; разрешение свободных имён, дат и диапазонов; выбор участников и слотов; подготовка черновика | dialogue |
| participant-memory | Локальные подтверждённые соответствия имён и прозвищ, частота выбора участников; исправление и забывание | dialogue, calendar-skills |
| response-templates | Markdown-ответы, карточки кандидатов, слотов и черновика, стартовые подсказки; отдельные файловые шаблоны | dialogue, calendar-skills |
| mood | Стиль общения: нейтральный, строгий, молодёжный, альфа, технарь; отдельные описания и выбор в настройках агента | dialogue |

Порядок: dialogue → calendar-skills → participant-memory → response-templates → mood.

## Предлагаемые решения для последующих спецификаций

- Пользователь пишет обычным языком. ID и ISO остаются внутренним контрактом
  инструментов; источник ID — каталог и подтверждённое состояние диалога.
- «Завтра» вычисляется относительно текущего времени Asia/Almaty на каждом ходе.
  «После обеда» использует сохранённые часы либо явно предложенный диапазон
  14:00–18:00. Длительность уточняется, если ранее не согласована.
- При нескольких Олегах показать кандидатов с должностями, спросить одного
  уточнения и принять ответ «второй», фамилию или нажатие на карточку.
- Память помогает ранжировать кандидатов и использовать подтверждённые прозвища;
  сама частота встреч не разрешает молча выбрать человека при неоднозначности.
- Память хранится вне репозитория, отдельно для аккаунта; содержит минимум
  сведений об участниках. Пользователь может сказать «запомни» и «забудь».
  Актуальность записи проверяется через каталог перед использованием.
- Слот выбирается ответом или кнопкой. Проверка занятости охватывает весь состав.
  Явно запрошенные выходные поддерживаются инструментом и инструкциями.
- Создание остаётся отдельным действием из итоговой карточки с повторной
  проверкой занятости и защитой от повторной отправки.
- Шаблоны хранятся отдельно от скиллов: поставляемые файлы плюс локальные
  переопределения вне приложения. Редактора шаблонов в UI нет. Предпочтение:
  Markdown для текста, декларативные шаблоны карточек с проверяемыми полями
  и действиями. Произвольный исполняемый HTML модели не нужен.
- Карточки используют реальные результаты инструментов. Демо-имена и статусы
  со скриншотов не переносятся; оформление следует компактным токенам проекта.
- Mood влияет на лексику и краткость. «Альфа» — уверенный прямой стиль без
  давления, унижения и сокрытия неопределённости. По умолчанию — нейтральный.
- Нужны проверки многоходового сценария, смены аккаунта, памяти после перезапуска,
  неоднозначных имён, границы суток, выходных, устаревших слотов, шаблонов и Mood.
  Детерминированные тесты инструментов дополняются проверкой реального LLM.
