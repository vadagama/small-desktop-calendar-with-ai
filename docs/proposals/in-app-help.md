# Встроенная документация Small

## Цель и границы
Помочь сотруднику выполнить задачу без изучения устройства приложения: найти встречу,
подобрать время, разобраться в загрузке и настроить ассистента.
Результат — самостоятельный раздел в desktop-клиенте и его демонстрация в прототипе.
Общий компонент руководства используется в обоих интерфейсах, тексты описывают
возможности соответствующего окружения.

## Требования
1. Постоянный вход «Помощь» в навигации. Помощь открывается как самостоятельный раздел в основной рабочей области.
   Календарная боковая панель заменяется оглавлением гайда. Иконка вопроса отмечает
   активный раздел; модального окна и затемнения нет. Календарь и диалог сохраняются.
   Темы сгруппированы по этапам обучения, доступны переходы «Назад» и «Далее».
   Возврат из интерактивного сценария сохраняет выбранную тему.
2. Поиск по заголовкам, содержимому и примерам без учёта регистра. Понятное пустое
   состояние и сброс поиска. Разделы: начало работы, календарь, подбор времени,
   поиск событий, аналитика, память и настройки ассистента.
3. Статья: задача пользователя, ожидаемый результат, 2–4 шага, скриншот с подписью,
   пример запроса или переход в нужное место, ограничения сценария.
4. Скриншоты сняты с текущего прототипа на вымышленных данных; подпись обозначает
   демонстрацию. Изображения имеют alt-текст и увеличиваются без перехода наружу.
5. «Подставить запрос» открывает ассистента, добавляет текст к существующему черновику,
   ставит фокус в поле. Сообщение не отправляется автоматически. Повторное открытие
   помощи не сбрасывает переписку. Пользователь редактирует и отправляет запрос сам.
6. «Открыть …» выполняет только локальную навигацию: календарь, аналитика, память,
   настройки AI. Создание/изменение/удаление событий из документации напрямую
   не выполняется; используются обычные формы и подтверждения продукта.
7. Явно различать возможности демо и desktop-клиента. В прототипе ответы сценарные,
   приглашения не отправляются, данные встреч сбрасываются при обновлении страницы.
   Не обещать поддержку произвольных запросов, повторений или часовых поясов в демо.
8. В эксплуатационной документации объяснять выбор часового пояса, различие одного
   повторения и серии, права организатора и проверку результата перед повтором операции.
   Здесь эти случаи описываются как ограничения демонстрации, а не готовые действия.
9. Визуальный язык: существующая нейтральная палитра, компактная плотность,
   --font-menu 12px, --font-compact 13px, --font-body 14px, --font-dialog-title 18px.
   Узкое окно: список тем над статьёй, без горизонтального скролла.
10. Документация и изображения доступны локально без сети. При изменении интерфейса
    обновлять соответствующие шаги, изображения и проверку переходов в одной задаче.

## Реализация и проверка
- React/TypeScript, существующие токены интерфейса и lucide-react; без новых зависимостей.
- Desktop-статьи: src/renderer/help-content.ts; демонстрационные: prototype/src/help-content.ts.
- Общий интерфейс: src/renderer/ui/Help.tsx, help.css, help-types.ts.
- Интеграция: App.tsx и Assistant.tsx; изображения: prototype/public/help/.
- Только перечисленные типизированные действия; текст статей не исполняется как код.
- Сохранять существующие пользовательские изменения. Не менять backend и профили.
- Стиль: `onAction("memory")`, явные props и локальное состояние поиска/статьи.
- Порядок: требования → тест поведения → статьи и навигация → скриншоты → проверки.
- Команды из prototype/: `npm run test:ui -- tests/help.spec.ts`, `npm test`,
  `npm run build`, `npm run test:ui`.
- Приёмка: поиск/пустое состояние; все переходы; загрузка скриншотов; редактируемый
  запрос без отправки; сохранность черновика; навигация между разделами и клавиатура; узкое окно;
  отсутствие ошибок страницы. Скриншоты общей страницы и статьи для просмотра.
- Desktop-проверка: `npm run typecheck`, `npm test`, `npm run build:desktop`,
  `npm run test:desktop`. Руководство доступно без Small и LLM; встроенные
  изображения загружаются через локальный протокол. Подстановка не отправляет
  запрос и не обрезает черновик при превышении лимита 2000 символов.
- Desktop-изображения: resources/renderer/help/. Для обновления основных экранов:
  `node --import tsx scripts/capture-help.mjs` после сборки. Используется временный
  профиль и синтетический Small API; производственная сеть заблокирована.
- После упаковки запускается отдельный новый профиль с пустыми настройками и памятью.
