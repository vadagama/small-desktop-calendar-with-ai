# ADR-005: сессия Small без сохранения пароля и Keychain

## Статус и дата

**Принято**, 30 октября 2026 года, по явному решению пользователя.
Заменяет предложение [ADR-004](004-secret-storage.md).

## Решаемый вопрос

Пользователю подходит повторный ввод пароля после окончания серверной сессии.
Нужно исключить сохранённый пароль и обращения к Keychain, сохранив удобство входа.
Срок refresh-cookie около 30 дней не доказывает срок серверной сессии.

## Решение и его граница

- Сохранять cookie сессии и логин. Обновлять access token через refresh без пароля.
- Пароль использовать только для явно инициированного входа; не записывать на диск,
  не передавать ассистенту и не использовать для фонового повторного login.
- При отказе refresh удалить сессию, сохранить логин и явно предложить ввод пароля.
  При сетевых ошибках предлагать повторную проверку, сохраняя сессию.
- Сохранять логин также после явного выхода и ошибочного входа. Поле остаётся
  редактируемым для смены аккаунта. Пароль в форме очищается после отправки/закрытия.
- Автоматически переписать запись версии 2 без пароля при первом чтении, до сети.
  Не создавать резервную копию с паролем. При невозможности записи сообщить ошибку.
- Не обращаться к Keychain для импорта или удаления старых записей.

## Последствия и альтернативы

Утечка текущего профиля больше не раскрывает сохранённый пароль Small, но cookie
сессии и ключи моделей остаются секретами в local vault с прежней границей защиты.
Это не полное устранение риска копирования профиля. Старые резервные копии/SSD и
неиспользуемые записи Keychain автоматически не стираются.

Варианты Keychain с постоянной подписью и мастер-пароль отложены в пользу выбранного
сценария. Системные диалоги авторизации приложению для этого режима не нужны.
Отдельно остаются требования подписи и notarization для корпоративного выпуска.

## Проверка

Unit: login/refresh/logout, миграция до сети, отсутствие пароля, offline,
отказ refresh, другой аккаунт, параллельность. Electron: восстановление сессии,
предзаполненный логин после рестарта/выхода, явное сообщение о пароле, пустое поле,
сохранение черновика встречи, прежняя типографика и отсутствие ошибок renderer.
