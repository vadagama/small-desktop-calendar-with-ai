# Целевая архитектура Go и Wails

Пользователь выбрал Go для бизнес-логики, Wails для оболочки, React/TypeScript и shadcn для компонентов с сохранением существующей дизайн-системы и Dockview Community. Документ предлагает способ перехода для принятого направления. Текущий продукт описан в [ADR-002](002-desktop-stack.md).

Для первого среза предлагается стабильный Wails v3.0.0. На macOS он использует WKWebView, а его сервисы дают типизированные вызовы и события для React. Сборка требует Go 1.26 или новее. На машине обнаружен Go 1.25.5. [Официальный релиз](https://github.com/wailsapp/wails/releases/tag/v3.0.0) · [Документация WKWebView](https://wails.io/features/windows/options/)

Go-сервисы с бизнес-правилами тестируются без Wails. Тонкий адаптер Wails передаёт только конкретные операции и события. TypeScript-адаптер сохраняет используемый UI контракт `smallDesktop`. Сессия и секреты остаются вне renderer. Для кеша и данных профиля сохраняется файловое хранение с текущими гарантиями шифрования и изоляции аккаунтов. SQLite можно рассмотреть по отдельному решению при подтверждённой потребности.

## Подключение ассистента

Сохраняем [действующее решение о Vercel AI SDK](003-agent-harness.md), закреплённые версии SDK, TypeScript-рантайм, React `useChat`, промпты, выбор моделей, схемы инструментов и поведение чата. Календарные инструменты сохраняют свой контракт и вызывают соответствующие сервисы Go.

Предварительная сборка Wails использует локальный процесс Node.js под управлением Go. Он запускает общий рабочий модуль ассистента через `worker_threads`. Связь с React проходит через Wails с тем же форматом потока, отмены и ошибок. Ключ модели хранится в локальном зашифрованном хранилище и передаётся рабочему модулю на время запроса. Go проверяет сессию и принимает календарные записи после подтверждения в интерфейсе.

В предварительный DMG для macOS arm64 вошёл Node.js 22.23.2. Образ занимает 48,2 МБ. Подробности сборки, проверок и оставшихся работ записаны в [результатах этапа](../specs/SPEC-0003-wails-assistant/verification.md).

### Переход на Bun для Wails

Для Wails выбираем стабильный Bun как среду запуска отдельного процесса ассистента. Go запускает вложенный в приложение бинарник Bun с `--no-env-file` и существующим `assistant-host.mjs`. Такой переход сохраняет Vercel AI SDK, TypeScript-логику и протокол между ассистентом, Go и React. Версию Bun фиксируем при сборке. Эксперимент с Bun 1.4.5 выполнен в отдельной копии проекта.

Основное основание для перехода — размер сборки. На macOS arm64 подписанный локальный `.app` с Bun 1.4.5 занимает 103,0 МБ против 126,6 МБ с Node.js 22.23.2. Экономия составляет 23,6 МБ, или 19%. Размер DMG с Bun пока не измерен. Сборка с `bun compile --trim` весила 79,5 МБ и требовала канареечного Bun 1.4.6 с экспериментальным компилятором. Для выпуска выбираем обычный запуск на стабильном Bun. [Документация Bun о `--trim`](https://bun.com/docs/compiler/size)

На Apple M4 Pro с одинаковым JS-бандлом и локальными заглушками календаря и модели получены следующие медианы. На каждую комбинацию среды и задержки выполнено 30 измерений с чередованием порядка запуска.

| Метрика | Node.js | Bun |
| --- | ---: | ---: |
| Холодный старт процесса ассистента до первого ответа хоста | 52,1 мс | 33,1 мс |
| Первый текст после вызова инструмента календаря | 81,6 мс | 53,2 мс |
| То же при добавлении 40 мс на каждое обращение к модели | 165,9 мс | 136,8 мс |
| Первый текст повторного запроса | 59,2 мс | 43,3 мс |

Выигрыш в локальных сценариях составляет десятки миллисекунд. Задержку реального провайдера и отрисовку в WKWebView в этом замере не измеряли.

С Bun прошли все 10 тестов Wails, включая скрытые проверки WKWebView, потоковый ответ, инструменты календаря и сохранение памяти. При отдельном запуске TypeScript-набора под Bun прошли 578 из 580 тестов. Два теста TypeScript-кеша Electron завершились по тайм-ауту при ожидании перехвата файловых операций. Кеш Wails реализован на Go. Его сценарий чтения после перезапуска без сети прошёл. Перед выпуском проверяем в подписанном `.app` потоковый ответ с реальным LLM-провайдером, вызов инструмента, отмену запроса и успешный повторный запрос. Совместимость перепроверяем при обновлении Bun. [Совместимость Bun с Node.js](https://bun.com/docs/runtime/nodejs-compat)

## Порядок перехода

Поэтапный переход позволяет сравнивать каждый перенесённый сценарий с Electron и отдельно выявлять WebKit-расхождения. Первый срез использует текущие компоненты и стили как эталон. Затем внедряем shadcn с существующими токенами цветов, типографикой и плотностью. Dockview Community сохраняет компоновку, перетаскивание и изменение размеров панелей. Каждый заменённый компонент проходит сравнение внешнего вида, фокуса и поведения.
