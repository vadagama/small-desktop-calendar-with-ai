# ADR-001: Electron и календарный харнес на TypeScript поверх AI SDK

## Статус и дата

**Предложено пользователю**, 28 октября 2026 года. Выбор не считается принятым
до ревью ADR. Документ предлагает решение; приложение и зависимости не созданы.

## Контекст

Нужен macOS-клиент с переставляемыми и изменяемыми по размеру виджетами,
нативными уведомлениями и доступом к Keychain. Ассистент работает через
корпоративный Small vLLM либо персональный OpenAI-совместимый endpoint.
Нужны управляемые календарные инструменты, подтверждение записей, сохранение
черновиков и проверяемая аналитика. Не требуется агент с произвольным shell
или долгоживущая совместная агентная сессия нескольких пользователей.

Текущий Mac проверен локально: macOS **15.1**, build **24B2083**, **arm64**.
Это первая целевая комбинация, не обещание поддержки всех macOS/Intel.
На момент исследования [Electron публикует Apple Silicon binaries и поддерживает
macOS Ventura и новее](https://github.com/electron/electron/blob/main/README.md#platform-support).
Совместимость конкретной сборки приложения всё равно требует smoke-проверки.

## Рекомендуемое решение

| Часть | Выбор и причина |
| --- | --- |
| Оболочка | Electron: встроенный Node.js позволяет запускать TypeScript-харнес без отдельной установки runtime у сотрудников. |
| UI | Локально собранный React/TypeScript, календарный UI на основе доступного исходного frontend после проверки доступа и лицензии. При невозможности переиспользования потребуется отдельное решение; не копировать bundle как исходник. |
| Компоновка | Dockview Community для перемещения и изменения размеров панелей; хранить локально компоновку, view и выбранные календари. |
| Харнес | Небольшая прикладная обвязка над Vercel AI SDK `ToolLoopAgent`, с реестром узких календарных инструментов и контролируемыми состояниями операции. |
| Модели | Прямое соединение с выбранным endpoint через OpenAI-compatible provider; `baseURL`, `modelId`, ссылка на запись Keychain и настройки возможностей. |
| Секреты | Прямой доступ к macOS Keychain через отдельный адаптер; кандидат `@napi-rs/keyring`, проверяемый в подписанной arm64-сборке. |
| Состояние | Локально сохранять настройки, черновики, подтверждения и журнал исходов операций; формат и срок хранения уточнить при реализации. Секреты в Keychain, не в журнале. |
| Сервер | Новый сервер для v1 не добавлять: существующие Team Small и выбранный LLM endpoint. Пересмотреть, если корпоративная авторизация требует серверного обмена. |

Это оценка простоты для данного продукта, а не результат сравнительного
бенчмарка скорости. [AI SDK поддерживает TypeScript и Node.js](https://ai-sdk.dev/docs/introduction);
[ToolLoopAgent](https://ai-sdk.dev/docs/agents/building-agents) предоставляет
цикл инструментов. Наличие SDK не заменяет наши бизнес-правила и сохранение состояния.

### Границы процессов и полномочий

- Renderer: локальный UI, без Node.js, без ключей и произвольного IPC;
  `contextIsolation` и sandbox включены, аргументы bridge валидируются.
- Main: жизненный цикл, Keychain, Team API с актуальными правами,
  scheduler уведомлений и контролируемое открытие URL.
- Agent worker: Node.js utility process, получает scoped-вызовы календарного
  сервиса через main. Календарные секреты ему не передаются. LLM-запросы
  выполняются отдельным сетевым адаптером main, чтобы ключи LLM также оставались
  вне контекста и состояния агента.
- Worker улучшает изоляцию сбоев, но не является security sandbox:
  это доверенный код приложения. Никакой генерации и выполнения кода моделью.
- Изменения исполняет сервис main только после проверки подтверждения
  текущей версии черновика. В prompt нельзя подделать факт нажатия пользователем
  кнопки подтверждения. Повтор после неизвестного исхода начинается со сверки API.

Основание: [Electron security](https://www.electronjs.org/docs/latest/tutorial/security)
и [utilityProcess](https://www.electronjs.org/docs/latest/api/utility-process).
Не подключать к remote Team Small странице bridge с секретами или привилегиями.

### Харнес и модели

Прикладные состояния: сбор параметров → поиск слотов → черновик → ожидание
подтверждения → повторная проверка → запись → проверка результата.
Состояние и версия подтверждённого payload сохраняются приложением,
а не только текстом истории модели. На рестарте незавершённую запись
считать неизвестным исходом и сверять, не автоматически переигрывать.

Профили подключения:

1. **Small vLLM**: корпоративный endpoint, доступная модель и персонально
   выданный корпоративный токен; общий секрет не вшивать в приложение.
2. **Персональный OpenAI-compatible**: пользователь задаёт endpoint, модель и
   ключ. Приложение явно показывает активный профиль; переключение только явно.

Нет автоматического fallback на внешний endpoint при ошибке корпоративного.
Ключ принадлежит профилю и конкретному origin; его нельзя пересылать после
redirect на другой host. Вход Small Team и LLM-токен — разные учётные данные.
Правила передачи рабочих данных персональному провайдеру остаются предметом
корпоративной политики, выбор профиля сам по себе их не определяет.

[OpenAI-compatible provider](https://ai-sdk.dev/providers/openai-compatible-providers)
позволяет задать base URL, ключ и model ID. Это не гарантия одинаковых возможностей
всех endpoint. [vLLM tool calling](https://docs.vllm.ai/en/latest/features/tool_calling/)
зависит от выбранной модели, parser и chat template. Нужна проверка streaming,
tool calls, ошибок и ограничения схем на реальном Small endpoint.
GLM / DeepSeek Flash остаются вариантами до получения доступных model ID.
Vercel hosting или AI Gateway не требуются: выбирается прямой provider.

### Keychain и уведомления

Сохранять сессию Team и LLM-ключи отдельными записями с идентификаторами
пользователя/профиля. [Keyring binding](https://github.com/Brooooooklyn/keyring-node)
кандидат на адаптер, а не установленная зависимость: до принятия проверить
darwin-arm64, подпись, отказ доступа, обновление приложения и удаление записей.
Electron [safeStorage](https://www.electronjs.org/docs/latest/api/safe-storage)
шифрует содержимое для хранения на диске с OS-backed ключом; это отличается
от прямого хранения сессионного секрета в Keychain, поэтому не подменяет AUTH-2.

[Electron Notification](https://www.electronjs.org/docs/latest/api/notification)
позволяет задать title/subtitle/body и macOS actions. В уведомлении показывать
название, интервал и организатора, действие «Подключиться» открывает сохранённый
URL. Не полагаться на кликабельность произвольного URL внутри body.
Системный формат карточки, разрешения и Focus контролирует macOS.
Актуальная документация требует подписи приложения для показа уведомлений;
это нужно проверить в упакованной сборке на macOS 15.1 уже в первом spike.
Точное расписание при закрытом окне обслуживает main, независимо от LLM.

## Альтернативы

| Вариант | Достоинства | Почему не выбран для v1 |
| --- | --- | --- |
| Tauri + Node sidecar | Системный webview, возможен меньший размер оболочки | Для Node-харнеса нужен sidecar, его упаковка/жизненный цикл плюс Rust-граница. Дополнительные части при приоритете простоты. |
| Pake | Быстро упаковывает сайт | Перестраиваемое рабочее пространство, свой харнес и секреты требуют существенной доработки; одной упаковки сайта недостаточно. |
| SwiftUI + TS-сервис | Прямые нативные API и UI | Два стека и мост для TypeScript; сейчас не даёт достаточной выгоды относительно сложности. |
| Pi agent-core + pi-ai | TypeScript, streaming, tools, OpenAI-compatible API | Реальная альтернатива. Для нашего продукта AI SDK уже даёт цикл и approvals; для обоих всё равно нужен календарный сервис и журнал. Вернуться к Pi при потребности в его событиях/context API. |
| Pi Durable | Durable conversations/tasks/docs и replay policy | Авторы явно помечают API экспериментальным. Сохранение черновика и сверка записи не требуют общего durable runtime. Пересмотреть для длительных фоновых задач или совместных агентов. |
| Hermes Agent | Готовый универсальный агент и развитая экосистема | Python-runtime и широкий набор возможностей усложняют упаковку узкого TypeScript-клиента. |
| Собственный LLM loop с нуля | Полный контроль | Придётся поддерживать streaming и совместимость протоколов; используем библиотечный loop и пишем только календарную политику. |

Источники альтернатив: [Tauri sidecar](https://v2.tauri.app/develop/sidecar/),
[Pake](https://github.com/tw93/Pake),
[Pi agent-core](https://github.com/earendil-works/pi/tree/main/packages/agent),
[Pi provider API](https://github.com/earendil-works/pi/tree/main/packages/ai),
[Pi Durable README](https://github.com/earendil-works/pi/tree/main/packages/durable),
[Hermes pyproject](https://github.com/NousResearch/hermes-agent/blob/main/pyproject.toml).
Сравнение описывает пригодность для наших требований, а не невозможность
реализовать продукт на альтернативе.

## Последствия и проверка решения

Electron несёт размер Chromium/Node и потребление памяти; их не объявляем
минимальными без измерения. Обновления Electron и упаковка native Keychain
binding требуют сопровождения. Пока нет гарантии совместимости конкретной
GLM/DeepSeek конфигурации Small с tool calling.

Для CAL-1 [Dockview](https://dockview.dev/docs/overview/introduction/)
даёт docking и сериализацию. [Community-лицензия](https://dockview.dev/docs/overview/licence/)
MIT включает перетаскивание и resize; Enterprise не требуется для заявленных
сценариев. Сохранение layout — предложение ADR, а не уже подтверждённый пункт UI.

Условия принятия: ревью пользователем и ограниченный технический spike
без реальных записей: запуск arm64-сборки на macOS 15.1; Keychain с синтетическим
секретом и очисткой; нативное уведомление с открытием безопасного тестового URL;
перемещение/resize двух панелей; потоковый запрос и read-only tool call через
настроенный endpoint; сохранение черновика и отказ от повторной записи после
симулированного сбоя. Точные версии фиксируются в манифесте/lockfile spike,
не по плавающей странице latest. Сейчас этот spike не выполнялся.
